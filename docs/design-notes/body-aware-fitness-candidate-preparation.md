# 身体密度の候補準備と環境採点を分ける

日付: 2026-09-26。状態: 移動への接続に先立つ最小準備の登録。
通常のPitchController・乱数列・提案時刻は変更しない。

代表密度は候補一つで旧経路約42 msを要した。全候補の密度を作る間に環境snapshotを固定すると、
計算終了時にはその環境が鮮度期限を越える恐れがある。身体密度は環境から独立しているので、
先に候補基音の密度を準備し、その後に届いた一つの環境batchで全候補を採点する境界を使う。
候補抽出も身体評価に依存するため、旧Cで上位候補を選んでから身体密度を作る方法は採らない。

最初の部品は、既存PitchHillClimbPitchCoreが採点し得る全基音の集合を環境に依存せず準備する処理である。
初版は大域候補0・ratio候補無効の範囲に限る。局所窓の全bin、現在targetと近傍二点、
同じ乱数状態から作るGaussian三候補を含める。実際の候補抽出・1セント重複除去・greedy閾値・Metropolisは
既存 `propose_with_scorer` が実行する。準備集合はfloat bitの完全一致だけで重複を除き、
1セント近傍や周波数格子へ丸めない。こうして、実採点が要求する任意の非格子候補も準備対象へ残す。

準備用乱数器は独立した複製とし、通常Voiceの共有乱数状態を書き戻さない。
この部品だけでは、非同期requestへ乱数を予約する方法、body generation、期限、cacheの管理を実装したとは扱わない。
後の実接続で候補準備中にtarget・制御・身体が変わった場合の無効化を別途登録する。
現在音高が滑っていることと、目標音高や身体recipeが変わったことも区別する。

検査では、64固定seed、帯域中央と両端、近傍step 24／200セント、温度0／0.05／0.26を使う。
複数の異なる地形scoreで実 `propose_with_scorer` の全呼出位置が準備集合に含まれることを確認する。
同じscoreを事前保存した表から返した場合、直接採点とtarget・salience・終了乱数状態が一致することも要求する。
大域・ratio有効はunsupportedとして返し、準備不完全な表を使わない。
これは候補集合の十分性の検査であり、身体密度の近似、実時間利用率、移動の生態効果の検査ではない。

I11 §5.7の専有中は静的実装のみ行い、検査は専有解除後に実施する。
