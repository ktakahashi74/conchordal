# F4c案: 成人の身体評価から親選択と遺伝出生まで

作成: 2026-09-27。状態: 接続案。取得前登録でも実装結果でもない。
前提は[F4a](body-aware-fitness-f4a-results-20260926.md)と
[F4b](body-aware-fitness-f4b-birth-registration.md)の限定接続であり、F4bの修正版検査終了を待つ。

## 確認する因果の範囲

成人の身体評価がenergyを更新し、そのenergyを既存の親選択が読み、選ばれた親から生じる
周波数候補を子の身体で評価して実際に生成する。この一連の接続を、一つの出生機会で確認する。
親の重みに身体scoreをもう一度掛けない。現行の`weighted_parent_select`はenergy比例、
総和ゼロなら一様という規則であり、これを維持する。

これは音高と系譜の継承である。子の身体はPopulationのtemplateから作られるため、
親の音色を遺伝させたという結果にはならない。長期の選択、PeakBiased、settle候補、
非同期出生のID予約は対象外とする。

## 最小の固定場面

同じPopulationに生存するEntrainの親候補を二つ、死亡を確定させる旧個体を一つ置く。
音源ID、子の未使用ID、生成frame、seed、固定Harmonicのtemplate、基音、habitat route、
旧個体のnote-off時刻、出生時刻は取得前登録で固定する。身体密度はF1/F2の同じ経路を使う。
親の成年評価は各親だけを除いた音源別環境、子の評価は死亡音のreleaseを含む共有環境を使う。
旧個体や選ばれた親を、子の自己音として引かない。

親のenergyは値を捏造して身体評価の結果に見せず、F4aと同じ実lifecycle更新の前後を記録する。
この更新で内部attackやGated onsetを同時発生させる必要はない。親選択入口で読み出したenergyを
更新後の値へ照合し、同じ候補用RNGの複製で親の抽選、16候補の生成、子の選択を独立に再演する。
異なるseedで親の選択が変わることを結果に合わせて探索しない。
親抽選時のpoolは生存Entrain二体だけとし、死亡個体が含まれないことをIDで検査する。
更新後energyは双方が正で、互いに異なることを登録条件にする。条件を満たさない取得を
energy比例選択の正例とせず、一様fallbackとは別に扱う。

## Random出生から変わる接続点

Hereditaryでは、親を一度選んでから全候補へ同じ系譜を与える。候補周波数は親のlog2周波数に
既存の正規変動を加え、既存範囲へclampする。Randomの正score重み抽選とは異なり、
Hereditaryは候補のlevelが最大のものを選ぶ。候補順、同値時の選択、重複、乱数消費を保存する。
F4bの接続はRandomのscore抽選と選択後のlevel判定に限られる。
Hereditaryの`max_by`が読む全候補levelも身体評価へ接続する必要がある。
選択後の閾値だけを置き換えて、候補比較を旧点地形に残さない。
最低levelの出生拒否と、拒否時のspawn counter・runtime ID・member indexの扱いもF4bと同じく検査する。

子の候補身体は各周波数について、実際の`spawn_with_landscape`と同じchild ID、frame、
Population、member index、parent ID、generation、seedから構成する。
Random出生のgeneration 0を流用せず、選ばれた親のgeneration + 1を用いる。
実生成後のbody snapshot、代表recipe、基音、親ID、世代を採点時の候補へ照合する。
templateの`Debug`文字列を身体同一性の検査に使わない。

F4bの独立レビューで、代表recipeの全要素が子から再取得されているわけではないと確認した。
body、基音、代表modulatorは子から照合する一方、hold、ADSR、平滑化、sample rateには
固定した代表条件を使っていた。F4cでもこの定義を取得前に明示し、代表励振による身体評価として扱う。
期待recipeをcloneして残りの定数を保持したhash一致を、実子の発声条件全体の一致とは呼ばない。
実際に発音されるToneまで一致させる検査は、発声経路から全recipeを取得する別の接続が必要となる。

## 取得前に確定する判定

1. 二つの親の代謝には、それぞれの身体score/levelだけが届く。旧点地形を変更した対照で、
   更新後energy、親抽選、子候補、選択結果、終了RNGが一致する。
2. 親選択の入力energyと候補生成後の系譜を保存し、二重の身体score重み付けを検出する。
3. 全候補は同じ出生前共有環境で採点する。親LOOを渡した場合と同じ値とは仮定しない。
4. 採用・最低levelによる拒否を、F4bと同じ取得前固定の閾値導出式で検査する。
5. 準備後の親世代、template、child ID、frame、候補順の変更は、子の追加前に検出する。
   この試験の明示的な拒否を、通常演奏の非同期fallback実装と読み替えない。
6. 試験機能なしの通常releaseを固定した旧版と比較し、対象条件の音声・行動記録を保つ。

上記を通過しても、F4全体の完了にはならない。出生時の候補生成まで旧点地形へ依存する入口、
実時間の欠測、初期配置、長期の生存・分布、音色遺伝は引き続き別の工程である。
