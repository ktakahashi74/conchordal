# F4 全消費者比較の実装レビュー

2026-09-27。対象は `.worktrees/body-fitness-repeated-respawn` の第十八版b。静的な設計レビューであり、実装、実験取得、合格判定ではない。[F4計画](body-aware-fitness-plan.md) §5 と[先行草案](body-fitness-all-consumers-draft-20260927.md)を、通常の `conchordal-render` 経路に落とす。以下のコードリンクはこの隔離作業木の確認箇所を指す。同hop遷移の修正は別作業中であり、この記録の根拠は修正前の保存版とする。

## 推奨する実装順

第一単位は、出生のない固定二身体を別Populationに置き、同じsource-removed環境と同じ判断時計で基準／移動のみ／生存のみ／移動＋生存の四条件を走らせる。これはF4全消費者の前段であり、親選択・出生地点の効果を含まない。別Populationなら各`template`が独立し、通常の`Action::Spawn`で宣言した身体を維持できる。`Spawn`を同じPopulationへ二回送る方法は、`ensure_population_state`が後のspecでtemplateを更新し、`on_spawn_action`がmember indexを各回0から振るため使わない。[actions.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/actions.rs)

第二単位で同一Populationの異種founderと、親から遺伝しない固定子身体を導入する。これを終えてから、基準／移動のみ／生存のみ／全接続の四条件に出生候補採点を加える。現在の`validate_offline_respawn_metabolism_scenario`は一つのtime-zero Linear Spawnに三つの同一specを要求し、`RuntimePopulationState`は単一templateを持つ。異種親poolの比較は第一単位から推論できない。[runtime/mod.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/mod.rs)、[community.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community.rs)

## 第一単位: 同じ機会で採点方式だけを変える

既存の`body_fitness_action=false`を「点」条件として使うのは不適切。通常の`PitchHillClimbPitchCore::propose_target_with_crowding_salience`は共有Landscapeの`sample_consonance_score_with_loo`を読み、近似自己減算か旧`ExactScan`を適用する。一方、身体条件は各sourceの実PCMを除いたLandscapeを`Ready::score`に渡す。環境、自己除去、候補準備の時刻が同時に変わる。[pitch_core.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/pitch_core.rs)、[body_fitness_preparation.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/body_fitness_preparation.rs)

通常offline実行専用の小さい採点選択を`BodyFitnessAction`へ渡し、全四条件で同じ`before`→`PitchController`のprepared gate→`after`→render後`request`を使う。`Request::capture`が採った候補集合、target、RNG snapshot、source identity、body generation、route、epochを保ち、`Ready::score`の候補score生成だけ切り替える。身体は現行の代表密度加重平均。点は**同じsource-removed Landscape**の`consonance_field_score_eff`を候補log2で補間する。どちらも同じ`PreparedVoiceDecision`を通す。点のlevelが必要な箇所では補間したscoreに`ConsonanceRepresentationParams::level`を適用し、補間済みlevelを別目的として混ぜない。[body_fitness_action.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/body_fitness_action.rs)、[pitch_controller.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/pitch_controller.rs)、[landscape.rs](../../.worktrees/body-fitness-repeated-respawn/src/core/landscape.rs)

`BodyFitnessAction::before`はoffline設定でpending workerに`receive_offline()`を使う。現行の非同期作業はwalltime遅延による任意のhop欠測ではなく、前hopのrender後に依頼し、次の`before`で結果を待つ順序。両採点方式をこの同じgateに置けば、単に`body_fitness_action`をOFFにする場合の保留時間差を排除できる。ただしsource退役、Recipe変更、候補不支持による拒否は記録し、同じ機会数を確認する。身体採点だけ有効率が低いなら比較は未成立。[body_fitness_action.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/body_fitness_action.rs)、[runtime/mod.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/mod.rs)

代謝も全条件で`OfflineMetabolism::install`と`Voice::tick_articulation_lifecycle`の同じ経路を使う。現行のcontextなし分岐は共有Landscapeを読むので点対照に使わない。`OfflineMetabolism::evaluate`の身体分岐は代表密度を作って加重scoreを返し、点分岐は同じinstall済み`c_score_eff_scan`を現f0で補間してscoreと`repr.level(score)`を返す。onsetとlifecycleの両方に同じ選択を適用し、receiptへ採点方式と同じsource、support、decision時刻を記録する。今回の実装選択では、点条件でも同じ代表密度を準備し、`body_fitness::evaluate`で実測した`in_band_mass`を保持した上でscore/levelだけを点値へ置換する。massは点評価の重みではなく、共通の代表身体準備の診断値として記録する。架空の0を代入せず、固定身体のRecipe/source照合と支持拒否も両条件で維持する。計算費用の最小化は今回の比較対象にしない。[offline_metabolism.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/offline_metabolism.rs)、[voice.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/voice.rs)、[consonance_kernel.rs](../../.worktrees/body-fitness-repeated-respawn/src/core/consonance_kernel.rs)

第一単位の通常offline配線には、既存booleanを独立マスクと見なさず、明示的な比較モードを追加する。`AppConfig::validate`、`wire_runtime`、`run_render`の三箇所の組合せ検査を同じ意味に更新する。身体actionと身体metabolismを同時に初期化し、二つの独立した`decision_batch`借用が同一hopの同じsource集合・epoch・supportを使うことを照合する。`Landscape::apply_habituation`はbaseのscore/massからeffective値を再計算するため、同じ状態を再適用してもeffective値をさらに侵食する処理ではない。代謝installとactionの`before`で同じhabituation状態・thetaを使うことを照合する。現行のrespawn/birth専用validatorを第一単位へ流用せず、time-zeroの異なるPopulation二声、固定解析設定、Finishを検証する小さい専用validatorを置く。[config.rs](../../.worktrees/body-fitness-repeated-respawn/src/config.rs)、[runtime/mod.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/mod.rs)、[body_fitness_observer.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/body_fitness_observer.rs)

第一単位の条件は点／点、身体移動／点生存、点移動／身体生存、身体移動／身体生存。初期body spec、source IDs、seed、音量・route、制御、48 kHz/512 hop、解析空間、habituation、終了時計を固定する。代謝係数は生存差を観測できる**非ゼロ**値を結果取得前に登録する。音響シーンと二身体はF2で支持・順位差を確認した固定対から選ぶ。死亡や移動で後続音場は分岐するため、異条件間の同一WAVや全hopの同一RNG列は要求しない。各条件内の再現性、初回共通機会の候補集合/RNG snapshot/score順位、以後のbranch時刻、判断有効率、energy、死亡時刻を報告する。共通機会で候補が違うなら採点効果の比較に進まない。[body_fitness_preparation.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/body_fitness_preparation.rs)、[metabolism_policy.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/metabolism_policy.rs)

## 第二単位: 異種親poolと出生先

同一Populationへ異なるbody specを入れる最小の通常Scenario入力を定める。候補は、ひとつの`Action::Spawn`内にmemberごとのspec列を持たせ、同じaction内でIDとmember indexを一意に割り当てる形。一般Rhai APIを直ちに広げる必要はないが、通常`conchordal-render`で読み込むScenarioから指定できる入口が必要。`cfg(test)`専用hookでは比較実行を証明しない。Populationには親抽選用の単一template依存を残さず、**固定子specを親抽選前に一つ決める**。この段階では親の音色を子へ継承しない。子の確定spec/ID/metadataを使い、現行`OfflineRespawn::prepare_candidates`、`peak_bias_candidate_bins_with_scores`、局所候補、最終Hzの評価をそのまま生かす。parent poolは`respawn_on_new_deaths`の更新後energyで作り、`weighted_parent_select`の乱数消費を維持する。[actions.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/actions.rs)、[respawn.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/respawn.rs)、[offline_respawn.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/respawn/offline_respawn.rs)、[child_body.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/child_body.rs)

出生候補も点／身体を同一`OfflineRespawn`の中で切り替える。出生前の子は自己PCMをまだ持たず、現行evaluatorは同時点の共有Landscapeのeffective値を使う。死亡した親のtailを子の自己音として引かない。点条件はこの同じ出生前環境、同じcandidate search、占有・spacing・min-level、同じRNGを使い、score/levelだけ点関数にする。legacy分岐へ戻して候補抽出や制約も同時に変えない。child bodyは候補評価前に確定し、実際にspawnした子のRecipeと照合する。出生の可否や親poolは生存介入の結果でも変わる。出生地点の**直接**効果を識別するには、同じ親poolと親RNG snapshotから点／身体を対にした初回出生機会の追加比較が必要。四条件の長期差だけで親効果と出生採点効果を分解しない。[respawn.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/respawn.rs)、[offline_respawn.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/respawn/offline_respawn.rs)

`advance_population`の順序は、前hop batchの検査→scenario dispatch→代謝context install→`collect_phonation_batches`（onsetの代謝を含む）→action `before`→`advance_with_listener_pressure`（移動・lifecycle）→action `after`→前児の次hop receipt検査→cleanup/respawn→新生児のゼロ自己PCMを含むrender→翌hopのsource-removed batch、という境界を保つ。出生hopの子は`BirthShared`または現respawn経路の未receipt状態であり、まだ自分のsource-removed historyを持たない。新生児を古いbatchの既存sourceとして評価しない。親pool snapshotはadvance後・cleanup前のenergyを読む。前児の次hop検査と新出生が同hopなら、現行のcleanup後の重なりassert以前にpreflightで許否を確定するか、両遷移を順に受け入れる。親RNG・spawn counter・ID割当前に五番目のsource、未解決前児、stale batchを拒否する。[runtime/mod.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/mod.rs)、[respawn.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/respawn.rs)

第二単位の四条件は点／点／点、身体移動のみ、身体生存のみ、三消費者すべて身体。親重みはenergyの派生なので、生存のみでも変わる。親の抽選確率、spawn sequence、candidate binsと最終Hz、子のRecipeとsource birth sample、次hop receiptを記録する。四source上限内の「三founder＋一新生児」だけを最初の範囲とし、反復出生は別境界。固定異種親の勝敗、出生地点の差、子の生存差はそれぞれ独立した観測量。[runtime/mod.rs](../../.worktrees/body-fitness-repeated-respawn/src/runtime/mod.rs)、[respawn.rs](../../.worktrees/body-fitness-repeated-respawn/src/life/community/respawn.rs)

## 未決の登録事項と失敗判定

実装前に、二身体の宣言値と同じf0でのscore差、非ゼロ代謝係数、固定seed群、観測期間、死亡・出生機会の期待範囲、比較に必要なaction判断有効率と代謝receipt完全率、許容差を固定する。初回の共通機会でsource identity/候補/RNGが揃わない、点・身体の介入先以外のgateがずれる、代謝receiptが欠ける、第五sourceに達する、子Recipe/次hop sourceが違う場合は、その取得を全消費者比較に数えない。現在の厳格offline代謝は欠測をpanicにする。欠測をゼロfitnessとして更新する規則へ暗黙に変えない。長期連続運用向けの欠測時計、任意の同ID再利用、音色遺伝、実時間費用はこの比較の外で別に決める。
