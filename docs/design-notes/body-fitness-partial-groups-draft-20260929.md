# 次の身体表現：部分音群と疎な採点の設計草案

2026-09-29。[直接モデルv1の結果](body-fitness-direct-model-results-20260929.md)を受けた次の設計単位。取得前契約ではなく、未決の数式を含む草案である。新しい数値・性能取得やruntime接続はまだ行わない。v1の意味判定・資源判定の不合格は保存する。

## この変更が必要になった理由

v1は各候補で全binの配列を消去・変換・検査・積分する。Sineの実laneは1本でも、690＋21候補、16体の評価に約22–24 msを要した。各laneを使う部分だけでなく、候補数とbin数の積に比例する仕事がある。Landscape条件では候補ごとの実子生成も含めて約41–73 msだった。対象16体の同hop条件は満たさない。

また、独立laneをそのまま聴感指数へ通す方式では、近接unisonの統合や弱い部分音の扱いが旧frontendと異なる。減衰だけを追加しても最大誤差と明確な順位逆転は改善しなかった。次は全binを作らずに処理できる部分音群の表現を一案として定義し、計算構造と身体の意味を同時に見直す。

実kernel応答を全候補×72時点×全lane×全bandで計算する案には進まない。PCMを省くだけで大きな積の仕事を維持しても、同hopの見通しにはならない。旧frontendへ疎な針状powerを渡すだけで、連続lobe・prominence・guardの意味を再現したとも扱わない。

## 維持する入力と境界

- 実子のBodySnapshot/Recipe、ID・seed・frame、候補に応じた実ratioを使う。Landscape依存の身体を別候補から流用しない。
- Sine/Harmonic/Modal、Nyquist maskとModalのclampの違い、帯域外量と質量ゼロの明示結果を保持する。
- A-weightingは絶対Hzで適用する。完成済みの聴感密度を横にずらさない。
- 群内ではpowerを先に合算し、群の聴感変換は一度だけ行う。Log2Spaceへの必要な出力は変換後のmassを保存する形で投影し、power分割後の指数で質量を増やさない。
- 実unisonの振幅gain=1/Uを保持する。位相省略に伴う絶対powerの変化を補正係数で隠さない。正規化scoreで共通倍率が相殺される条件と、絶対閾値・帯域出入りで相殺されない条件を区別する。
- Cの空間・epoch・有限性の確認を身体群ごとに繰り返す必要はないが、候補採点の前に一度は行う。疎な支持だけを見て、不正な環境や古いepochを見逃す入口を作らない。
- 身体入力・候補集合・選択式・既存出生hop・同時出生の対象負荷を、都合のよい範囲へ縮小しない。

## 契約前に解く点

近接群の形成には、既存peak処理のERB座標と0.2 ERB等の規則を参考にできる。ただし旧peak検出器の局所極大・谷・prominenceをそのまま借りることはできない。群の代表Hz、同点順序、弱群の質量移動、絶対閾値の有無、band端の群の扱いを一つの新しい規則として明記する必要がある。[部分音群モデルの読取調査](../../target/body-fitness-direct-model-20260929/sparse-partial-group-model-audit.md)はその設計素材であり、採用済みの規則ではない。

Harmonicのmotionは全laneへ共通の `f0*(vibrato+jitter)` を加える。これを部分音ごとに比率比例の変調へ変えない。時間状態を身体ごとに一度準備できても、候補ごとに最大72×576点を再展開すれば費用が戻る。時間変化を相対powerの有限表現へまとめられる範囲と、候補依存のERB群形成・band処理を分け、同bin合算と時間平均、聴感指数の順序が変わる箇所を証明または明示する必要がある。[相対power監査](../../target/body-fitness-direct-model-20260929/relative-power-factorization-audit.md)にあるとおり、旧NSGT結果そのもののshift不変性はない。

Modalの減衰・入力結合とHarmonicの状態変化を、それぞれ何の代表状態として評価するかを固定する。新モデルの定義に対する数値精度、旧72-frameとの差、出生で必要な意思決定と時間条件を別に検査する。旧0.025等の未達を後付けで合格へ変えず、別の定義を採るなら相違と新基準の根拠を取得前に記す。

## 次の実装へ進む条件

群形成と時間集約の式、全candidateと選択後Hzを含む仕事量、入力上限、数値の独立参照、失敗状態が一つの契約になってから隔離実装へ進む。資源の問題をdense配列の小さい係数調整だけで追いかけず、ゼロbinの反復と候補ごとの不要な身体全体生成を含めた構造を扱う。草案だけでは本番成立とも次試作の合格とも数えない。
