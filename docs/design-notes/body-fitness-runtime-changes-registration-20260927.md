# Body fitness: non-Sine and mid-run change registration

Date: 2026-09-27. Status: conditions fixed before acquisition. This plan applies to the isolated `body-fitness-ecology` worktree and normal `conchordal-render` execution. Functional evidence is separate from real-time deadline, listening, and author acceptance.

## Fixed conditions

Use seed 17, 48,000 Hz, 512 samples per hop, `body_fitness_action = true`, and the local non-ratio hill-climb. Run each scenario twice. The scene has two separate one-Voice populations: Harmonic at 220 Hz with brightness 0.30, and Modal at 330 Hz with brightness 0.60. Both start at sample 0, stay alive with `brain("drone").sustain().endurance(10.0)`, send to both buses, and use amplitude 0.06, `adsr(0.005, 0.0, 1.0, 0.2)`, `seek_consonance()`, `proposal_interval(0.05)`, `move_cost(0.0)`, `temperature(1.0)`, `glide(0.04)`, `global_peaks(0, 0.0)`, and `ratio_candidates(0)`. No Sine Voice is present.

Scenario A is unchanged for 1.6 seconds. Scenario B starts identically, changes Harmonic brightness to 0.85 at 0.64 seconds (sample 30,720, frame 60), changes that population's landscape weight to 0.0 at 1.28 seconds (sample 61,440, frame 120), and ends at 2.2 seconds. Changes and initial placement are flushed at their declared times. The 48-hop action report cadence yields before-change frame 48, after-body frame 96, and after-control frame 144; frame 192 is a later recovery observation. Boundary event ordering must be checked against the actual event records before attributing a counter difference to a change.

## Required observations

The normal report must expose each source's cumulative `consumed_decisions` and `rejected_decisions`, current body generation, `last_rejected_decision`, and `last_consumed` with serial, body generation, support/decision samples, target before/after in log2 Hz, physical frequency after commit, and score-use count. The current `population_step.mean_freq_hz` for a one-Voice population is an independent check of physical pitch, but it cannot reveal a target change before the body glides. No wall-clock duration or worker throughput measurement is part of this acquisition.

For Scenario A, each Harmonic and Modal source must consume prepared decisions with `score_uses > 0`, and show at least one decision whose target changes, followed by a physical frequency change from its initial frequency. A consumed counter alone does not satisfy this condition. The two runs must match in action records, population frequency traces, and WAV bytes. Every consumed decision must satisfy `support_end_sample <= decision_at_sample` with age at most 4,800 samples; all reported per-worker caches stay within 256 entries and 1 MiB.

For Scenario B, both sources must consume before the first change. The Harmonic body generation must increase at the brightness change, then a later consumed decision must use the new generation. At the frame-120 control change, the previously prepared control should be rejected as `ControlChanged` if it reaches a due gate; the report must show at least one rejection after the change and a later consumed decision with the current control. If event/gate ordering makes the old job unavailable, report that fact and do not relabel deferral as rejection. The Modal source remains a control: its body generation stays fixed and it keeps consuming. The two runs must agree on action records, population frequency traces, and WAV bytes. Any target or physical pitch claim requires the corresponding recorded values, not just a total count.

## Route boundary

The current Rhai `send()` method configures a `PopulationSpec` before spawn. Neither a live Population routing method nor `ControlUpdate.routing` exists, so a normal script cannot change one Voice's route mid-run. A replacement Voice with a new route tests birth/retirement rather than route validation for the same Voice. Record initial habitat-only versus both-bus behavior if useful, but do not claim mid-run route rejection or recovery from it. A same-Voice route mutation is assigned to a separate crate-internal normal-hop boundary test. This acquisition does not add a Rhai API or a test-only production hook.

The separate `runtime::body_fitness_action::tests::actual_preparation_rejects_route_mutation_then_recovers_without_old_proposal` fixture uses seed 7, a 440 Hz Sine Voice, 48,000 Hz/512-sample hops, an actual 72-hop density worker, and a flat accepted environment. It installs a prepared job, changes the Voice's presentation-route flag, expects `RouteMismatch` with unchanged RNG and target, then requests serial 2 and expects consumption with a cache hit. This is an internal route-validation and recovery test. It does not establish source-removed PCM behavior or normal-render route mutation. The focused test passed; its log is `target/ecology-validation/route-boundary-final2.log`.

Pre-acquisition arithmetic correction: a 2.0-second scene would end before report frame 192 (2.048 seconds), so Scenario B is fixed at 2.2 seconds; its seed, sources, and update times did not change. The registration fixes conditions before rendering. If a stated observation is unavailable in the report or a scripted update is not accepted, amend this draft with the precise blocker before changing the fixture. Preserve failed attempts and classify them as failed or inconclusive; do not tune seed or temperature after observing output and call the result preregistered.

Its result must be reported separately from this failed first acquisition.

The phase-zero revision then acquired both registered scenes twice with `at(220.0)` and `at(330.0)`. Binary SHA-256 was `079c51c9d2ba3f073a1648187abb3d999f8d9e23adac1471a9c06e8fd62535dc`; raw evidence and an immutable fixture/source manifest are in `target/body-fitness-ecology-build-20260927/runtime-action-ecology-evidence/run-143-1790482523123571196/`. Both scenes were deterministic. Scenario A consumed 30 decisions per source by frame 144 with stable body generation 1, but neither target nor physical pitch moved. The movement failure is an independent scenario construction error: `at(freq)` supplies `Placement.freq_hz`, which `place_population_spec` applies through `set_freq`; that sets `PitchMode::Lock` after `seek_consonance()` selected Free. The controller computes and consumes prepared scores, then Lock pins the target to the original frequency. This finding does not weaken the pitch movement criterion. A separate v2 registration replaces only the placement expression with `line(freq, freq)` before new acquisition.
