# 身体評価付き出生の再出発：時刻契約と方式選定

2026-09-29。主計画は[身体適応度計画](body-aware-fitness-plan.md)。[Opus 5.5レビュー](body-fitness-plan-opus55-review-20260929.md)と[所見への対応](body-fitness-plan-review-response-20260929.md)を受け、第一工程の静的確認を実施した。本書の時刻・意味の境界と作業順を現行方針とする。本番実装、軽量モデルの数値精度、実device上の成立はまだ検証していない。

## 1. 今回完了した第一工程

Opusが指定したQ1–Q6を、main、隔離time4版、保存済み入力・reportで確認した。新しい音声取得や性能測定は行っていない。Sol 6が読み取りと記録を担当し、主担当が主要な依存関係、旧結果の現在地、レビュー提案の採否を確認した。

| 問い | 確認結果 |
|---|---|
| Q1：子の乱数入力と決定時点 | 身体用seedはcommunity seed・子ID・seed frameに依存する。隔離版では予約時に確定し、生命時計はcommit時に始まる。未来の死亡frame・実IDを未確定のまま同一の実子表を作る契約はない。 |
| Q2：環境依存の身体 | LandscapeDensity/Peaksのmode生成は実装・sampleに存在する。固定time4の36条件では未被覆。身体確定後の密度が環境独立でも、身体確定自体は環境依存の場合がある。 |
| Q3：出生種別間の系列 | 初期Spawnとrespawnの配置・親選択には共通counterが関わる。一方、候補表の身体用seedは別である。選択counterの未来値だけを、予定Spawnの身体表を先に作れない理由にしない。 |
| Q4：2秒と24秒の差 | 狭域I/Rは各193候補、広域I-W4は690候補で3予約が直列処理された。R系にはさらに19–21件の局所密度計算がある。出生種別そのものの速度差とは言えない。 |
| Q5：予定Spawnの列挙 | 通常Rhaiは再生前にScenarioを構築するので、予定SpawnのID・時刻・spec・rangeは列挙できる。実dispatch frame・身体入力・解析設定も一致する条件なら、配置抽選を先取りせず全bin表を準備できる余地がある。 |
| Q6：選択後の追加Hz | 初期Spawnのjitter Hz、respawnの局所格子は出生時の環境・親・占有に依存する。追加保持上限256件は期限保証ではなく、再採点・再要求が有限回で出生へ収束する保証もない。 |

第一工程の終了条件である「Q1–Q6を根拠付きで回答し、残る未確認を示す」は満たした。一般的な子在庫については、未来の実ID/frameを別系列に置き換えなければ前確定できない条件があるため、レビューの中止条件に従い、在庫の通常実装へは進まない。これは予定済み・環境非依存の子に限った前倒しまで否定するものではない。

## 2. 方式について決めたこと

全候補×72 frameのTone合成・NSGTは、固定された代表身体モデルの数値参照として保持する。出生要求後にこの全表を計算する方式を本番へ採用しない。SIMD、lane数、queue優先等の追加チューニングでこの判断を先送りしない。

子の表在庫は、同一の子・予定frame・身体入力を確定できる場合の補助手段とする。未予告の要求、死亡、身体変更、Landscape依存mode、在庫切れを覆う一般方式にはしない。準備時間・失効・保持量・継続的な補充CPUも費用に含める。約7.5 CPU秒／表という既測定条件なら、単一coreの理想的な補充でも約0.133表／秒である。これは算術上の目安で、実workerの供給率を新しく測った値ではない。

次に設計する一案は、**実子の確定済み部分音・mode情報から、その場で評価に使う身体分布を作る方式**とする。候補探索の変更や複数の補間方式の比較は同時に始めない。最初は参照と同じ候補集合・環境・占有・選択式を使い、身体分布の構成だけを分離して検証する。

これは新しい身体表現の設計候補であり、旧72-frame密度と同値とは扱わない。既存 `project_spectral_body` の出力はそのまま主観強度密度ではない。位相、ADSR、時間変化、解析器応答、聴感変換を何として表すか、単位・正規化・帯域支持を先に定義する。完成密度の線形補間が失敗したことをこの別方式の反証とせず、成功の根拠にも使わない。代謝・移動まで接続する場合も、その同じ定義を使う。

## 3. 本番の時刻・失敗契約

基準は既存mainの出生機会とVoice生成時刻である。計算が終わるまで生命時計や加入時刻を遅らせる仕組みを、身体評価の採用条件にしない。

| 経路 | Voice生成の設計目標 | 初発音と観測 |
|---|---|---|
| 予定Spawn | Conductorがactionを処理する既存の該当hop内で選択・生成を終える。事前準備の有無で予定をずらさない。 | 同hopにphonationの機会があっても、発声はarticulation・gate・envelopeに従う。 |
| 予告なしSpawn | actionを受理・処理するhop内で選択・生成を終える。事前のcache hitを必須にしない。現在の通常Rhai経路では予定actionとして構築されるが、外部から未予告で与えられる場合の境界を設計から落とさない。 | 予定Spawnと同じ発声規則を使う。入力の受理時刻と処理hopを別に記録する。 |
| 死亡後respawn | 死亡・補充条件を確認するcleanup hop内で選択・生成を終える。現在の生存親・更新後energy・環境・占有を読む。 | cleanupはそのhopのphonation収集後なので、子の通常phonation機会は次hop以降。過去の音を作らない。 |

この同hop目標は既存挙動を維持する設計条件であり、新実装の実測保証ではない。ユーザーが約107 msの遅延を承認したとは扱わず、Opusの10 hop案は採用しない。固定48 kHz・512 sampleなら1 hopは約10.667 msだが、出生処理がその全量を使えるわけではない。通常の分析・生態更新・描画・配送を含むhop全体で予算を満たす必要がある。

Voice生成、最初の非ゼロ音、出生hopの自己PCM、翌hopのSourceRemoved receiptは別の時刻・事実として観測する。音響初発音を必ず出生hopにするために発声規則を変更しない。新方式でもobserverのidentity・支持時刻・route・body generationの照合を維持する。

cache未命中や失効の通常ケースは、対象負荷の範囲で同hopに終わる計算法が必要である。入力不正・対応外身体・容量超過・期限超過では明示的に失敗を報告する。通常対応を約束する条件で起きた失敗は不合格であり、黙った点評価への切替、古い環境での抽選、秒単位の延期を成功に数えない。具体的なbatch部分失敗、ID/counterの消費、再試行の扱いは試作前の契約に記す。

## 4. 負荷と数値精度の残る決定

| 項目 | 現時点で決められること | 次工程で必要なこと |
|---|---|---|
| 最大Voice・同hop出生数 | mainのcountにはこの用途の固定全局上限を確認していない。隔離版の4 source／4予約は旧取得の範囲である。 | 既存sampleを含む利用範囲から目標負荷を明示し、失敗しやすい範囲を後から除いて合格にしない。4 sourceでの局所試作を一般受入としない。 |
| 候補・部分音・mode数 | 旧全bin2048・追加256は保持保護で、処理deadlineの保証ではない。 | 全bin、非格子Hz、mode数、unison、局所探索の最大仕事量を式と数値で固定する。 |
| CPU・memory | worker、準備、失効分も含める。690表のscan本体だけで約1.816 MiB／子。 | 既存負荷の残余から出生に割り当てる上限を定め、冷状態・連続要求の最悪条件を含めて測る。旧1.5 core等の試験上限を自動転用しない。 |
| 精度・意思決定 | 旧F2式と72-frame参照値を保存する。旧許容差を変更しない。 | 新表現の定義と用途に基づき、支持・分布・score/level・候補選択への許容差を数値取得前に固定する。代謝へ進む段階でenergyの影響も規定する。 |
| 再利用 | 子のhashだけでなく、候補Hz・解析設定・観測条件等の一致を照合する。 | 部分音表現に必要なkeyをその関数入力から定義し、正しさの証明をcache hit率で代用しない。 |

数値上限と新モデルの許容差はまだ未確定である。誤差を見て通る値へ合わせることも、未確定のまま通常runtimeへ接続することもしない。

## 5. 次の一単位

次はF2内の「本番用身体表現の契約定義」に進む。入力は実子のBodySnapshot/Recipe、部分音・mode射影の既存実装、固定した参照例と上記の時刻・負荷契約である。対象は既存のSine/Harmonic/Modalを明示し、Landscape依存modeや音高外成分を無言で除外しない。

成果物は、(1) 身体分布の式・単位・代表状態と、省略する時間・位相情報、(2) 旧参照との一致を要求する部分と別モデルとして比較する部分、(3) 全候補と選択後Hzを含む仕事量上限、(4) 小さい反例集合と事前の合否値、(5) 未準備・部分失敗時の状態遷移、を一つの短い契約にまとめることである。新しい抽象層や汎用cacheの実装を先に作らない。

契約の終了条件は、未定義の重み・単位・対応外状態・上限がなく、小さい隔離試作を実行できること。参照密度とのbit一致を暗黙の条件に戻したり、任意の閾値緩和でモデル変更を隠したりする場合は未完とする。成立した一案だけを小試作へ進め、失敗時はその理由を保存して設計へ戻る。I11、音色遺伝、大規模な36条件再取得、NSGTの追加性能探索へ自動で広げない。
