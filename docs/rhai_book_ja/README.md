# 日本語版の執筆規約

日本語版は英語版の逐語訳ではない。英語版と同じモデル、事実、API、コード例を、
日本語の読者が一度で理解できる順序と語彙で書き直す。

## 固有のオントロジー語は翻訳しない

次の語は、実装上の型名であると同時にConchordalの概念体系を構成する固有語である。
日本語の普通名詞へ置き換えず、本文でも常に原綴りを使う。

- PopulationSpec
- Population
- Voice
- Community
- Placement
- Consonance Field
- Landscape
- ListenerTwin

たとえばVoiceを「声」、Populationを「集団」とだけ書くと、音響現象としての声や一般的な
集団との区別が消える。必要なら「一個の生きた構成員であるVoice」のように説明を添えるが、
固有語そのものは残す。

関数名、定数名、実際の変数名はバッククォートで囲む。上記のオントロジー語は文章中の
固有名詞として使うため、通常の本文ではバッククォートを必須としない。型として明示する
必要がある箇所では`Voice`のように表記してよい。

## 一般語は自然な日本語にする

| 英語原文 | 日本語本文で使う語 |
|---|---|
| founder voice | 初代として生成されるVoice |
| live patch | 実行中の更新 |
| runtime | 実行時 |
| handle | 参照 |
| default | 既定値、初期状態 |
| score / level | 評価値 / 水準 |
| density / mass | 密度 / 正規化前の重み |
| lifecycle / viability | 生存過程 / 生存可能性 |
| respawn | 再生成、世代交代 |

ただし「初代の声」のような説明語を、Voiceそのものの代名詞として使い続けない。
「初代として生成されるVoice」のように、どのオントロジー要素を説明しているかを残す。

## 書き方

1. 英語の文を一文ずつ訳さず、章全体を読んで要点と因果関係を先に整理する。
2. 各段落を「何が起きるか」「なぜ必要か」「どう使うか」の順で日本語として組み立てる。
3. 主語が連続する長文を避け、一文には一つの判断だけを書く。
4. 英語の名詞へ日本語の助詞を付けただけの表現を避ける。
5. 専門語は日本語へ置き換えて曖昧になる場合だけ原語を併記する。
6. コード例、数式、数値、APIの意味、章間リンクは英語版と一致させる。

避ける例：

> VoiceのPopulationがField内をmovementする。

推奨：

> Populationを構成するVoiceは、Consonance Fieldに沿って移動する。

> このPopulationは`place()`が返す参照を通じて操作できる。

## 更新手順

1. 対応する英語章を最後まで読む。
2. 英語章の見出し、事実、リンク、`rhai`コード例を確認する。
3. 日本語章をこの規約に従って独立した文章として書く。
4. `cargo test --test rhai_book_examples -- --nocapture`で章構成とコード例を確認する。
5. `cargo test --test rhai_book_ja_style -- --nocapture`で既知の翻訳調を検出する。
6. `mdbook build docs/rhai_book_ja`でリンクと出力を確認する。

英語版の章を追加または削除した場合は、同じ変更で日本語版も更新する。翻訳を後回しにする
空ページや英語本文のコピーは追加しない。
