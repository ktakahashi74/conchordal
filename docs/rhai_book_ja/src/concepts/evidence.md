# 機構の根拠と作曲者の選択

Conchordalの語には、[APIリファレンス](../reference/api.md)とエディタの説明表示で、根拠の札が付きます。札は、その機構が何に基づくかを示します。配置、初期の身体、大きな形を指定する語なら、機構には該当しないと示します。設定項目が増えるわけではありません。まず既定の動きで作り、作品に必要な操作を選べます。

## 札を読む

| 札 | 意味 |
|---|---|
| 原理 | 一次資料の根拠と同定された機構があり、公表モデルを原典どおりに採用し、新たな人間のデータ収集を必要としない機構です。入力の機能に付く札は、周囲の実装の全ての式や定数を認定するものではありません。 |
| 候補（出典） | 公表された形式モデルはあるものの、対応する脳の機構が未同定、またはパラメータが特定の課題に合わせた値である仮説です。原典にない補足には、作者規則の札を別に付けます。 |
| 候補（照合未了） | 公表モデルに対応する部分を特定した段階で、原典との一致は未確認です。受入済みの候補を意味しません。 |
| 作者規則 | 対応する公表形式モデルを持たず、作者が形や閾値、値を選んだ機構です。感覚の情報を使う行為則も、それだけで原理にはなりません。 |
| 該当なし（種類） | 配置、初期の身体、大きな形、経路、運転、データです。入力や行為の根拠は、参照先の語の札で確認します。 |

一つの語にも、部分ごとに違う札が付きます。`metric()`では、入力となる拍の知覚機能は原理です。Largeの神経共鳴振動子の形とLarge & Jones（1999）の利得は、原典との照合が未了の候補として記します。参加の規則や結合の既定値は作者規則です。また、`consonance()`は配置の操作です。H/Rと作者が定めた協和の評価を読み、選択規則を適用します。操作全体を感覚の原理と呼ぶわけではありません。

`follow_own_sequence(w)`では、PPM-Decay（Harrisonほか、2020）の候補モデルと、作者が定めた音程の符号化・生成への接続を分けています。既存の原典fixtureで照合するのは分布、情報量、学習状態であり、R APIや乱数生成器の同値性ではありません。重みの既定値は0で、明示して使う語です。対応する実行経路と資源の制限は[リズム](rhythm.md)を参照してください。

`phrase_boundary(w)`では、LBDM（Cambouropoulos、2001）の候補モデルと、作者が定めた有限列の完備化、6 Onのオンライン接続、出生時に固定する上限、境界判明後の合法なSine On一件へのgainを分けています。実装の検査は原著プログラムやcorpus成績の再現ではありません。重みの既定値は0で、既定の聴き手の型には含めません。対応範囲と反応の期限は[リズム](rhythm.md)を参照してください。

根拠の段は、公開用途の **Core / Experimental / Tuning / Research** とは独立です。Experimentalだから候補、Coreだから原理、とは読めません。

## 既定で働く機構

原理は既定で働きます。同時に、楽器の基本動作を作ってきた作者規則も維持されます。移動費用、tessituraへの引力、協和の評価、馴化の定数、参加、代謝、生存過程の規則が該当します。例えば移動費用は0.5、解決後のtessituraへの引力は0.1のままです。これらの値は作者の選択であり、感覚の原理から導かれた定数ではありません。札の追加で音、値、経路、操作は変わりません。

現在の方針では、**新しく加える候補と作者規則の軸は、既定で中立**にします。既存の基本動作を止める指示ではありません。`dwell`、`rest_on_habituation`、`follow_own_sequence`、`phrase_boundary`は、既定の重みが0の任意の操作です。既定の動き、まとめられた設定、個別の操作の順に選びます。簡単な作品を作るために、多くの値を積み重ねる必要はありません。

**既定の聴き手の型は、まだ実装されていません。** 方針では、原典との一致を確認し、作者が試聴して採用した候補を、一つの型にまとめる道を認めています。名前と内容は未決定です。将来は一つの語で、その型を外したり置き換えたりできるようにします。今回の札は型の導入でも、候補の全受入条件を満たしたという宣言でもありません。

## 作曲者が選ぶ範囲

作曲者は、認知を表す層3の座標で、仮説を使うか、その重み、作風に依存する事前分布を選びます。初期条件と大きな形も作曲者の選択です。一方、記憶の統合や学習の内部動態は層4に属します。札を付けても、これらを操作項目として公開したり、層1の感覚入力、粗さ、調和性を変えたりはしません。

APIリファレンスの設定一覧には、位置づけを明示するため研究用の設定も含めています。それらを作曲の操作に昇格させる一覧ではありません。協和の評価係数も、引き続きRhaiへ直接公開しません。

## 受入で確かめる範囲

原理と候補の受入では、原典との数値的一致、登録した因果的な差、宣言した負荷でのリアルタイム動作を確かめます。候補について確かめるのは、仮説どおりに実装できたかです。**仮説そのものの正しさを証明する手続きではありません。** 原理の受入に主観評価の条件はありません。

作者規則では、既定の一致、因果的な差、リアルタイム動作の実装確認に加え、作者の試聴を要します。既定の聴き手の型は、まとめた構成を一度試聴して採用します。試聴で個々の値を順位づける方針ではありません。作曲の操作量の上限は、計算費用ではなく破綻や効果の飽和で定めます。エディタに札が表示されても、これらの受入条件は変わりません。
