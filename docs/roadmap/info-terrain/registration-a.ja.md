## 1. 範囲

- 観測するのは、聴き手側の予測についての二つの候補の指標、驚きと精度である。いずれも Log2Space の bin ごとに求める。
- 二つの版を並べる。
  - **原型版:** Anikin 2026 の式 4 に従う。
  - **拡張版:** 線形予測を使う。authored 層に属する。
- 出力は report と、実測のための記録だけに使う。地形（`Landscape`）にも生成にも、どの経路でも渡さない。
- 設定節 `[info_terrain]` に `enabled = false` を既定値として置く。他の節と同じく `deny_unknown_fields` とする。無効のときは状態も確保しない。

照合した資料：Anikin 2026（*Behav Res Methods* 58、CC BY 4.0、doi:10.3758/s13428-026-03153-3）の本文、OSF bgzvc の解析コード（`analysis/acoustic_analysis.R`、`analysis/optim_*.Rmd`）、OSF に同梱された実装、soundgen 3.0.0 の `R/surprisal.R`。

| 窓のフレーム数 | `floor(winSurp / step)` | 同じ | `floor` |
| 開始時 | 現在を含めて 3 フレームから、短い窓で計算する | 同じ | 変更：窓が埋まるまで欠測（第5節） |
| 標準偏差 | 標本標準偏差 `sd(x1)` | 母標準偏差 | 3.0.0（母標準偏差）。標準偏差の比は `sqrt(n/(n−1))` で、窓 93 フレーム（履歴 n = 92）では約 0.55 % |

| 一定の履歴 | NA | NA | 同じ（第5節） |

## 3. 原型版の規則と変更点

| 項目 | 論文付属 | 本登録 | 理由 |
|---|---|---|---|
| 入力 | `melfcc` の帯域パワー（20 帯域、窓 100 ms、step 20 ms、線形）。周波数範囲と前処理は `melfcc` の既定に従う | NSGT のパワー `P` の平方根、振幅 `a = sqrt(P)`（Log2Space、既定 55–8000 Hz、96 bins/oct）。前処理なし | 既存の解析経路を使うため。パワーから振幅への変更と、帯域ごとに時間応答が違う点（NSGT の窓は周波数に依存する）も変更点として記録する |
| フレーム間隔 | 20 ms | 解析 hop（既定 512/48000 ≈ 10.7 ms） | 同上 |
| 窓 | 1000 ms | `W = floor(1.0 s / hop_sec)` フレーム（既定 93）。現在を含む | 原型の値 |
| 平均・偏差 | 上の表 | 現在を除く `W − 1` フレームについて、2 パスの中心化二乗和で計算する（`f64`） | 桁落ちを避ける（第6節） |
| 評価 | チャネル | bin。scan として保持する | 観測の scan として持つため |

**精度（原型版）。** 現在を除く窓の平均 `m` と母標準偏差 `sd` から、変動係数 `c = sd / m` を求め、`precision_state = 1 / (1 + c²)` とする。

- 原型には精度の指標がないので、これは authored の定義である。`π_ref` は 1 に固定する（`c = 1` で 0.5）。
- これは履歴の散らばりの尺度であり、予測誤差の尺度ではない。
- 振幅の一様な増減に対して不変である。驚き `z` も同様に不変なので、二つの指標はどちらも利得に依存しない。

## 4. 拡張版の規則（authored）

**特徴 `φ_t`（10 次元）。**

- 定数 1
- 直前の振幅 `a_{t−1}`
- その bin の `SpectralHistory` の 8 つの年齢（0.125〜16 s）の RMS

**時刻の順序。** 解析 worker は、時刻 `t` の観測を `SpectralHistory` に入れる前に、A の計算を行う。したがって年齢の特徴は時刻 `t − 1` までの状態から読む。時刻 `t` の値を含めない。

**特徴の尺度。** 振幅の特徴は、すべてその bin の `EMA(a)` で割る。予測の対象も `a_t / EMA(a)` とする。これで学習が振幅の尺度に依存しない。

**年齢の被覆。** `SpectralHistory` の被覆が 0.5 未満の年齢は、その特徴を 1.0（正規化後の中立値）に置き換える。1 秒待っても 16 秒の年齢が満たされるとは限らないので、被覆で扱う。

**予測と残差。**

- `â_t = wᵀ φ_t`
- `e_t = a_t / EMA(a) − â_t`

驚きと精度は、時刻 `t − 1` までの残差統計を使って評価する。そのあとで、残差統計と重みを `e_t` で更新する。

**RLS。** 指数重みつきの RLS とする。演算は `f64`。

```
k = P φ / (λ + φᵀ P φ)
w ← w + k · e_t            （e_t は更新前の重みでの事前残差）
P ← (P − k φᵀ P) / λ
P ← (P + Pᵀ) / 2           （対称化）
```

- `λ = 0.999`（時定数はおよそ 1000 hop ≈ 10.7 s）、初期値 `P = 100 I`、`w = 0`。
- 毎回の更新の直後に検査する。`trace(P) > 1e6` または非有限値なら `P = 100 I` に戻す。重みが非有限なら `w = 0` にも戻し、その hop の値は欠測とする。

**正規化と初期化。**

- 正規化に使う `EMA(a)` は、時刻 `t` の更新前の値 `EMA_{t−1}(a)` とする。
- 拡張版の学習も、窓が埋まってから始める（第5節の 3）。窓が埋まる前は、拡張版の状態を一切更新しない。
- `EMA(a)` は、窓が埋まった後で、次の二つを満たす最初のフレームの現在振幅 `a_t` で初期化する。一つは、その bin が無音でないこと（第5節の 5）。もう一つは、`a_t` が有限で正であること。そのフレームでは RLS を更新せず、残差の EMA も更新せず、拡張版の両方の指標を欠測とする（更新前の `EMA_{t−1}(a)` がないため）。学習と評価は次のフレームから始める。初期化の前は、拡張版を欠測とし、除算をしない。
- 直前振幅の特徴 `a_{t−1}` は、窓のリングバッファから読む。学習は窓が埋まってから始めるので、必ず存在する。

**EMA。**

- 係数は `α = 1 − exp(−hop_sec / τ)` とする。
- `EMA(a)` は `τ = 1 s`。
- 残差の平均と分散は `τ = 1 s` とし、中心化した指数重みの更新で求める（Finch 2009 の形）。どちらも 0 から始める。

```
d = e − μ_e
μ_e ← μ_e + α d
v̂  ← (1 − α) (v̂ + α d²)
```

これは `E[e²] − E[e]²` の差をとらないので、桁落ちが起きない。

**無音中に更新する状態。**

- 原型版のリングバッファは、無音でも常に更新する。
- 拡張版の RLS、残差の EMA、`EMA(a)` は、無音（第5節）の bin では更新しない。発音が再開したら、そのまま続ける（初期化し直さない）。

**指標。**

- 驚き：`S′ = min(e_t² / (2 max(v̂, v_floor)), −ln 1e-12)`
- 精度：`precision_state′ = 1 / (1 + v̂)`（尺度は正規化済み）
- `v_floor = 1e-12`

**非有限値。** 驚き、精度、`v̂`、`μ_e` のいずれかが非有限になったら、その hop の値を欠測とする。その bin の拡張版の状態（`w`、`P`、`μ_e`、`v̂`、`EMA(a)`）は初期状態に戻す。

残差の分散は、恒常的な偏り（`EMA(e)`）を除いた散らばりである。予測に系統的な誤差が残っても、精度の指標はそれを示さない。これを限界として記録する。

**計算量。** bin あたり約 10² の積和で、690 bin で 1 hop あたりおよそ 7 万回。

## 5. 欠測、無音、学習の開始、取りこぼし

判定と状態の操作は、各 hop で次の順に行う。

1. **取りこぼしの検出。** 解析 worker がフレーム番号の不連続を検出し、ストリームをリセットしたときは、評価の前に A の学習の状態を捨てる。対象は、リングバッファ、RLS、EMA、窓を満たすためのカウンタである。ブロックの集計（欠測の数を含む）と、実行全体の損失の累計は捨てずに保持する。取りこぼしがあったブロックには印をつける。
   - `SpectralHistory` は既存の規則のとおり、欠けた区間を未知として先に前進させる。過去は消さない。拡張版の特徴は、その後で読む。
   - habitat 側は hop を落とさない（既存の契約）。presentation 側は落としうる。
2. **NSGT の再充填。** 解析 worker のウォームアップ中（`warmup_samples > 0`）は、A は評価も学習もしない。窓のフレーム数 `W` は、ウォームアップが終わった最初のフレームから数える。
3. **学習の開始。** 窓が埋まるまで（数え始めてから `W` フレーム）は、両方の版とも欠測とし、拡張版の状態も更新しない。窓が埋まるまでは履歴の平均 `m_b` が定義されないので、4 と 5 の無音の判定も行わない。
4. **全体の無音。** 全 bin の窓平均振幅の最大値 `M = max_b m_b` が 0 のとき、すべての bin を欠測とする（床が 0 になるのを先に避ける）。
5. **bin の無音。** `m_b < a_floor = 1e-4 · M`（振幅で −80 dB）のとき、その bin を欠測とする。`m_b` は、現在を除く窓の平均である。
6. **一定の履歴。** 現在を除く窓のすべての値が等しい（範囲が厳密に 0）とき、原型版の驚きは欠測とし、原型版の精度は `c = 0` から 1 とする。数値上の分散が 0 でも範囲が正なら、一定とは扱わない。

**欠測の表し方。** 欠測は scan では `NaN` で表し、別に欠測 bin の数を記録する。report では `null` とする。scan の長さは常に `n_bins()` とする（F1）。

## 6. 置き場所、数値、出力

**置き場所。**

- 解析 worker（`src/core/analysis_worker.rs`）の中で、ストリームごとに独立に計算する。habitat 用は常に、presentation 用は listener 解析が動いているときだけ動く。既存の habituation と同じく、生態系側と聴き手側を別の状態として持つ。
- 解析 worker は hop 経路の割当規則の対象外だが、それでもバッファは有効化の時点で確保する。

**数値。** 平均と分散は、毎 hop、リングバッファから 2 パスの中心化二乗和で計算する（`f64`）。累積和は使わない。費用は 93 × 690 ≈ 6.5 万回の加算で、許容できる。

**出力の型。**

- bin ごとの scan（両方の版の驚きと精度）は、解析 worker の中の状態として持つ。`AnalysisResult` にも `Landscape` にも入れない。worker の外へ出るのは、下の集約だけである。将来 UI に scan が必要になったら、同じ専用チャネルで送る。
- scan を受け渡すすべての境界（worker の中の関数の間を含む）で、`Log2Space::assert_scan_len_named` を呼ぶ（F2）。

**集約。**

- **ブロック。** worker の中で、1 秒ごとのブロックについて集約する。フレームの開始サンプル `s` に対し、ブロック番号は `floor(s / fs)` とする。各 hop はちょうど一つのブロックに属し、分割はしない。
- **hop ごとの統合スカラー。** 両方の版について、二つの規則で求める（3.0.0 の規則と OSF 同梱版の規則）。統合スカラーは、欠測でない bin の驚きの重みつき和である。重みの規則は第2節の表による。欠測でない bin が一つもない hop では、統合スカラーも欠測とする。
- **ブロックの量。** 分母は、指標ごと、bin ごとに数える。
  - **驚き:** 統合スカラー `S` について、時間平均は `ΣS / N`（`N` は `S` が定義された hop の数）、時間最大値は定義された hop の中の `max S` とする。
  - **精度:** hop ごとの振幅重みつき平均の分母は、精度が定義された hop の数とする。驚きが欠測でも精度が定義されていれば（一定の履歴など）、精度は数える。
  - **bin ごとの時間平均:** その bin でその指標が定義された hop の数で割る。
  - **振幅の重み（精度の平均）:** 現在を除く窓の平均 `m_b`（評価と同じ時刻の基準）を使う。精度が定義された bin の中で、総和 1 に正規化する。この正規化し直しは精度の平均だけに使う。驚きの統合スカラーには使わず、第2節の表の規則（3.0.0 は正規化し直さない重みつき和）に従う。
  - **分位点の重み:** bin ごとの驚きの時間平均に対する重みは、その bin で驚きが定義された hop について `m_b` を時間平均したものとする。
  - 統合スカラーの時間平均と時間最大値。
  - bin ごとの驚きの時間平均を、その bin の時間平均振幅で重みづけした、bin 間の中央値と 90 パーセンタイル。
  - 精度の状態について、hop ごとに振幅重みつき平均をとり、さらにその時間平均をとったもの。
  - 欠測した (bin, hop) の数と、統合スカラーが欠測した hop の数。
  - ある指標が、ブロックのすべての hop で欠測なら、その指標の量を `null` とし、数だけを記録する。
- **重みつき分位点。** 値を昇順に並べ、重みを総和 1 に正規化する。各値の累積重みの中点を位置とし、目標の確率 `q` の位置を線形補間で求める。`q` が最初の中点より小さければ最小値を、最後の中点より大きければ最大値をとる。
- **trace。** 実測用の設定 `trace = true` のときは、各 hop の統合スカラーをブロックに添えてすべて記録する。

**配送。**

- 集約は、解析結果（`AnalysisResult`）には添付しない。A 専用のチャネルで送る。
- 各ブロックは、ブロック番号、ストリームの種類、含まれる hop の範囲、そのブロックの中で取りこぼしがあったかどうかの印を持つ。
- ストリームが終わるとき（入力のチャネルが閉じたとき）は、worker が端数のブロックを「不完全」の印をつけて送り、そのストリームの専用チャネルを閉じる。
- runtime は終了時に、両方のストリームの専用チャネルが閉じるまで取り出しを続ける。そのあとで report の書き込みを完了させる。損失したブロックの総数は、report の最後の集計レコードに書く。
- runtime は、毎 hop、このチャネルから受信できるものをすべて取り出す（最新の一つだけを選ぶことはしない）。`--report` のときだけ report に書く。
- 決定論的な解析（offline render）では送信をブロックさせるので、ブロックは失われない。実時間の実行で送信が詰まったときは、捨てたブロックの数を記録する。その実行は損失ありとして扱い、第7節の実測には使わない（実測は offline の決定論的な実行だけで行う）。

**不変性（検証すべき要件）。**

- 無効のときは、既存の出力が bit 単位で一致する（`tests/flora_invariance.rs` の参照）。
- 有効のときについては、まだ断定しない。値を読む経路がなくても、追加の負荷が解析の到着時刻や presentation の取りこぼしに影響しうるためである。そこで二つを分けて検証する。
  - **決定論的な出力：** 同じ設定、seed、report の条件で、offline render の WAV が off と on で一致すること。
  - **実時間：** 解析の遅れと presentation の取りこぼしの数を、off と on で測って記録する。

## 7. 実測の手順（試聴と照合のため。合否の閾値は置かない）

### 7.1 統制刺激

offline render、48 kHz、各 20 秒。評価区間は 2〜20 s とする。

- **レベルの基準。** 表の「−12 dBFS」は、ピーク −12 dBFS の正弦波と同じ RMS を意味する。つまり RMS = `10^(−12/20) / √2` で、フルスケール振幅 1 を基準にした RMS では約 −15.01 dB にあたる。
- **雑音の生成。** 白色雑音は、splitmix64 による一様乱数から Box–Muller 法で作ったガウス雑音とする。pink 雑音は、白色雑音に Kellet の 3 次フィルタ（Paul Kellet の「economy」版）をかけて作る。どちらも 20 秒全体の RMS で正規化する。

| 番号 | 刺激 | レベル・seed |
|---|---|---|
| 1 | 定常の純音 440 Hz、位相 0 から始める | −12 dBFS |
| 2a | 白色雑音 | −12 dBFS、seed 1 |
| 2b | 2a と同じ波形を −30 dB にしたもの | 2a − 30 dB |
| 3 | pink 雑音 | −12 dBFS、seed 2 |
| 4 | 決定論的な周期：0 s から 440 Hz、0.5 s から 660 Hz、以後 500 ms ごとに交互。各区間の正弦波は区間の開始で位相 0 から始め、境界の前後 5 ms ずつ（計 10 ms）を raised-cosine で切り替える | −12 dBFS |

### 7.3 仮説

**適用先。**

- 統制刺激 1〜5 は、habitat の解析と同じコード経路に WAV を直接通す評価用のハーネスで解析する（crate 内部の試験、既定では実行しない）。刺激 6 と 7 は、offline render の `--report` で habitat ストリームを記録する。
- 仮説はすべて habitat 相当のストリームの、3.0.0 の統合規則による値に当てはめる。原型版と拡張版の両方に当てはめ、版ごとに結果を記録する。

審査草案 §5 の未検証の仮説を、新しい定義に合わせて登録する。比較の基準は、1 と 2a の値とする。

- **比較する統計量:** 仮説 1〜3 の「小さい」「高い」は、評価区間 2〜20 s の定義された hop についての、驚きの統合スカラーの時間平均と、精度の振幅重みつき平均の時間平均で比べる。
- **1：** 驚きは 2a より小さく、精度は 2a より高い。純音で驚きが全欠測になった場合（履歴が厳密に一定）は、驚きの比較はできないと記録し、精度だけを比べる。
- **2a と 2b：** 厳密な演算の下では、振幅、`m`、`sd`、`M`、`a_floor` がすべて同じ比で変わるので、欠測のマスクも二つの指標も一致する。これは仮説ではなく、実装の検査として扱う。
  - 欠測のマスクは完全に一致すること。
  - 数値は `|x − y| ≤ 1e-6 + 1e-4 · max(|x|, |y|)` を満たすこと（0 付近でも定義される）。
  - 外れたら、丸め、量子化、初期化、実装のどれに由来するかを切り分ける。NSGT や解析経路に絶対的な床があれば、それもこの検査で見つかる。
- **3：** 精度と驚きはともに 1 と 2a の間に入りうる。仮説の向きは定めない。
- **4：** 原型版では、切り替えのたびに驚きが残る。拡張版では、学習が進むにつれて驚きが減りうる。
- **5：** trace から、6.5、10.5、14.5、18.5 s に始まる 500 ms の各区間について、統合スカラーの最大値を求める。それが 4 の同じ区間の最大値より大きくなる。なお、置き換えの直前の履歴が一定だと、原型版では欠測になりうる。

### 7.4 原型への外部照合

新しい被験者データは使わない。

- **データ：** Anikin 2026 の刺激 300 本（OSF `stimuli.zip`）。予測不能性の推定値は `1 − fit` とする。`fit` は、OSF の `data/fit_per_sound.csv` にある、多階層モデル（brms）が出した刺激ごとの予測可能性である。結合のキーは `token` とする。`token` は、ファイル名から拡張子を除き `_` で区切った 2 番目の欄である（例：`bark_aOQbMp_0_0.25` の `aOQbMp`。公開コード `acoustic_analysis.R` の分割に従う）。結合できない刺激は除き、その数と最終的な本数を記録する。
- **比較する版：** 入力（3 通り）と規則（2 通り）の組で、6 版を求める。
  - **入力：**
    - **R:** 参照に近い近似。前処理なし、Hann 窓 100 ms、step 20 ms、FFT 長 8192 とする。0 Hz からナイキスト周波数までを HTK mel 尺度で等分した 20 帯域の三角形フィルタの、帯域パワーを使う。フレームは 0 サンプルから始め、端数のフレームは捨てる。`melfcc` の正確な再現ではないので、細部の違いを記録する。
    - **N:** NSGT の振幅。
    - **N-P:** NSGT のパワー。
  - **規則：**
    - **S:** soundgen 3.0.0 の規則。開始時は短い窓で計算し、一定の履歴は NA とし、統合は 3.0.0 の重みで行う。
    - **O:** 本登録の規則。開始時は欠測とし、無音のマスクを使う。統合は 3.0.0 の重みで行う。
  - **主比較と補助比較:** 系列の値には、3.0.0 の統合規則によるものを主比較として使う。OSF 同梱版の統合規則による値は、補助比較として記録する。
  - **事前に定める対比：**
    - 同じ入力で規則を変える（R-S と R-O）。
    - 同じ規則で入力を変える（R-S と N-S、N-S と N-P-S）。
  - soundgen そのものは R が使えないため実行しない。式は 3.0.0 のソースから移植する。移植が正しいことは、短い数列についてソースの意味どおりに手計算した期待値（一定の履歴で NA、`min(½ z², …)`、重みの規則、欠測の重みつき和）と比べる単体試験で確かめる。
  - R と N の差には、帯域の表現だけでなく、hop の間隔、帯域の配置、帯域ごとの時間応答の違いも含まれる。したがってこの対比は、表現の違いではなく「解析経路全体の差」の目安として扱う。
- **刺激の前処理:**
  - OSF の `stimuli.zip` は MP3（64 kbps、44.1 kHz、ステレオ）303 本である。
  - macOS の `afconvert`（macOS 26.6.2 付属版）で 44.1 kHz の線形 PCM に復号し、左右の平均でモノラルにする。
  - 全版を 44.1 kHz のまま解析し、リサンプルはしない。R の窓は `round(0.1 · fs) = 4410`、step は `round(0.02 · fs) = 882` サンプルとする。N と N-P は、解析ストリームを 44.1 kHz、hop 512（≈ 11.6 ms）で構成する。
  - MP3 の符号化遅延による先頭の無音は取り除かない。その影響は留保として記録する。
  - 論文の解析が MP3 と原音源のどちらを使ったかは、公開資料から確認できていない。
- **求める量：** 各版の刺激ごとのフレーム平均と `1 − fit` の、ピアソン相関。
- **比べる相手：** 論文の報告値（r > .6）。R と N の差を、解析経路全体の差の目安とする。N と N-P の差を、振幅とパワーの違いの目安とする。
- **比較の集合：** すべての版で系列の値が定義された刺激の共通集合で比べる。版ごとに、除外した刺激と理由（結合の失敗、全欠測）を記録する。
- **信頼区間：** 25 の原型を単位とするクラスタ・ブートストラップ（10000 回、復元抽出）で、95 % パーセンタイル区間を求める。各回の再標本は全版に共通に使い、版間の相関の差（R − N、N − N-P）の区間も同じ再標本から求める。`fit` の推定の不確かさ（`lwr` / `upr`）は別の留保として記録し、信頼区間には含めない。
- 閾値は置かない。

## 8. 二層分類

- 驚きの式（`min(½ z², …)`、現在を除く窓、母標準偏差）は、原典（soundgen 3.0.0、および論文付属版との差を明記したもの）と照合した既存の刺激→知覚モデルの部分である。
