# Manifesto Conchordal に基づく機能整合と beta 計画

更新日: 2026-09-05
基準: v0.4.0、`390ae1e` に続くローカル改善実装
状態: 基盤修正を実装・検証済み。以下の機能拡張は計画であり、実装済みではない。

## 目的と判断の基準

[Manifesto Conchordal](../../web/content/manifesto.ja.md)の目的は、聴覚認知を
Landscapeとして実装し、その環境とVoiceの局所的な相互作用から音楽を生むことにある。
次の開発では、既存機構の数を増やすことではなく、その相互作用が聞き取れる結果を
生むことを合格条件にする。実装上の正しさ、モデルの妥当性、音楽的な説得力は別々に評価する。

原則と機構のスケッチは区別する。Manifestoの固定delta/theta/alpha/beta表は、
すでに創発するbeat・subdivision・measureへ改訂されている。遅い構造をすべて低速の
振動子へ置き換える計画にはしない。原理との対応と新しい知見の正本は
[技術ノート第9章](../../web/content/technote.ja.md)とする。
この文書は実施順序と受入条件を管理する。

維持する境界は次のとおり。

- 音名・音階・拍子記号の列を生成エンジンの必須中間表現にしない。連続周波数と実音の特徴を使う。
- Voiceの判断は局所的な知覚と状態から導く。共有meterは集団自身の音から生まれ、外部の拍送りにしない。
- Scenarioは人間によるマクロの演出を担う。期待モデルを追加しても、作者の構成を自動的に上書きしない。
- ListenerTwinの証拠はpresentation busだけから得る。予測には`pred_`、実音分析には`perc_`を使い、
  同じ層で両者を区別する必要がある場合だけ接頭辞を付ける。
- 周波数方向の新しい`*_scan`はLog2Spaceへ整列させる。時系列イベントや記憶グラフにはこの接尾辞を使わない。
- 楽器`conchordal`は音声を保存しない。比較用WAVは別バイナリ`conchordal-render`だけで作る。

## 0. 今回完了した整合修正

| 問題 | 修正後の契約 | 検証 |
|---|---|---|
| render中の再生成が後続VoiceのIDを消費 | 全ScenarioのIDを共通初期化で予約 | 時間差配置と高頻度再生成を組み合わせたrender回帰テスト |
| Field配置が指定Hz範囲を逸脱 | 両端を正順化し、揺らぎ・占有回避・代替抽選も範囲内へ制限 | 狭帯域、逆順、一点、解析端、全占有、解析域外の境界テスト |
| 解析域外のanchorが解析端へ移動 | anchorは音源許容域内の指定周波数を保持。探索移動は解析域を使う | 低域・高域の配置を50hop進めて実周波数と目標を確認 |
| 無効な設定がpanicや生成停止を起こす | sample rate・FFT・hop・latencyを入口で検証し、ring容量を最低1hop確保 | 設定境界と機器不要のバッファテスト |
| listenerの欠落音声を連続した入力として分析 | 欠落時に観測を無効化し、NSGT履歴を消去。連続した1窓分の入力後に再開 | 欠落通知、回復前の観測抑制、古い観測の再流入拒否 |
| DCCが解決可能性を二重乗算 | `pressure = tension_level * coupling_strength`。解決可能性はtension内で一度だけ反映 | 同一の聴取音で結合の有無を比較し、生成側の音高変化を確認 |
| RT監視とrelease回復処理の検査不足 | hop全体と分析待ちを計測し、音声出力不足を集計。Linux CIにrelease検査を追加 | callbackの不足検出テスト、release用phonationテスト |
| Habituation入力長の不一致をゼロ補完 | Log2Spaceとの長さ不一致は明示的に失敗 | 短い入力・長い入力の境界テスト |
| ListenerTwinがERB密度を直接重み付け | 密度×ERB積分幅の質量でstability・resolvability・証拠量を統一 | 等質量ピーク、無音境界、空間変更、scan長のテスト |
| 小幅な音量操作が持続音へ届かない | 明示的なamp変更を既存Toneへ一度反映し、自律的な微小変動の抑制は維持 | 小音量調整、mute/resume、同値再指定の回帰テスト |
| Sample 12のglide時定数だけが変わりGateSnapが残る | 24秒でGlideモードを明示し、Rhai参照に両者の違いを記載 | 日英API再生成と例の検査、修正版24条件のrender |
| flowを削除すると登場前の再生成IDと乱数系列が変わる | renderer限定のID予約を全条件で揃える | 24条件を再測定し、flow有無の全12組で介入前PCM・状態が一致 |
| 機器接続失敗を含む実行を実機性能として扱う危険 | headless初期化失敗は非0。report独立のprofileで機器・出力不足・worker割当を記録 | failure経路と計測窓の回帰、MOTU M2出力の36条件 |

Field配置は、解析帯域との共通部分があればそこを使い、共通部分がなければ指定域の
対数一様分布へ切り替わる。後者は協和性を推定した結果ではない。RhaiのField配置の両端は
音源許容域1〜20000 Hz内の有限値に限る。配置後の`seek_consonance()`は初期配置範囲に拘束されない。

検証記録: 通常Rustテスト659件、profile-alloc付き660件、比較runnerのPythonテスト35件が成功。両ビルドでClippy通過。全出力と終了値は`test_report.txt`・
`test_status.txt`、release検査は`test_report_release.txt`・`test_status_release.txt`。
feature付きの全出力・終了値は`target/rt-validation/`に保存した。
これらはローカル生成物。自動テストの成功自体は、実機性能や試聴の合格を意味しない。

## 1. 現行版の評価基準を作る

依存: 基盤修正。最初に実行する開発単位。

進捗（2026-09-05）: [比較手順](beta-evaluation.md)を実装し、標準12条件の
[測定表と試聴用WAV](beta-baseline-2026-09-05.md)を作成した。未観測PLVを`null`へ修正し、
再測定した全12WAVが修正前と一致することも確認した。続いてsample 12の温度・音高移動・flowを
8組×3seedで比較し、制御修正前後の計48条件の[結果と試聴ページ](resolution-assay-2026-09-05.md)を作成した。
指標の質量重み、小幅な音量操作、glide指定の不整合を修正したが、tension低下はseed依存のままである。
さらに[ID予約を揃えた24条件と実機36条件](flow-controls-and-runtime-load-2026-09-05.md)を実行した。
flow比較は全12組で介入前のPCM・状態が一致した。MOTU M2で4・16・64 Voice × 3音色 × report/DCCの
36条件が性能基準を満たし、測定窓の出力不足はゼロ、最大hop p99は2.651 msだった。
worker割当は計測済み。作者の補足により、glide ONの試聴条件で協和音へ落ち着きやすいことも確認された。
音量操作の効果は判定保留、曲の区切り・終止感は未判定とする。seed・時刻が未指定のため個別条件へ一般化しない。
曲全体の受入判定、密な発音・長時間演奏の負荷、analysis/callback/nativeの割当は残っている。

[Alphaの受入記録](v0.4.0-alpha-acceptance.md)は機能統合を合格とし、拍・和声展開・
曲全体の形の試聴課題をbetaへ持ち越した。[既存のrhythm結果表](v0.4.0-rhythm-report-runs.md)は
再設計前の記録であり、現行版の測定値として再利用しない。

実施内容:

1. samples 07・08・09・12をseed 1・21・42で比較する。公開sample本体にseedは埋め込まず、
   CLIから指定する。研究用の比較シナリオを追加する場合は`samples/research/`へ置く。
2. commit、未コミット差分、設定、seed、sample、sample rate、hop、ビルド条件を各結果に添付する。
   音楽評価にはreleaseを使い、JSONLと別バイナリのWAVを同じ条件で作る。
3. 07–09では拍の可聴性、同期が成立するまでの時間、非拍節的なまとまりを別々に評価する。
   12では緊張から解放への変化と区切りを、コードを見ない試聴でも識別できるか記録する。
4. 4・16・64 Voice、sine・harmonic・modalで負荷を測る。報告の有無とDCCの有無を分け、
   起動時の準備期間も明記する。今回追加した待ち時間・出力不足の集計に加え、
   hop時間のp95/p99と割当数を測る再利用可能な実行手順を作る。

合格条件:

- 全比較に再実行できる条件と生データが揃う。旧版の数値や異なるseedの結果で穴を埋めない。
- 宣言した実機・同時Voice数で、定常時の出力不足がゼロ。hop全体のp99がhop時間以内。
  未達条件は対応性能として公表せず、ボトルネックを特定する。
- 作者の試聴判定を拍・和声展開・区切りごとに残す。測定値が改善しても試聴未達なら未達とする。
  聞き取れる変化の時刻と、どの局所機構・Scenario操作が寄与したかを対応づける。

成果物: 比較実行手順、現行版の測定表、試聴票、betaで扱う同時Voice数の範囲。
この段階で長い作品や新しい認知モデルは追加しない。

## 2. 既存の閉ループを音楽的に成立させる

依存: 第1段階で未達条件を特定していること。次の三課題は独立した小変更として扱う。

| 課題 | 最小の実装・実験 | 合格条件 |
|---|---|---|
| 小節アクセントの生成 | 既存のmeasure位相・確信度を、Voiceの局所的な発音強度や回復へ弱く接続する候補を比較。固定拍子や別の拍送りは導入しない | 入力の強弱を検出できるだけでなく、生成音側に反復する強弱が生じる。一様入力の対照では架空の小節を主張しない |
| Habituationの回復と再訪 | 移動するargmaxではなく、同じ周波数領域を追跡。刺激持続→退出→回復→再訪をon/offで比較 | 同じ領域の侵食と回復を観測し、再訪が回復に依存するか判定。現在のPARTIAL判定はこの結果が揃うまで維持 |
| DCCの実用的な結合強度 | 固定した聴取音・同じseedで結合強度を段階比較し、探索量と解決までの時間を測る | 結合ゼロは基準と一致。非ゼロで予測した効果があり、上限を守り、持続的な過剰探索を起こさない。欠落中は圧力ゼロ、回復後だけ再開 |

今回のDCC因果テストは効果を検出するために増幅した条件であり、推奨設定ではない。
デフォルトの結合強度はゼロを維持する。Habituationの既存検証と残課題は
[設計記録](../superpowers/specs/2026-07-17-habituation-field-design.md#assay-results-and-closure-verdict-2026-07-17)を参照。

## 3. 短い期待と終止を、まず観測できるようにする

依存: 第1段階の比較環境と第2段階の安定した短時間の閉ループ。

順応はすでに実装されている。追加する対象は「次に何が起きると予測するか」と、
「何が起きたら一区切りと知覚するか」である。

最初はListenerTwinの受動的な観測機能として、短い記憶、次の変化の予測誤差、
境界・終止の候補を報告する。入力はpresentation側の音高顕著性、音色の変化、
発音間隔、沈黙など、実音から得られる特徴に限る。生成側のVoice ID、Scenarioのsection名、
将来イベントを観測モデルへ渡さない。

最小比較は、同じ短い輪郭の反復、一部を変えた反復、順序を崩した対照。
音量差だけを検出していないか、移調しても相対的な輪郭を扱えるかを調べる。
何を予測するかを一つの比較で確定してから数学的表現を選ぶ。
時定数を遅くしたmeterだけでphraseを表さない。

合格条件:

- 未見の次イベントを評価し、事後的に正解を読んでいない。無音・不規則入力で確信を過大評価しない。
- 反復、変更、順序破壊を区別する観測があり、作者の区切り・終止の判断との一致と不一致を記録する。
- 短い記憶の上限と更新コストを明示し、第1段階のRT条件を満たす。
- 受動観測が役立つと確認してから、局所的な探索・発音への結合を一つだけ試す。
  西洋調性の終止規則や特定の秒数を普遍的な不変条件にしない。

成果物: 短い検証シナリオ、記憶・期待・境界の観測契約、受動レポート、結合導入の判断。
sectionの自律生成と長編formの記憶グラフは、この段階では実装しない。

## 4. 個人差・生体信号・長時間構造を段階的に接続する

次の項目は同時着手せず、それぞれの前提を満たしてから具体的な実装仕様にする。

| 拡張 | 前提と次の設計作業 | 受入条件 |
|---|---|---|
| 個人差・文化差を持つLandscape | 第1段階の比較刺激を使い、既存係数で表せる差と不足する表現を切り分ける。環境設定と聴き手固有設定の所有者を分ける | 設定変更が指定した評価軸へ作用し、無関係な軸を勝手に変えない。新しい固定音階への量子化を必須にしない |
| 実生体信号によるDCC | 第2段階で有効な圧力と上限を確定。まず人工入力で時刻・遅延・欠落・再接続を検証し、次に一種類の実センサーを受動接続 | 有効性と経過時間を確認できる入力だけを使い、欠落・古い入力では中立に戻る。模擬信号の成功を実聴者での有効性と取り違えない |
| section・長編formの記憶 | 第3段階で役立つphrase表現を得る。反復・変奏・回帰の記憶を受動的に比較する | 長い音響パターンを区別でき、Scenarioによる作者の構成を保つ。独立した観測上の利点がない記憶グラフは追加しない |

時間尺度ごとの考え方は[既存の階層設計メモ](../design-notes/dcc-neurocognitive-hierarchy.md)を
参照する。ただし、その記述は設計仮説であり、各機構の妥当性を検証済みとは扱わない。
空間音響、音色の遺伝・種分化、複数聴取者の参加、他芸術領域への展開は、この計画の後続候補とする。
音色遺伝へ進む場合も、現在の音高中心の継承と区別し、まず変異ゼロで親の音色パラメータを
保持する条件、変異が指定範囲内に収まる条件、継承なしの対照を定義する。

## 実装単位と終了条件

各変更は「Manifestoの公約 → 観測する現象 → 最小機構 → 対照条件 → 受入判定」で記述する。
公開APIは実際の利用者が必要とする範囲に限り、研究段階の操作を最初から一般向け設定へ増やさない。
生成Rhai参照は登録情報から再生成し、手書きしない。技術ノートの日英台帳は同じ判定に保つ。

第1段階の比較手順、標準12条件、ID予約を揃えたsample 12の24条件、固定集団の実機36条件の測定表は完成した。
作者の補足により、glide ONでの協和への落ち着きは聞き取れた。次はglide・基準音の帰還を共通にし、
24秒のflowの減音の有無だけを比較する[2条件の試聴計画](flow-controls-and-runtime-load-2026-09-05.md#次の判断)を実施する。
この2条件は未生成である。音量操作による差の可聴性と落ち着きへの寄与を別々に記録し、その結果から第2段階の実装順と
受動的な短期期待モデルの必要性を判断する。判断保留だけを理由にモデルを追加しない。
betaの完了は、全自動テストの成功に加え、対応性能の範囲内で動く作品例について
拍・和声展開・曲全体の形を作者が受け入れ、その判断を再現条件とともに残した時点とする。
