## 直近の再開点

T-30は作者が「Bのほうがよい」と回答済み。デモの下書きでは主旋律だけ`leave_self_out(false)`とし、全声部へ広げたCは採らない。
E-11の回答は「1：open 2:いいえ」。Furnace and Braidの次の基準は、床なし・主旋律だけ自己包含のv2に80〜112秒だけ全声部flowを置いたOpen Timeである。
Copper and Glassは床なしのv2へ差し替えず、根音の床あり・動く声部が自己除外する旧版を残す。この違いを一般規則にしない。
E-9の「3分間同じ拍で退屈」への後続はこの比較であり、旧二版への回答待ちには戻さない。

1. T-31の保存音を聴き、音高提案の近似を修正候補へ置き換えるかを作者へ返す。現行`approx`は自己の倍音位置の場全体を引き、現在位置の得点をほぼ0にする。
   候補は身体スペクトル投影から自己の割合を推定し、残余を既存H／R kernelで評価する隔離試作である。採用する場合は自己モデルと実レンダーの適合確認、またはレンダー由来経路の具体化と受理が必要になる。
2. 生存選択の`viability_scope("environment")`の近似も変えるかを、音高提案と独立に返す。今回の試作は従来式を保持している。変える場合は登録済み六条件assayの新しい比較取得が生じ、既存結果は保存する。
3. 自己除外が有効な場合の既定modeを`exact`へ変えるかを返す。現行の`exact`も基本波の一bin全量除去であり、空binでは旧近似へ戻る。自己の寄与だけの除去が完成するわけではない。
   採る場合は文書と既定modeを変更し、対象負荷で実時間確認を行う。自己除外そのものの既定falseは別である。
4. 次の版の番号とReleaseの扱いを作者に確認する。CHANGELOGはUnreleasedのまま。曲の段の完成判定と公開条件も未定であり、ここで番号や条件を補わない。

リポジトリのrootで、次のcommandを使う。再生は作者の指示を受けて行う。

```bash
./.orchestration/units/T-31/listen.sh
./.orchestration/units/T-31/listen-samples.sh
```

`listen.sh`はOpen Timeの現行→修正候補→既存exact、続いてCopper旧版の同じ三方式を通して再生する。
`listen-samples.sh`はsamples 13〜16の各現行→修正候補を通して再生する。描画と再生用scriptはmachine-localであり、別のmachineでは保存物の所在を確認する。
保存上の制約は[証拠の所在](../operations/evidence-locations.md)にある。三判断は未決で、試作の検査通過やoffline描画を本体への採用・実時間合格・作品の採択へ読み替えない。

T-28の私有の運動の型は、形成・区切り・変奏を原理から導けない設計問題として返されたままである。
作者はL3の最終形を曲の段の後へ延期している。E-11の回答を実装開始の指示とは読まない。E-10の人為的な根音移動も不採用のままである。
