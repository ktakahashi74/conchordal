現在の状態: 通常Voice・PhonationEngineへ接続済み。周期と音長を同時に追従させる実験は
Sample 08の流れへの評価を受けて一度戻した。その後、周期追従を保ちながら音長を固有周期で
固定したBへ、作者は「自然になった」と回答した。この分離を本体へ反映する。
所見のseed・再生範囲・Bという対象名は回答中に明示されておらず、直前の案内に基づく対応付けである。
その後の09への僅かなA選好と12の流れ維持を受け、現在はentrainedに周期追従を残し、
flowの更新間隔は固有周期を基準とする。標準12条件の保存音源との一致を確認した。
その後、無音からの再参加の回帰テストを追加し、通常Rustテスト705件が通過した。
現行08の縮退確認への回答は「縮退してない」。この試聴で元の一拍への縮退が残らないと確認し、
現行の周期・音長の分離とentrained／flowの役割分担を採用する。回答の対応範囲は「元の縮退への試聴確認」に記す。
以下は基準測定からの経過記録であり、各段階の測定はその時点の実装だけに対応する。
現行の音の実装は「entrainedとflowの周期追従を分ける」、後続の検証はそれ以降の各節を参照。

## 実行した比較

`scripts/evaluate_rhythm_perception.py`が研究用PCM16音源とイベントの正解情報を別々に作る。
`core::meter::audio_assay::export_audio_perception_assay`はWAVだけを読み、現行の
`DorsalStream`から`MeterNetwork`へ渡す。正解のイベント時刻・音色ラベル・seedは解析へ渡さない。
内部onset指令による補強も生成へのフィードバックもない。
ハーネスは`#[cfg(test)]`だけに存在し、楽器の音声保存経路や公開APIを追加していない。

基準は10条件×seed 1・21・42の30音源。6つの本試験に、間隔並べ替え対照、
1.4 Hzと2.6 Hzのパルス、全無音を加えた。各40秒、48 kHz、hop 512。
各音源を無指定のmeterとSample 08相当の事前条件（basin 1.6–2.0 Hz、stability 0.45）で解析した。
後者はその帯域外の入力へ追従できるという試験ではなく、事前条件の作用を分離する比較である。

追加検証は、初期比較で使わなかった3音色の交替、±25 msのjitter、間隔が不均等な
1.37秒周期、同じ間隔の並べ替え対照を、seed 7・57・113で生成した12音源。
解析器へ渡す条件を変えず、合計42音源・84本の観測を保存した。
波形、イベント、観測CSV、ソースの写しとhash、ライブラリtest binaryのhashを保存している。

```bash
python3 scripts/evaluate_rhythm_perception.py \
  --output target/rhythm-perception/2026-09-06-baseline
python3 scripts/evaluate_rhythm_perception.py \
  --output target/rhythm-perception/2026-09-06-validation \
  --seeds 7 57 113 \
  --cases ternary_marked jittered uneven_cycle shuffled_uneven_cycle
```

実行済みの出力先は再利用しない。再測定では新しい名前を指定する。

## 現行モデルで分かったこと

以下は無指定のmeter、32–39秒、3 seed平均である。音楽的な得点ではない。

| 入力 | 推定Hz | beat確信度 | 実onset位相のR1 | R2 |
|---|---:|---:|---:|---:|
| 2 Hzパルス | 2.006 | 0.917 | 0.990 | 0.962 |
| 2音色の交替 | 1.998 | 0.051 | 0.003 | 0.992 |
| 周期的な欠落を含む反復 | 1.993 | 0.075 | 0.004 | 0.980 |
| その間隔の並べ替え | 2.002 | 0.104 | 0.011 | 0.925 |
| 不規則な更新過程 | 2.004 | 0.235 | 0.197 | 0.146 |
| 1.4 Hzパルス | 2.001 | 0.132 | 0.086 | 0.222 |
| 2.6 Hzパルス | 2.003 | 0.116 | 0.061 | 0.040 |

交替と欠落条件では、全ての正解onsetが60 ms以内に一対一で対応し、余分な検出はなかった。
したがって、低い確信度を音の立ち上がりの検出漏れだけでは説明できない。
1.4 Hz・2.6 Hzでも推定が初期値2 Hz付近へ残る。生成の内部指令を使わない実音経路では、
この刺激・音量・40秒の範囲で、十分なテンポ獲得が成立していない。
Sample 08の事前条件では、2 Hzパルスでも推定1.796 Hz・確信度0.304となった。
これらをSample 08の閉ループでの縮退原因の寄与率へ換算しない。

R2へ切り替えるだけでも解決しない。間隔を並べ替えても、元の1/4秒格子は残り、R2は高い。
特定の位相格子に乗ることと、音の順序まで予測できることを分ける必要がある。

## 比較した予測モデル

`scripts/evaluate_rhythm_recurrence.py`は、音から検出したonsetと、その時点で最大のエネルギーを
持つ低・中・高の帯域だけを読む。知覚上の声部分離を完成させたモデルではない。
0.25–2秒の遅延候補ごとに、過去3回分の出来事から次のhopの音の有無と帯域を予測する。
時刻の幅は5 hopのkernelで持ち、候補を重み付きで混合する。
時間離散化は解析の分解能であり、音符や拍内の席を設定するAPIではない。

比較対象は、周期を仮定しない適応的なイベント率モデルである。
毎hopを観測する前に確率を出し、音がなかったhopも含めて対数予測成績を比較する。
同じ区間を覚えてから採点する方法や、PLVを予測精度と呼び替える方法は使わない。
この予測器は独自の工学的な候補であり、PIPPETそのものや、確定した神経機構の実装とは呼ばない。

二つの適応方法を比較した。

- `forgetting`: 各候補の相対対数成績を6秒の時定数で忘却する。
- `switching`: 観測後に候補の重みをBayes更新し、同じ6秒の時定数で事前分布へ少量戻す。
  文脈の変化を許す候補の切替モデルであり、音を発生させる仕組みではない。

初期版では、無音だけでも小さな予測利得が生じた。最近の音の証拠がない場合は候補も
基準モデルの予測を使うよう修正した。修正前の`2026-09-06-recurrence-prototype`は失敗記録として残す。
無音での事前の混合重み0.5を、beat確信度と解釈しない。支持のない周期候補は出力を空欄にする。
複数の候補の周期を平均すると存在しない周期を作るため、最新の出力は候補の分布を記録する。

## 予測成績と次の選択

以下は`switching`、32–39秒における基準モデルに対する利得の3 seed範囲。
正の値はその区間での予測改善を示し、音楽的な快や拍の正解を示さない。

| 条件 | bits/秒の範囲 |
|---|---:|
| 2 Hzパルス | 7.910–8.379 |
| 2音色の交替 | 14.140–16.775 |
| 周期的な欠落 | 8.022–8.052 |
| テンポ変化の終盤 | 8.861–9.997 |
| 不規則な更新過程 | −0.102–−0.093 |
| 全無音 | 0 |
| 未使用の3音色交替 | 20.417–22.327 |
| 未使用のjitter | 2.316–5.102 |
| 未使用の不均等な周期 | 13.905–13.994 |
| その間隔の並べ替え | 0.012–0.181 |

`forgetting`では、不均等な周期の並べ替えのseed 113で−1.751 bits/秒となった。
同じ入力を使った`switching`では0.181となり、規則的な条件の利得も保った。
一方、不規則な更新過程では`switching`に小さな負の利得が残る。全条件で基準を上回るとは主張しない。
この比較では`switching`を次のRust実験候補として選ぶ。追加検証条件の結果も選択に使ったので、
これらを選択後の完全に独立な最終評価とは呼ばない。

```bash
python3 scripts/evaluate_rhythm_recurrence.py \
  --baseline target/rhythm-perception/2026-09-06-baseline \
  --output target/rhythm-perception/2026-09-06-recurrence-switching \
  --adaptation switching
python3 scripts/evaluate_rhythm_recurrence.py \
  --baseline target/rhythm-perception/2026-09-06-validation \
  --output target/rhythm-perception/2026-09-06-recurrence-switching-validation \
  --adaptation switching
```

反復周期はbeat/tactusとは別である。2 Hzパルスに1秒の反復候補が支持されても、
その予測自体は矛盾しない。生成へ接続するときに最頻候補だけを唯一の時計へ変換すれば、
今回の設計分離を再び失う。接続対象は複数候補から得る時刻の予期と不確実性である。

## 有界なRust実装と観測時刻

`src/core/temporal_expectation.rs`へ`switching`モデルを移植した。移植時点では`#[cfg(test)]`であり、
楽器の発音経路へは入っていない。モデルは固定長の配列を使い、過去3回の反復を参照する。
参照する時間範囲は最大約6秒である。モデル本体は28 KB未満で、音声窓だけ初期化時に確保する。
観測後の重み更新と、観測前に確定した予測の採点を分け、未来への照会も学習を変えない。

音声の入口は約100 Hzの固定窓を使う。44.1 kHzなら441、48 kHzなら480サンプルである。
runtimeのhopの途中で窓が切れた場合は、残りを次の入力へ持ち越す。
1・257・512・4093サンプルの異なる分割で、観測結果が完全一致することを検査した。
現在まで届いた音声フレームと解析済みのフレームを区別し、過去の時刻や予測範囲外への
未来予測の照会は値を返さない。音声フレームの欠落は無音観測へ置き換えず、履歴を失効させる。
実際に届いた無音は、出来事がなかった証拠として更新する。

既存のonset detectorは`src/core/onset.rs`へ抽出した。42音源を再解析した結果、
既存meterの84本のCSVは抽出前と完全一致した。同じ観測カテゴリをPython版とRust版へ渡した
照合では、イベント確率の最大差は`3.69e-6`、モデル重みは`4.33e-6`、

出力は`target/rhythm-perception/2026-09-06-rust-port/`に保存した。

## 個体の参加方策の最初の試作

最初の`src/life/temporal_participation.rs`も`#[cfg(test)]`だけで動く研究実装だった。固有のペースが定める発音時刻の
近傍を探し、以前の発音時に予期していた周囲の特徴に近い時刻を選ぶ。
特徴は低・中・高のonset確率の基準モデルからの差を、参加時刻と80 ms先で読んだ6値である。
この値はbeat確信度ではなく、相手のVoice IDや声部分離でもない。
発音した場合だけ記憶を更新し、発音不可の身体は関係を学習しない。
探索幅は身体の周期の20%か60 msの小さい方で、特定の拍原点は使わない。
身体の周期も実行した発音間隔から少量更新するが、共有の最頻周期へ代入しない。

固定した24音源に対して、固有レート2 Hz、結合0と0.7の仮想的な発音候補を比較した。
現行の研究方策は1回の更新につき最大1件の候補を返す。runtimeの全レートへの対応はまだ検証していない。
最初の3個体は偶然に初期の発音時刻が近かったため、8個体へ広げた。
その行動は音へ変換せず、観測音源へも戻していない。したがって、これは閉ループでも
PhonationEngineとの結合試験でもない。

基準検査では、証拠がなければ固有のペースを保ち、観測があると結合0の対照とは行動が変わった。
しかし、この二条件だけでは時間的ニッチの成功を判定できない。
例えば並べ替え入力のseed 307・48 kHzでは、32–39秒の相互の最近接発音距離を平均すると、
20 ms未満となる個体対が結合0の9/28から結合0.7の21/28へ増えた。
これは集中の記述であり、20 msを音楽性の判定基準にするものではない。
順序に乏しい入力でも、短い予測特徴を記憶するだけで発音が集まる余地が残る。
この試作を時間的ニッチの解決として採用しない。

この結果を受け、自分の音を出した際の重なりの予測を、次の研究実装へ加えた。
仮想的な参加までの結果は`target/rhythm-perception/2026-09-06-participation-eight/`の
`summary.json`と`pair-summary.json`へ保存した。先行する3個体の記録も残す。

## 自分の音を区別した重なり予測と実音の循環

`BandEnergyHistory`は固定長の3帯域のエネルギー履歴である。同じ反復候補と重みを用いて、
共有の音響エネルギーと個体自身が作った音のエネルギーを別々に予測する。
後者を前者から差し引き、残る周囲のエネルギーと自分の音の重なりを、発音候補の評価に加える。
個体別にbeat推定器を複製する処理ではない。自分の音は自身の合成結果から得るが、他個体の
内部予定やVoice IDを知覚上の証拠にしない。

評価は3帯域のエネルギーの競合を表す工学的な近似である。心理音響上のmaskingや、
H/Rに基づく協和・融合を完成させたものではない。混合音のエネルギーには波形の干渉項があるため、
自己予測の差し引きも一般には厳密な音源分離ではない。負の差は0へ切り上げる。
単独の音では、共有音と自己音が同じなので、差し引き後の競合予測は完全に0となる。
この条件では、重なり回避・重なりを求める設定の両方で、記憶だけの方策と発音時刻・音声が完全一致した。

`src/life/temporal_participation_assay.rs`は短い減衰音を合成し、その実音を次の観測へ戻す。
全個体が過去の同じ観測から判断してから、そのhopの音を合成する。
個体の訪問順を逆にしても、発音時刻と合成音が完全一致することを検査した。
このループでは新しいattackを出す経路は一つであるが、まだPhonationEngineや通常の代謝とは接続していない。

48条件（4つの入力構成×4方策×seed 1・21・42）、各24秒を比較した。
構成は単独、同じ440 Hzの3個体、180・1800・6800 Hzの3個体、1個体が8–16秒に休止する集団である。
方策は固有ペース、参加時の記憶、記憶に重なり回避を加えるもの、記憶に重なりを求める作用を加えるもの。
後者は同時発音を意図した対照であり、感覚的な融合の判定ではない。
どの構成にも専用の拍打ちや外部の同期音はない。

発音時刻だけでなく、各個体の合成結果から得た実際の帯域エネルギーも保存した。
自身の帯域エネルギーを`E_i`、他個体の合計を`E_o`としたとき、実測した重なりの比率は、
各時刻・帯域の`E_i * E_o / (E_i + E_o + 1e-12)`の和を、`E_i`の和で割ったものである。
これは実際の音のエネルギーを用いる記述量であり、予測の値や音楽的な得点ではない。

次は18–23秒の集団全体の比率である。休止・復帰のseed 42では回避方策でも重なりが増えた。
全条件を改善する最適化と主張しない。同じ音域のseed 42では、記憶だけでも既に小さかった。

| 構成・seed | 参加時の記憶 | 重なり回避 | 重なりを求める |
|---|---:|---:|---:|
| 同じ音域・1 | 0.2065 | <0.0001 | 0.3304 |
| 同じ音域・21 | 0.3383 | 0.0510 | 0.3017 |
| 同じ音域・42 | <0.0001 | <0.0001 | 0.6499 |
| 休止・復帰・42 | 0.0138 | 0.0323 | 0.0629 |

重なり回避で、同じ音域・異なる音域の常在個体は各24秒に47–50回発音した。
停止させて重なりを消した結果ではない。一方、短い減衰音の3個体という範囲を超えた検証は残る。
音長が長い場合、多数のharmonic Voice、生命状態によるgate、既存の共有振幅変調、社会・代謝報酬への
影響を確認するまで、Sample 08への適用が完了したとは扱わない。

最新の出力は`target/rhythm-perception/2026-09-06-participation-acoustic-overlap-energy/`。
`overlap-summary.json`がエネルギーの比較、`summary.json`が発音時刻の比較である。
`audition.html`には48音源と発音時刻の図を置き、同一構成内の平均音量を揃える再生切替も設けた。
エネルギー記録を加える前のキャンペーンに対して、全48条件のWAVと発音CSVは完全一致した。
音源・観測・ソースとhashを保存している。

## 通常Voiceへの接続

`TemporalExpectation`と`TemporalParticipation`を通常のビルドへ含め、habitatの実音を
次のVoice判断へ戻す経路へ接続した。`RhythmRelation`で明示的な同期と音を参照する参加を
区別し、`metric()`は前者、`entrained()`と`flow()`は後者を使う。Rhaiの関数署名は変えていない。

ScheduleRendererは、参加するVoiceの実際の合成音を、身体全体とhabitatへの寄与に分けて
再利用バッファへ記録する。誕生が観測窓の途中でも、誕生前は既知の無音として時刻を合わせる。
退出後に残るToneは混合音へ残るが、次に同じバッファ位置を使う個体の自己音にはならない。
追跡の有無でpresentation/habitatの全sampleが一致し、繰り返す退出でも履歴の枠数が増え続けない
ことを検査した。履歴や音声窓は個体の登録時に確保し、定常hopでは再利用する。

PhonationEngineは候補を選んでから、既存のonset条件とgateを通して実行し、その成否を方策へ返す。
候補を選ぶだけでは関係も身体の実行履歴も学習しない。実行されなかった発音予定を現在時刻へ

## 音響周期と発音位置の分離
