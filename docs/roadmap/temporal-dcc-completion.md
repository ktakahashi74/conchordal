# 時間構造DCCの完成計画

更新日: 2026-09-09
状態: 計画完成。基準メモのFableレビューは指摘ゼロで終了。実装・同定・採用は今後の作業。
対象: 現行Conchordalから、時間構造DCCの全機能と生成結合の完成まで。

## 1. 到達点と完成の意味

[神経認知階層メモ](../design-notes/dcc-neurocognitive-hierarchy.md)を実装仕様の基準、
[技術ノート9.3.55](../../web/content/technote.ja.md)を原理と実装状況の正本とする。
この文書は実装を完了した報告ではなく、完成までの作業、依存関係、判定、失敗時の戻り先を定める計画である。
基準メモの版と実際のFable応答は[レビュー記録](../design-notes/dcc-hierarchy-review.md)に固定した。
2026-09-10の実装済み・未達・保存範囲と再開位置は[停止地点の記録](checkpoint-2026-09-10.md)を参照する。

完成対象はアーティキュレーション、グルーヴ、拍・小節、反復・変奏、フレーズの継続・境界・終止、
section、帰還・展開を含む全曲文脈である。各対象について、実音の観測、関係の保持・期待、
局所的な生成への作用、後から聞こえた結果による更新を通す。和声のR/H/Cカーネルは入力として維持する。
時間に沿った和声的期待は対象に含める。実生体信号による結合は、この内部時間構造モデルの完成条件には含めない。

完成はメモ10.3節の四つの判定を、T1–T7のすべてで通すことを意味する。
数値実装の正しさ、認知課題との対応、意図した関係の可聴性、作者の音楽的な採用を別々に記録する。
一つの試聴、波形予測の改善、レビューの通過から他の判定を補わない。
対象ごとの妥当性は宣言した音楽・聴取者・演奏条件の範囲に限定し、全人類・全様式に共通する脳モデルとは主張しない。

## 3. 実装上の配置と責務

最初の共有実装はcrate内部の `src/temporal_cognition.rs` とする予定。
観測・候補・記憶・要約を通常の構造体で実装し、規模と独立した用途が生じた部分から分割する。
汎用推論フレームワークや新しい公開型の体系を先に作らない。

- **Pの所有者**：分析経路が実音区間のID、support、available時刻、coverageと特徴を作る。
  原音の欠落と配送の遅れを区別する。NSGTの重なる窓を独立標本として数えない。
- **Mの所有者**：認知ワーカーが区間を順番に一度だけ処理する。順序付きの区間関係、変形、
  想起、フレーズ・sectionの候補を保持する。過去の解釈を改訂しても発行済み予測は改変しない。
- **Aの所有者**：Voiceが自身の身体と作者から与えられた傾向を使い、要約の支持する範囲で行動を選ぶ。
  大域状態が音列や全Voiceの終了を命令する経路は作らない。
- **二つの聴取領域**：habitat用とpresentation用は別インスタンス。共通コードを使っても状態を共有しない。
  生成側で分かる自分の行動はpreviewに使えるが、ListenerへVoice ID・Scenarioラベルを渡さない。
- **結果の帰属**：候補、発行した予測、実行した行動、観測結果を別記録にする。実際に鳴らなかった候補は学習しない。
  個体の死は私有の参加履歴を閉じる。共有された聴取履歴は維持する。

現在、presentationの重い分析はreport等による強制または既存DCC結合で有効になる。
新しい時間認知の有効化は、その音高用の結合強度と独立に配線する。
presentation側にも既に共通のanalysis workerがあり、`AnalysisDelivery::Ordered`、frame ID、
欠落reset、SpectralHistoryを備える。両busの既存経路へ関係用recordを追加する。
NSGT解析器を重複して新設せず、新しい型付き記録・epoch管理・消費者だけを実装する。
聴取評定から適合したheadをhabitatへ使う際は、routing／gainで両busが異なる条件の移転検査を行う。
分離renderer側で各busを比較用に出力し、それぞれを実際に聞いた判断へ照合する。instrument側に録音経路を追加しない。
検査前のhabitatのordinal帰結は、同じ混合音の条件に適用を限定する。
生成側の共有記憶には自身が実際に出した音も入る。これを他個体からの応答と誤認した説明はしない。
既存の`ListenerState`の短時間指標と新しい時間文脈の要約は併存させ、消費者を区別する。
listener文脈を生成へ返す場合は、実際のpresentation routingを通した候補を評価し、
同じ単位を持つ別の由来付き帰結として扱う。各係数は独立で初期値ゼロとし、habitatと独立の証拠として乗算しない。
通常演奏でreportを切ったときも認知が動作し、reportの有無で生成が変わらない経路を作る。
認知入力のキューは有界とし、飽和時は失った区間を欠落として報告する。音声callbackを待たせない。
オフラインの決定的実行は区間順序と時刻を一致させる。実時間の遅れをオフライン成功で隠さない。

## 4. 完成までの作業単位

M0→M1を共通基盤とする。M2とM3を進め、M3→M4→M5で長い関係までを通す。
M6は支持された機構から一つずつ接続できる。M7–M9で全体を統合・採用する。
M2の全条件での最良予測を、M3以降の着手条件にしない。
表の依存は必要な入力と観測契約の成立を指し、下位の全課題での採用を着手条件にはしない。
M6ではT3以外の支持された関係を接続し、T3の局所生成と全体の結合はM7で判定する。
部分モデルの試作では未接続の入力をunknownとして記録する。全機能を組み合わせた段階で
メモ10.1節の四段階の適合・校正を改めて固定し、部分モデルの合格を統合版へ転用しない。

各段階で、仮説の変更理由、旧対照との比較、採否と再開位置を一つの段階記録へ残す。
この段階表をM0–M9の定義の正本とする。メモの各M-IDは、この表の一行にだけ対応する。
番号または担当範囲を変更するときは、メモの担当・停止・再設計先も同時に改訂する。逆方向の変更も同じ条件とする。
段階記録は`docs/roadmap/temporal-dcc/`、再生成可能な実験出力は`target/temporal-dcc/<run-id>/`を予定する。
記録から設定・入力・sourceのハッシュ、実行コマンド、結果manifest、採点の版へ辿れる形にする。
M0は`docs/roadmap/temporal-dcc/feature-manifest.json`も作成し、共通条件付き特徴の全座標、
数式・単位・欠測・由来・相互作用の組・並び順を確定する。変更時はモデルを改版し、再適合する。
すべての感度比較に、対象T行、基準と変種、同じ素材・分割、指標と単位、不確かさ、事前の採否規則を登録する。
規則は基準維持、変種を改版して必要な再適合・判定を行う場合、感度を適用限界へ残す場合を区別する。
資源指標だけで認知・関係の指標を置き換えず、結果を見て採否規則を決めた比較は完了扱いしない。
accentは比較する三時点のrise／fluxの両方を必要とし、一成分のmaskも検出支持の欠落として記録する。
word complexityのPMFは過去8秒の有効なmatched wordのstep頻度を音響admission支持で混合する。
stage 3の事後重みへ置き換えず、未group・未量子化区間のmaskと支持率をメモ9.2節どおり登録する。
音響groupのエネルギー配分、アクセントの四hop支持、unknownへの物理時間に基づく遷移、
境界の全体集約、記憶のmembership、座標と容量も数値参照へ登録する。
初回ridge継続では周波数をzero-slope persistenceで予測し、slope残差はmaskする。観測済みの傾斜ゼロとは区別する。
ridgeの傾きは連続した完全観測hopのlog2周波数差／秒とし、選んだpredecessorごとにsecantを保持する。
欠落をまたぐ新しい傾きはmaskし、古い傾きによる外挿と新しい観測を区別する。二／四間隔の回帰対照も登録する。
group前のtrajectory energyからlog2-RMSを作り、bundle相関は有効なpaired hop値の通常のPearsonとする。
平均・積和はf64、ゼロ分散はmask。linear-RMS入力との比較も既存の窓・閾値比較へ含める。
group照合は最後に支持された最大八memberの周波数・傾き・log-envelope・時刻・所属重みを参照する。
raw重みは距離1以内のmemberについて`max(r_jg*exp(-d_ij²))`、残余rawは`exp(-1)`とし、全groupと残余で一度だけ規格化する。
適格groupなしの観測軌跡は全て残余、欠測軌跡は未知とする。割当後に参照を更新し、出生等のseedを同じhopへ遡って再配分しない。
置換済みparentは文脈として保持しても現行の割当先から外す。最大7,168 bytesと追加896 member距離／hop／busをO04へ計上する。
896の内訳は七resolved groupの保存参照×八member×残余軌跡を含む八current trajectory×二slopeとする。
曖昧な所属、残余重みの半分／倍、出生閾値0.5の両側、energy保存、初期化・休眠・置換・欠落をO03／O09／O10へ登録する。
bundleは最大八trajectoryのsingletonからcomplete-linkで作り、全cross相関が既知かつ0.8以上の組だけを結合する。
最小cross相関が最大の組を選び、同値は整列した世代handleで決める。相関の非推移性を連結成分で潰さない。
三hopの持続キーは同じmember集合と固定した旧parent。交替・欠落・条件失敗でresetし、birthのu_B条件をsplit／mergeへ流用しない。
splitは同じ旧parentの二bundle、mergeは一bundle内の二parent部分集合として判定する。相関はsplitで最大、mergeで最小を使う。
mergeのparent対は非方向的とし、stable handle順へ並べて各member集合を対応させる。A／Bを逆順で与えても同じkeyとなるfixtureを置く。
候補支持は各memberのmax associationの和、同値はmerge／split／birth、parent／member handle順とする。
一hopでparent／memberを二重消費せず、相関非推移・同値・member churn・初回継続・競合をO09で検査する。
整数group境界の探索幅はt0+j*L*Pの各点から±0.10*L*P、j=1,2とし、二つ目で広げたり最初の選択点へ中心を移したりしない。
その後の二反復それぞれの長さ検査は別に残し、両方をproposal manifestへ固定する。
M0は`docs/roadmap/temporal-dcc/hardware-baseline.json`にCPU、利用可能core、affinity、
仮想化・cgroup制約、RAM、OS／kernel／architecture、compilerとrelease設定、電力profile、
音声機器・rate・hop・buffer、busと出力のchannel数・順序、downmix／出力行列、gain／guard、両busを含む通常負荷を保存する。M8はその内容ハッシュを参照する。
現行の両busはmonoであり、callbackがpresentationを出力channelへ複製する。energyは観測時刻N個に対するmono標本の二乗平均とする。
多channel素材は算術平均で一度だけmonoへ変換し、解析と基準聴取の双方へ同じ結果を渡す。元の空間音響の知覚を検証したとは扱わない。
O09はmono、同一stereo、非対称、逆相相殺と複製時のenergy不変を検査する。O06／O14は元channel、変換・処理・gain、
提示channel／device mappingとguardの状態、解析・提示波形のhashを記録する。基準条件のguardは透明と確認し、非透明な処理は別の移転条件とする。
現在のlistener tapはdevice guard前であり、処理後と同一とはみなさない。channel／downmix／処理規約変更はepochとmodelを改版して再検証する。

## 5. 評価・同定を実行可能にする手順

### 5.1 素材と比較の固定

人を対象とするpilot前に、M0／O05が倫理審査の承認参照または担当機関による適用手続きの判断を記録する。
各言語の同意文・任意の離脱手順、謝礼、仮名ID、連絡／支払情報の分離、アクセス権、保持／削除期間、
個別回答と経験／言語層を共有する際の識別情報除去規則を登録する。分析に必要な同一参加者の対応は保つ。
機関判断や手続きの未登録はpilotを含む全収集を止める。すべての地域に同じ審査方式を仮定しない。

M0で三つの長さを固定する。短い関係課題は20–90秒、section課題は3–5分、
全曲課題は30分の連続した演奏とする。全曲には2分以上および10分以上の介在を越えた帰還を置く。
T2／T3には緩やかなtempo変化を含める。開始周期0.5–1.2秒、前後10秒の定常区間と
30秒のlog-linear rampを使い、自然対数ln BPMの変化率を毎秒±0.0025／±0.01／±0.02とする。
極端な終点周期は約0.2744秒と2.1865秒で、0.125–4秒の推定grid内に収まる。
往復条件も自然対数を使い、底と実現したtempo軌跡を刺激・採点metadataへ登録する。
メモ10.2節の正弦による滑らかな往復、平均速度を揃えた定常、終点を揃えたstepも比較する。
同じ実音を各対照へ与え、tempo予定値を知覚へ渡さない。追従遅延、相対位置、未知・提案・退避率を測る。
間隔許容幅、32秒bank、1秒dwellの感度比較と、徐々に身体／参加周期が変わるprivate trace移転も必須とする。
T7には通しで一度聞いた後の全曲の完了感を5段階で尋ねる独立課題を置く。
短いprefixの終止評定とは混ぜず、形のある終端・開いた終わり・中断を含める。EOFはモデルの特徴へ渡さない。
凍結したclosure／continuation、未解決期待、sectionのreturn傾向から採点用headを作り、
closureだけ、直近のgap／energyだけ、経過時間だけの対照とheld-out ordinal log lossで比較する。
この完了感の判定と、進行中の帰還・文脈予測はT7の別々の必要条件として記録する。
これらは評価範囲であり、知覚の普遍的な長さやプログラムの最大長ではない。

素材はpitchを追いやすい音と雑音的な音、短音と10秒以上の持続、疎な配置と重なり、
単純な拍節、異なるまとまり、非拍節的な流れを含める。相対tempo変形、移調、音色変化は
同じ関係を保持する条件と、順序を変えた条件を対にする。モデルの変形探索範囲外はunknownとして検査する。

構築した形式ラベルは実験設計と照合にのみ使い、聴取推論へ渡さない。
先行文脈の認知比較では、異なるprefixと同一の局所suffixを使い、suffixのPCMと直近の聞こえた情報を検査する。
未来の帰結表には観測・候補由来の仮想支持・未支持を別に記録する。
仮想の身体envelope、相対時刻、対応残差はscratch特徴で評価し、実音の記憶やcreditへ書かない。
候補と身体の既定動作に共通する発行時の観測支持率を使い、未来窓の未観測率だけで差を消さない。
実Voiceによる反実仮想のオフラインrender・再解析と照合し、headの移転検査を通してからordinal帰結を有効にする。
局所生成の因果比較は二種類を区別する。第一は同じ全入力・身体・私有traceに対するcontext on/off。
第二は、異なるprefixから受動的に作った認知状態を、同じ身体・私有traceへ移す明示的な状態介入である。
両者を混ぜず、その後は同じ外部入力で短い応答を比較する。帰結の圧力だけを比較するときは候補時刻集合も一致させ、候補生成自体の変更は別の除去比較とする。後者を自然な閉ループの履歴一致とは呼ばない。
全閉ループの演奏では音が分岐するため、以後も入力が同じだったとは主張しない。

### 5.2 パラメータ同定と聴取者

人のstage-1収集前に、M0がメモ10.1節のsynthetic parameter-recoveryを登録・実行する。
予定する人数／回答数と固定方策run数、独立した時間・干渉・接触回数、欠落と帰属の条件を使う。
メモの工学的パラメータgridの各点で100組を生成し、正値parameterの絶対log比誤差は中央値ln(1.25)以下、
90 percentile ln(2)以下、biasの絶対誤差は0.25／0.75以下を要求する。失敗fitを除外せず全条件を保存する。
初回は登録した模擬用の音響尺度で検査し、対応尺度の実際の適合後、記憶回答を収集する前にも再検査する。
私有traceは実際のcredit・正規化・overflow則で別に検査する。正規化で消えるparameterを同定済みと扱わない。
失敗なら課題、接触、割当数、同定不能なparameter化を改訂して再実行し、結果を見て許容誤差を緩めない。
`docs/roadmap/temporal-dcc/parameter-recovery.json`に設計版・seed・費用・全回収誤差・採否を残す予定とし、
O11／O13の収集開始条件にする。これは模擬モデル内での識別可能性であり、人の記憶法則の確認ではない。
境界／typeの収集前には、phrase／sectionのstage-2適合にも模擬検査を行う。
phrase hazardと出口分類はメモ9.4節の同じ26座標を、別の係数で使う。定数とlog経過秒、
articulation四状態、過去250 msの包絡上昇／下降・flux・energy比、二秒のgrouping支持、
現在の順序照合cost・検索支持・検索の曖昧さという12値と12maskを固定する。
時間窓・単位・標準化・欠測・query ageはメモの式に従い、M0で新たに入力を選ばない。
変更時はモデル改訂としてO03／O12の模擬検査と該当fitへ戻す。
単一・二・四・八group、低中高の事象率、偏った／均等なtype、予定する区間打切り、0／10／30%の未知支持を登録する。
各条件100組を既知のmixture-first-event則から生成し、適合後の独立probeで無条件CDFとtype分布を比較する。
10 ms grid上のCDF RMS誤差は中央値0.05／90 percentile 0.10以下、無事象・未知を含むtypeのTV誤差は0.10／0.20以下を要求する。
単一strandのprobeも必須とし、混合全体だけの一致で群ごとの予測不安定性を隠さない。
係数は予測用と位置づけ、非一意性は記録する。失敗は割当・打切り・単一strand素材・特徴／parameter化の改訂へ戻す。
正確な生成vector、条件、費用、全結果をparameter-recovery.jsonのO12部分へ保存し、許容差を事後に緩めない。
その後、対応するdevelopment素材で課題の分かりやすさと回答尺度を確認する。
pilot前にメモ10.2節の基準を登録する。言語ごとに最低12人、二つの手続き理解チェックを両方通る率90%以上。
事前に定めた明瞭なpractice／controlで、対応・再認・T1各回答・T2の種類と個数は70%以上、
五段階評定と全曲完了は80%以上、境界の区間／無境界は70%以上、境界を判断した回答のtypeは60%以上を要求する。
T5の音群をまたぐphrase課題は、明瞭な対照でyes／noの判断70%以上、全yes回答のうち有効な継続区間mark70%以上を要求する。
unableは未判断とし、両方の基準をpilot後に緩めない。
Gate-3の説明課題は三説明のいずれかを選ぶ率70%以上とし、意図した説明への同意率をpilot合格に使わない。
全割当を分母とし、曖昧な本試験条件や理解チェックの失敗者を除いて率を上げない。
不足なら手続き・説明・素材の明瞭さを改訂し、新しいdevelopment cohortで再pilotする。
同じpilotを見て基準を下げず、十分な課題が得られるまでO07の実用差設定を止める。
境界の時刻範囲、継続の期待、終止の程度、反復・変奏の対応、グルーヴと参加したい感覚を
それぞれ収集する。T1では聞こえたgestureとattack／continuation／release／gapの区間、
別gestureとの重なりを、端点の不確かさや未判定を保持して記録する。モデルのgroup IDは見せない。
T1は単一groupと二groupのhandoff unionへ支持IoUで対応させる。unionの二成員を
「別gestureとの重なり」へ二重計上しない。三group以上のgestureを含むfixtureで表現漏れを測り、
対象の広さに対して不足すればM2で有界な表現を改訂する。対応不能を単一音源の回答に読み替えない。
handoffはrelease開始の二秒前以降の、観測済みの重なり、または観測した低energy／gap開始から一秒以内のattackを許す。
release開始をgapの開始へ読み替えず、長いtailの終わりも実際に観測してから扱う。
0.25／0.75秒gapを正のfixtureとし、0.1／1／5秒releaseでも検査する。一秒超は初期の非提案と感度比較を測る。
必要な長いgap handoffの表現漏れはT1凍結前にM2へ、phraseの同一性も必要ならM4へ戻す。
gestureのfamily priorは固有のb_gを使う。過去8秒をepochとgroup世代の生存区間でclipし、
各hopのfractional trajectory所属を八group（残余込み）で規格化・時間積分し、再び八group間で規格化する。

### 5.3 判定と失敗の切り分け

- **実装**：時刻、欠落、観測の所有権、未来情報、ラベル混入、予測発行、結果更新の契約をテストする。
- **認知**：T1–T7の指定指標で、held-outの聴取判断と対照との差を評価する。
  実用差と不確かさの双方を判定し、unknown率・誤認識も報告する。
- **可聴性**：条件名を隠し、どの関係がどの区間で変わるかを回答してもらう。
  「違う音だった」と「帰還・受け渡し・終止が変わった」を分ける。
- **採用**：作者が自然さ、流れ、意図した関係を確認する。差が分からない回答を肯定に置き換えない。

失敗時は、観測不能→P、順序／変形の混同→M3、境界と終止の混同→M4、
長い介在後だけ失敗→M3/M5、知覚は合うが行動が変わらない→M6、
行動は変わるがランダムに聞こえる→M6/M7、実時間でのみ破綻→M8へ戻す。
一回の採点改善に合わせて音楽的な目標や作者の回答を書き換えない。

全段階の変種・指標・許容差・費用・再適合範囲をO03／O04／O10へpreflight前に登録する。
失敗箇所の処理を減らさない段階は非該当として記録できるが、無関係な容量変更を修復と扱わない。
機能上のdevelopment条件を通った変更だけを順番に残し、失敗した変更は戻して次を試す。
採否を記録し、両busの予算と機能が揃った一つの資源・モデル版を検証前に凍結する。
全案が失敗した場合は方式または宣言するhardwareを改訂し、同じ判定をやり直す。
鮮度窓や余裕を黙って緩めたり、時間構造の対象を削ったりして合格とはしない。

帰結表は100 ms周期で最大1,792 cell／bus、229,376経路評価を行う。特徴数を含む上限と再構築時間を記録する。
既定512 samples／48 kHzでは100 ms当たり9または10 hop、各busで最大655,360組の局所候補を評価する。
実際のdevice rateとhop設定を記録する。関係キューは32区間を上限とし、超過を欠落として伝え、音声出力を待たせない。
周期提案のgridは新アクセント対を加算し、時刻／容量による期限切れ対を一度だけ減算する。
周期候補は正値plateauの局所最大とし、端では存在する隣接値だけと比較、一様gridは候補なしとする。
同値は小さい周期のbin、支持順で選んだ候補間はlog2周期差1/24 octave以上を保ち、最大八個とする。
P_best・grouping・音群間／内部周期履歴が同じ一覧を使う。1/48／1/12 octaveと広い峰・近い二峰・倍周期の列を比較する。
十hop／七groupのpeak処理は16,870 bin訪問、最大8,470候補のsort入力、67,760間隔検査を下記pair-grid費用と別に計上する。
1,024アクセントごとの再構築を含め、十hop周期で最大676,417 bin訪問／bus、対cacheは1,820,672 bytesを初期上限とする。
対recordの32 bytesは、u16の二slot・base bin・flags、f32の五寄与、4 bytes paddingとする。
寄与は一度だけf32へ丸め、その同じ値のf64変換を加算・減算・再構築に使う。slot再利用前に関連対を全削除する。
寄与のf32丸めとf64和のdriftを分け、全f64 kernel再計算、微小weightとpeak同値付近へ比較する。
これも50 msの計算予算へ含め、gap後の一括expiryと再構築を実測する。
groupingのanchor探索は100 ms周期で有界に更新する。integerは予測境界に最も近いaccentを使い、
cyclic wordは連続intervalを省略せず照合する。余分なaccentの扱い、tie、候補数と所要時間を記録する。
sectionの照合二入力は同じ0.1秒・16候補のcacheを使い、追加DTWを起動しない。
候補数の上限だけを処理時間の達成証拠とせず、全経路の実測で判定する。
これは現行の実測値ではない。ageの全作用区間0.25秒、ゼロ作用0.5秒との整合をM8で検査する。
T1–T7の局所行動比較ごとに遅延の内訳・全経路のp50/p95/p99と、age/coverage作用が全量・部分・ゼロの比率を記録する。
新しい軽量frameの時刻で、古い照合結果のageを若返らせない。予算と減衰の改訂はdevelopmentで同時に行い、検証前に凍結する。
私有参加fitもbindingごとにage／coverageで減衰する。ageは、その所属とanchor／periodの有効性に使ったinventoryの実音支持と、
cue-match queryのraw support終端の古い方から判断時点までとする。Voiceの最後の発音時刻や記憶・anchorの元時刻は使わない。
coverageは公開したhabitat情報の実音支持終端までの直近0.5秒、epochで切った窓の実観測割合とする。空窓はゼロ。
現在のanchorが有効なら、candidateと身体defaultへ同じ係数を一度だけ掛け、失われた重みを他参照へ振り直さない。
私有列へさらに共有tableのageを二重適用しない。trace自身の保持・干渉則は別に進める。
O09／O13／O15は新鮮／古いinventory、見かけだけ新しい公開時刻、長く発音していないVoice、anchor喪失、部分coverageと一度だけの減衰を検査する。
最大RSSと定常区間のメモリ増加を記録し、キューやepisodeの無制限な蓄積を認めない。
意図的な過負荷区間の失敗を通常条件の成功へ混ぜず、回復後の認知状態と音響動作を別に判定する。
オフライン計測は実機受入を代替しない。

通常の作者用APIは関係への参加と身体・生態の傾向を表す最小限にする。
新しい時間用の操作はoff／受動観測／局所参加のmode、メモ9.6節で列挙した帰結の符号付きgain、
別のlistener gainに限る。簡単な入口はmodeとdispositionを使う。classごとの未定義な事前値は追加しない。
正確なRhai／config名と既定値はM8で実際の消費者へ結び付け、既存の音高・身体・routing操作を閉じない。
modeは一演奏中固定とし、実行中の変更は状態を変えず拒否する。別modeは新しい演奏として、
新しいinstance／epoch、空のbank・新規private traceから開始する。
出荷する新しい時間modeの既定はoff。M8で決めるのは識別子の綴りと列挙であり、既定動作を後から変えない。
指定省略・明示off・採用済み旧挙動のbit一致を同じseed／身体／入力と固定した基準版で検査し、有効化は作者の明示操作とする。
O19の局所参加modeでの置換はこの基準を変更しない。後の既定変更は上記の別採用・期待mode／基準版の改訂として記録する。
offでは新しい関係workerやbankを作らない。受動観測では両worker、bank、帰結表、実行結果のprivate traceを
動かすが、新しい行動列はすべて無効。局所参加では同じ状態処理と支持・鮮度の条件を満たす行動列を使う。
既存のpitch DCCやreportに必要な分析は別に維持する。起動三mode、live変更の拒否、report／pitch toggleを検査する。
context圧力のon/off比較は明示したassay介入を使い、隠れたmode切替や状態持越しを使わない。
研究用のbeam幅や正則化を音楽的な操作名へ偽装しない。alpha段階では旧APIの互換層を既定で残さない。
旧2x3方式はoff／受動の生成経路と比較の対照として保持する。局所参加で置換した寄与の二重適用だけを除去する。

Rust変更時は毎回、変更に合うテストとリポジトリ必須の手順を実行する。

```bash
cargo fmt --all
set -o pipefail
( RUST_BACKTRACE=1 cargo test -- --nocapture ) 2>&1 | tee test_report.txt
echo "cargo test exit=$? @ $(date -Iseconds)" > test_status.txt
cargo clippy -- -D warnings
cargo check --all-targets
```

テストの非ゼロ終了を記録した場合は先へ昇格しない。公開APIを変更した段階だけ、
`cargo run --bin gen_rhai_defs`で生成し、両mdBookと生成同期テストを確認する。
coreの方式を変更した段階で技術ノート日英を同期する。実装時はこの計画で文書同期も明示した範囲に含める。
`conchordal`へ録音機能を追加せず、保存を要する比較には分離された`conchordal-render`を使う。
これがAGENTS.mdのair-gapであり、楽器のCLI・entrypoint・到達可能な出力経路をM8で確認する。
Scenarioラベルや私有状態の知覚経路への漏洩防止は別の契約として検査し、両者を同じ意味の語にしない。
標準sampleはseed固定なし、研究assayはseed固定を維持する。専用の拍打ちは同期が必要な実演だけに限る。
