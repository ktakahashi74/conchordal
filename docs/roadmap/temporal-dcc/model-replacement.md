# 時間構造DCCのモデル交換境界

更新日: 2026-09-11
状態: 設計・比較手順を登録。交換実験と本体への境界実装は未実施。

この記録はM0のO03・O09・O12を具体化する。設計の正本は
[神経認知階層メモ](../../design-notes/dcc-neurocognitive-hierarchy.md)、工程の正本は
[完成計画](../temporal-dcc-completion.md)。第一原理と実装の対応は
[technote 9.3.55](../../../web/content/technote.ja.md)へ記録する。
現在の数値参照を第一候補として保持し、数式・特徴量・容量・適合済み係数を
認知神経科学から一意に導出された仕様とは扱わない。

## 1. エビデンスと固定する範囲

現象の存在、説明機構、採用した計算式、生成への有効性は別々に評価する。
ある神経応答との対応だけでデータ構造や推定器を確定しない。

| 領域 | 設計を制約する知見 | 現在の選択と交換対象 |
|---|---|---|
| R/H | 粗さ・倍音性は知覚上の評価軸。好ましさとの関係は音色・経験に依存 | 既存カーネルと協和への合成則もモデル選択。今回は改変しないが、最終的な神経法則とは扱わない |
| 音群・アーティキュレーション | 連続性、開始・持続・終了、文脈によるまとまり | ridge追跡、群化、四状態と遷移率は第一候補 |
| 拍・小節 | 時間的期待と拍節解釈。神経応答の周期性だけでは振動子機構を同定できない | 周期・grouping提案、振動子と到来ハザードは比較対象 |
| 記憶・反復・変奏 | 順序、再認、時間と介在情報の影響 | 区間グラフ、DTW、変形、保持・干渉・検索則は交換対象 |
| フレーズ・section | 文脈に依存するまとまり、境界の予期、長いイベント構造 | 半マルコフ状態、ハザード、section記述と共有推論は計算仮説 |
| グルーヴ・終止・全曲完了感 | 対応する聴取判断を独立に測る必要性 | 順序ロジット推定器は評定への適合モデル。神経機構の再現とは別に検証する |
| 個体の参加 | 行為と観測結果の対応を保持する設計上の必要性 | 私有traceと行動評価は仮説。作者のdispositionは学習した神経定数ではない |

根拠の具体例として、音色操作による協和判断の変化とモデル改訂は
[Marjiehら (2024)](https://www.nature.com/articles/s41467-024-45812-z)、
振動子と誘発応答の両モデルによる拍応答の再現は
[Damsmaら (2025)](https://academic.oup.com/cercor/article/35/9/bhaf258/8263582)に対応する。
フレーズの予測的処理は[Tengら (2024)](https://pubmed.ncbi.nlm.nih.gov/38926087/)、
長いイベント構造の神経表現は[Williamsら (2022)](https://pmc.ncbi.nlm.nih.gov/articles/PMC9169871/)が
制約を与えるが、Conchordalの半マルコフモデルや区間グラフを同定する証拠ではない。
領域全体を一括して「強い／弱い」と順位づけず、採用する主張ごとに知見・仮説・適用範囲を残す。

## 2. 安定させる契約とモデル内部

安定契約は次の意味を保証する。これは現時点で公開Rust型や汎用plugin APIを新設する指示ではない。

- **入力**: bus、解析設定のepoch、元の標本区間、観測支持、実際に利用可能になった時刻、
  単位、欠測を保持する。既知無音と欠測を区別し、推論へVoice IDやScenarioラベルを渡さない。
- **出力**: 何についての予測・対応・境界・評定か、その支持区間、利用可能時刻、
  単位またはカテゴリ、未知・曖昧さ、校正の有無を保持する。モデル固有scoreを確率と呼ばない。
  出力の一致を求めるのは意味・因果条件であり、異なるモデルの予測値を一致させる条件ではない。
- **実行**: 有界な所有・キュー・期限・失敗報告を保つ。計算終了時刻で音声支持を新しくしない。
  遅延・退役・旧epochの結果は既存の受領規約で拒否する。すべての費用をO04/O17へ計上する。
- **行動**: 候補、発行予測、実行、聞こえた結果を区別する。支持不足時は既存の身体動作へ戻す。
  共有認知が全個体の音列を命令する経路を作らない。

10値のknot、320-byte配置、DTW経路、beam、phrase26／section82の特徴配列、
回帰係数、内部グラフは第一候補の内部形式とする。他モデルやVoiceにその形式を要求しない。
共有する不変byte pool等は所有・サイズ・期限を扱い、意味の復号と検査は形式を所有するモデルが担う。
既存の固定配置と資源上限は、第一候補の比較が終わるまで引き続き有効である。

必要な認知的区別を現契約で表せなければ、契約版も明示的に改訂する。
その場合は両モデルの利用先と該当T行を再検証し、「同じ契約のまま交換できた」とは記録しない。

## 3. 交換単位と依存方向

以下は責務の境界であり、各行を直ちに一つのtrait・thread・公開moduleへ変換しない。
実際に独立した実装が二つ存在する境界から、小さい内部関数・enum等で選択を実装する。
同じモデルコードをhabitatとpresentationで使えても、状態・bank・結果は別インスタンスにする。

| 交換単位 | 入出力と責務 | 内部へ閉じるもの |
|---|---|---|
| 観測・配送基盤 | 実音から順序付き証拠を提供し、期限付き結果を配送する | モデルの選択はcomposition rootで行う。基盤からmatcherやheadの内部検査を呼ばない |
| 音群・アーティキュレーション | 観測と前回の文脈から、音群・継続・release等の候補を得る | ridge、所属、gesture union、四状態、遷移パラメータ |
| 拍・到来 | 音響アクセントと音群から、周期・まとまりと次の到来を予測する | oscillator、周期探索、cyclic word、到来ハザードと固有の校正 |
| 関係記憶・照合 | 過去の支持と現在のcueから、対応・変形・想起候補を返す | descriptor、照合器、保持則、index、bankのcodecと内部edge。表現が変わる場合は一組で交換する |
| フレーズ・section | 下位証拠と保持文脈から、継続・境界・遷移候補を得る | 持続時間モデル、遷移状態、特徴集約。phraseからsectionへ渡す意味と依存を版管理する |
| 共有推論 | 各候補と証拠の依存を扱い、利用先へ関係の要約を返す | 条件付き分解、joint score、beam、内部状態。必要なら前記の認知モデル一式を含めて交換する |
| 評定推定 | 利用可能な文脈から、登録した課題の評定分布を返す | groove、参加意欲、継続、終止、全曲完了感の特徴・推定器・校正 |
| 個体の参加 | 文脈と自分の身体から候補の帰結を評価し、実行結果で私有状態を更新する | trace、候補評価・選択則。共有bankへ意図や未実行候補を観測として混入させない |

コードの依存は「runtimeから組立てと入出力契約を呼ぶ」「各モデルが契約と自分の内部表現を使う」
方向にする。VoiceとUI/reportは要約・帰結を読み、DTWやbeam、bankの内部配置を読まない。
モデル間の情報は登録した入出力を通す。共通の観測契約は特定モデルへ依存させない。

音楽上の相互作用は一方向の直列処理へ変更しない。推論内の同時更新は一つの所有者で閉じ、
音群へ返す文脈等は正本9.1節の前回要約を使う。現在区間の同じ音を循環的に独立証拠として増幅しない。
記憶と照合、phraseとsectionなどを別々に差し替えられない場合、利用先へ内部型を漏らす代わりに
交換単位をその組へ広げる。共有推論方式自体を不変の認知法則にしない。

現在の参照コードでは`temporal_bank_reference.py`がmatcherの`_validate`に依存する。
これは基準形式内部の既存依存として記録し、本体の共通bank APIへ転用しない。
形式の検査をモデル内へ配置し直す課題を、下記MR1の交換実験で確認する。

## 4. 版・状態・再適合

実行記録では、入出力契約、アルゴリズム、特徴の式・尺度、適合係数・校正、保存形式、
資源設定の各版と内容ハッシュの対応を識別できるようにする。
これは実験manifestの要件であり、全項目をhopごとのpayloadへ複製する要求ではない。

選択は演奏開始時に行う。契約・特徴・保存形式と適合済み係数の組が一致しなければ起動前に拒否する。
比較する各演奏は新しいepoch、空の共有記憶と私有traceから開始し、同じ記録済み入力を必要に応じて再生する。
異なるモデルの状態をそのまま引き継がない。既存off／受動／局所参加の規約とair-gapを保つ。
この研究用選択を直ちに作者用Rhai APIへ公開する必要はない。

変更は二種類に分けて記録する。

- **同一モデルの実装変更**: PythonからRustへの移植、packed入力、scratch再利用など。
  約束した数値・因果・例外の同値性を照合し、変化した処理・保存・配送の費用を再測定する。
  同値性が成立すれば認知係数の再適合は不要だが、モデル交換の証拠には数えない。
- **モデルの変更**: 状態・特徴・照合距離・保持・遷移・評定・行動の意味や値が変わる変更。
  同じ入力での差と該当課題を検査し、下表の依存に沿って再適合・校正を行う。
  高速化という名で数値や候補の意味が変わった場合もこちらへ分類する。

適合stage 1〜4は正本10.1節の定義を使う。各変更の記録には変更出力、その利用先、再生成する
out-of-fold入力、再適合するhead、校正、対象T行・生成列・資源検査を列挙する。

| 変更の起点 | 再適合・検証の基本範囲 |
|---|---|
| 観測、音群、アーティキュレーション | 変化するstage-1記述・対応・traceとstage-2入力を再生成し、依存するhead、stage 3、stage 4へ伝播。全T行への依存を確認 |
| 周期・grouping提案 | それを使う到来・記述・対応・traceから再生成し、利用するstage 2〜4とT2/T3、関連T行を再検証 |
| 到来ハザードだけ | stage-2到来、T2の評定接続、利用するstage 3・4、到来分位点を使う行動とT2/T3。周期提案等の再適合は出力依存がある場合に限る |
| 関係記憶・照合 | stage-1対応・保持・関連trace、想起を使うphrase／section／評定入力、stage 3・4。T4/T6/T7と想起を使う下位T行 |
| phrase／sectionの遷移・集約 | 該当stage-2モデル、変更したphrase入力を使うsection、利用する評定、stage 3・4、T5〜T7と影響する生成列 |
| 共有推論 | 内部表現も変える場合は必要なstage 1・2から。重みや分解だけでもstage 3・4と全T行への影響を検査 |
| 評定推定 | 該当stage-2 headとstage-4校正。stage 3その他がその出力を使う場合はそこへも伝播。評定対象と有効な生成列を再検証 |
| 参加trace／行動則 | 固定方策によるtrace同定・身体の帰結・行動比較と実時間性。受動認知の適合は入力・分布への依存がある場合に再実施 |

再適合を省く枝は「同じ特徴の意味・式・尺度・入力データと適合版が保持される」という根拠を記録する。
構造変更で同一入力の出力が変われば、型が同じでも以前の校正を自動転用しない。
一方、無関係な枝の全適合を機械的に繰り返さない。
固定入力での受動比較の後、生成を有効にした閉ループでも該当T行・元音の回帰を確認する。
生成が入力分布を変える効果を、受動比較の成功だけで認めない。

## 5. 登録する交換試験

すべて未実施。以下は比較手順の登録であり、数値・認知・音楽的な合格報告ではない。

| ID | 比較と入力 | 終了条件・担当 |
|---|---|---|
| MR1 | 現在の順序付き照合と、既登録の`memory_orderless`を小型bankで比較。同じ観測区間・cue・支持・配送時刻を使い、同じ内容の順序変更、欠測、遅延、世代退役を含める | M0/O03・O09で小型数値交換を実施し、本体組込み前に境界を確認。認知的採否はM3以降のT4/T6等へ残す |
| MR2 | 既存振動子／周期候補と、登録済み到来モデルを同じアクセント列・省略・tempo変更・非周期列で比較 | M0で手順を登録。M2で各モデルの予測対象・支持・尺度を合わせて比較し、O12とT2/T3へ接続 |
| MR3 | 別モデルの係数、特徴尺度、保存形式、旧epochの結果を意図的に与える | M0で手順を登録。M1以降の最初の本体境界で、起動前の不整合拒否・旧結果の不採用・空状態からの開始を検査 |

MR1の具体的な判定は次とする。

1. `memory_orderless`は正本9.3節の全区間の平均・標準偏差を使う。順序・timestampを
   hidden featureとして復元せず、DTW costや経路を偽造しない。双方とも独立した小型参照へ照合する。
2. 同じ値の並び替えに対してbag統計が一致し、登録した順序判別例で順序付き照合が差を持つことを示す。
   これは構築した入力の算法上の区別であり、人が変奏・帰還を聞き分けた証拠ではない。
3. 共通controller・配送・契約検査・下流の契約検査用consumerは、同一sourceのまま二方式を処理する。
   選択・モデル内codec・その契約adapterと版付き設定が変更範囲。共通側に算法名の分岐を追加したら
   境界未達として戻す。T4/T6用の意味あるconsumerは別途適合し、検査用consumerで代用しない。
4. 元の支持と受領時刻を保持し、未来入力、旧世代、別モデルの結果の誤採用はゼロとする。
   source／入力／出力のmanifest、数値差、wall time・copy・固定buffer・未知／拒否数を保存する。
5. 第一候補のDTW固有診断はモデル内部へ残す。raw costを共通の校正済み確率と解釈させない。
   decoderが異なる特徴を必要とする場合、記憶・decoderを一組で交換して変更範囲を明示する。

MR1は小型入力での交換境界の確認に限る。現在のnative高速化検査では代用できず、
全負荷O04の合格も代用しない。対照が認知課題で劣っていても、交換経路の確認には使える。
対照を本番へ採用するには、既存の課題・再適合・校正・生成帰結・作者採用の各判定が必要である。

## 6. M0台帳と今後の実装

- **O03**: 本記録の交換単位、安定契約、版対応とMR1〜MR3を登録する。
- **O09**: MR1の数値交換を実施して結果を保存する。MR3の本体検査はM1以降に所有させる。
- **O12**: 実際の変更ごとに第4節の依存・再適合表を埋める。未適合版の出力は認知的に校正済みとしない。
- **O04/O17**: 交換後のモデル全体、adapter・copy・配送・行動を含む実費用を既存の条件で測る。
- **M1以降**: 実装の利用先が生じた境界から分割し、研究用の選択と作者用操作を区別する。

この改訂では数値モデルの式・特徴配列・容量を変更していない。feature版は`m0-registration-29`を維持する。
過去の数値検査・外部レビューは各保存版にだけ対応する。進行中のpacked scheduler／worker接続の
未検証変更を、本記録の検証済み成果へ含めない。M0完了、人の収集、本体実装の完了を意味しない。
