Conchordal スクリプトリファレンス

はじめに

English version

Conchordalは、生成的な作曲のための生体音響楽器です。Rhaiは、この楽器にシナリオを 与えるための言語であり、音符を順番に並べるためのものではありません。音から Consonance Fieldをつくり、複数のVoiceがその中を移動し、生き残り、世代を重ねながら Populationを再編成します。

シナリオでは、まずPopulationSpecを定義します。それをplace()で配置すると、 世代交代を通じて同一性を保つPopulationになります。Populationを構成する一個の 生きた要素がVoiceです。同じLandscapeを共有するすべてのPopulationを合わせたものを Communityと呼びます。和声は心理音響的なroughnessとharmonicityから生まれ、 リズムはCommunity自身が駆動する共有拍の上で創発します。スクリプトの役割は、音符を並べる シーケンサーではなく、全体の条件と流れを整える演出者です。

Conchordal v0.4.0は、こうしたコンセプトを直接検討したい研究者と開発者のための Alpha版です。機能は未完成で、不安定な場合があります。作曲家や制作者は Beta版を待ってください。一般的な音楽制作の語彙で覆い隠さず、このモデル固有の 言葉で説明します。

本書の構成

  • チュートリアルでは、最初の音を鳴らし、エディタを設定し、演奏の実行、analysisの 記録、再現を扱います： クイックスタート、 エディタ設定、 演奏。
  • コンセプトでは、一つの生きたVoiceから、生態系と時間構造の全体までを 組み立てます： Population — Voiceをまとめる持続単位、 VoiceとLandscape — 音と環境のフィードバック、 Consonance Field — 音高を評価する地形、 リズム、 ルーティングとListenerTwin、 タイムラインと構造。
  • リファレンスには、生成されたAPIリファレンスと、 順に試すためのサンプルがあります。APIは Core API、Core候補を試聴するExperimental、Mechanism Tuning、 Research Controlsの四層です。まずCoreから始め、作品が必要とするまでは 残りを無視してください。登録signatureとtier分類はengineから生成して照合し、 意味を説明する文章はdocumentation registryで管理します。

本書のすべてのrhaiコードブロックは、テストスイートによって実際の スクリプトengine上で実行されます。これにより、現在のengineでcompile・実行 できることを確認します。ただし、説明文の意味まで自動的に証明するものではありません。

クイックスタート

リアルタイムinstrumentでシナリオを実行します。DSP性能のためrelease modeを推奨します。

cargo run --release -- samples/01_a_single_voice.rhai

最小の音

place(sine().amp(0.08).sustain(), at(440.0));
wait(2.0);

place(population_spec, placement)は、現在のスクリプト時刻にPopulationをただちに配置します。 返されたPopulationへの参照を使うと、実行中のPopulationを更新したり終了したりできます。

基本オブジェクト

  • PopulationSpecは、初代として生成されるVoiceとPopulation全体の方針を記述します。 sine()、harmonic()、modal()、saw()、square()、noise()から始めます。
  • Variantはvariant(population_spec)でspecificationを複製します。
  • PlacementはPopulationをどこへ配置するかを決めます。協和、不協和、その境界、空いた音域を consonance()、dissonance()、edge()、gap()で選べます。既定では候補を確率分布として 扱い、.peak()を付けると最も強い一点を選びます。ほかにrandom()、at()、line()があります。
  • Populationはplace()が返す安定した参照です。この時点で初代のVoiceが 存在し始め、実行中に使えるメソッドは現在のVoiceを更新します。
  • SectionはPopulationの有効範囲を定め、終了時に自動で解放します。

Populationは、配置後も同一性を保つ一つの安定した参照です。.count(6)を指定したPlacementでは、 そのPopulationに6つの初代のVoiceが生まれます。後でVoiceが死亡して再生成されても、構成員と世代が 変わるだけでPopulationの同一性は保たれます。詳しいオブジェクト構造と生存過程は Population — Voiceをまとめる持続単位を参照してください。

let population_spec = harmonic()
    .amp(0.08)
    .sustain()
    .brightness(0.35);

section("plain entry", || {
    place(population_spec, line(220.0, 440.0).count(3));
    wait(4.0);
});

Consonance Fieldへ配置する

consonance(root_hz).peak()は、基準周波数の周辺で協和の評価が高い位置へVoiceを 配置します。Fieldはsystemが知覚したものによって形づくられるため、anchorが入ると peakの位置も変わります。

let anchor = harmonic()
    .brain("drone")
    .amp(0.06)
    .sustain()
    .anchor();

let voice = harmonic()
    .amp(0.04)
    .sustain();

section("field placement", || {
    place(anchor, at(110.0));
    wait(1.0);

    place(voice, consonance(110.0).peak().range(1.0, 4.0).count(6).spacing(0.9));
    wait(6.0);
});

Consonance Fieldの働きと、その中でVoiceが移動し、生き残り、再生成される仕組みは Consonance Field — 音高を評価する地形で説明します。

実行中のPopulationを更新する

発音体、振る舞い、生存過程、再生成の方針は、place()より前にPopulationSpecへ設定します。 返されたPopulationには、配置後に意味を持つ操作、つまり実行中の更新と終了だけが 公開されます。APIリファレンスには、両者のメソッドが区別して 表示されます。

let spec = harmonic().amp(0.04).sustain();
let population = place(
    spec,
    consonance(220.0).peak().count(3)
);
population.amp(0.02); // live patch on running voices
population.glide(0.8);
wait(3.0);
release(population);

完成した小品

let anchor = harmonic()

let colony = harmonic()

エディタ設定（LSP）

Conchordalには、名前を持つ呼び出し可能なスクリプティングAPIとhover documentationを 記述したRhai LSP定義ファイルが付属します。対応するclientへ接続すると、place、 harmonic、.brain()、.send(habitat_bus)などでcompletion、hover、定義への移動、 diagnosticsを利用できます。busを結合する| overloadは名前付き宣言ではなくoperatorなので、 定義ファイルには出力されません。

repository rootにある次の2ファイルが設定の中心です。

  • Rhai.toml — rhai-lspが読むworkspace設定
  • rhai-defs/conchordal.d.rhai — doc comment付きの自動生成type/function宣言

upstreamのrhai-lspは、自らをexperimentalかつ incompleteとし、一般利用を推奨していません。保証されたproduction toolingではなく、 任意の開発補助として扱ってください。それでも使う場合は、crates.ioにはないため git repositoryから直接installします。

cargo install --git https://github.com/rhaiscript/lsp rhai-cli

これにより、lsp subcommandを持つrhai binaryが生成されます。

VS Code

公式Rhai extension が現在提供するのはsyntax highlightだけで、rhai-lspは起動しません。LSP機能には、 Conchordal workspaceから次のcommandを起動できるLSP client/extensionを使います。

})
vim.lsp.enable("rhai")

演奏

クイックスタートでは、最小のscenarioを書いて実行するところまでを 説明しました。本章では、リアルタイムinstrumentを起動して演奏を始める、終了する、 GUIなしで演奏する、その結果を記録・再現する、という一連の手順を説明します。

GUIで演奏する

リアルタイムinstrumentでscenarioを起動します。

cargo run --release -- samples/10_generations.rhai

scenarioをcompileした後にGUIが開き、初期設定では自動的に演奏が始まります。scriptが 大まかな時間構造を与えます。place()がPopulationを導入し、wait()がscript上の時刻を進め、 section()とplay()は内部で作ったPopulationを有効範囲の終了時にreleaseします。その間も、 Voiceの振る舞い、Landscape、それらのfeedbackはリアルタイムに変化し続けます。

進行バーはscenario上の時刻を表示します。演奏中は、その右側にあるボタンを押すと 演奏を終了します。ウィンドウを閉じるかCtrl-Cを押しても終了します。このボタンは一時停止では なく、GUI上でscriptを実行中に書き換えることもできません。scenarioを変更するときは、演奏を終了し、 Rhai fileを編集して、もう一度起動します。

GUIを先に用意し、合図に合わせて開始するには--wait-user-startを付けます。準備ができたら Spaceを押すか、開始ボタンをクリックします。

cargo run --release -- samples/10_generations.rhai --wait-user-start

scenarioが終わっても、初期設定では最終状態を確認できるようにGUIが残ります。進行バー 右端のボタンまたはウィンドウの閉じるボタンで終了します。scenarioの終了と同時に閉じるには --wait-user-exit=falseを付けます。

GUIなしで演奏する

--noguiを付けると、すぐに演奏を始め、scenarioの終了時にプログラムも終了します。GUIは 表示しませんが、初期設定では既定の音声出力先から音を出します。

cargo run --release -- samples/10_generations.rhai --nogui

音を出さず、simulationやreport作成だけを行う場合に限り--play=falseを使います。

cargo run --release -- samples/10_generations.rhai --nogui --play=false --report run.jsonl

--noguiでは、開始待ちと終了待ちの両方が無効になります。offline WAV出力は別の操作で、 conchordal-renderが担当します。リアルタイムinstrumentであるconchordalはaudioを 記録しません。

聴く・確かめる・修正する

scenarioは、どのPopulationをいつ配置し、どのような方針で振る舞わせるかを指定します。 ただし、演奏中の正確な音高、リズム同期、生存、respawnの結果までは事前に決まりません。 それらは、変化し続けるLandscapeとの相互作用から生まれます。scenarioを実行して聴き、 実際に起きたことを確かめ、scriptを修正して、もう一度実行します。

instrumentであるconchordalは、どのbuild profileでもaudioをdiskへ書きません。 演奏は、音が鳴り終わるとinstrument内には残らない一過的な出来事（ephemeral）として 設計されています。

演奏を再現する

各runはseedをlogへ出します。

scenario seed: 3821650944810716341 (replay with --seed 3821650944810716341)

最上位のサンプルは毎回新しいseedから始まり、一つの固定結果ではなくsystemのvariationを 示します。残したいrunが得られたら、表示された値で正確に再現します。

cargo run --release -- samples/10_generations.rhai --seed 3821650944810716341

conchordal-renderでも同じ--seedを使い、保存した演奏をWAVにできます。 script内のseed(...)は実行中に初期seedを上書きするため、常にcommand-line flagより優先します。 呼び出し方に関係なくscript自体を再現可能にする必要がある場合だけ使ってください。

レポート

--reportへ書き込み先を指定して実行します。

cargo run --release -- samples/10_generations.rhai --report run.jsonl

--reportはconchordal instrumentのflagで、--noguiでも動作します。 audioを描画するconchordal-renderにはありません。

fileはJSON Linesで、1行が1 record、type fieldで種類を示します。

  • meta — 最初に記録される有効なscenario seed。
  • scene_marker — 各section("name", || { ... })の開始位置。以後のrecordを直前の markerごとにまとめられます。
  • spawn / respawn / death — Voiceごとの世代交代。出現周波数、親となるVoice、 設定寿命、energy枯渇時刻、envelope tailを含む観測寿命、初期consonance、死亡時PLV。
  • onset — Voiceごとの発音開始時刻、強度、周波数、位相同期、足場の状態。
  • population_step — 再生成待ちのalive_count: 0も含むPopulation size、 平均周波数、Consonance Field score/level、周波数entropy。
  • listener_state — ListenerTwinの4つの知覚level、beat/subdivision/measure追跡、解析遅延。
  • rhythm_observation — Community全体の瞬間的なKuramoto orderと環境rhythm state。 rhythm_summary — Community全体およびPopulationごとのonset density、IOI規則性、 burstiness。Kuramoto summaryはCommunity全体にだけ付きます。
  • listener_confidence_summary — beat confidenceのpeakと終盤window。
  • dcc_pressure — listener由来のtension pressureとDCCが加えたpitch temperature bonus。
  • phonation_gate_open — phonation gateが開いた時刻と、その時点のconsonance値。

未加工のJSONLは「Population 3の構成員が実際に入れ替わったのはいつか」「anchorが入った直後、 tension_levelはどう変化したか」といった狭い問いに直接答えます。

レポートを読む

streamはplain JSONLなので、任意のJSON toolでfilterできます。次は全deathについて寿命と 初期consonanceを取り出します。

jq -c 'select(.type == "death")
       | {time_sec, population_id, configured_endurance_sec,
          energy_depletion_sec, lifetime_sec, first_k_mean}' run.jsonl

scene_markerの時刻でbucketに分ければ、「第IV sectionでcolonyは飢えたか、その時の consonanceはいくつか」を直接読めます。専用digest toolはありません。重要なsummaryは 作品ごとに異なるため、問いに合わせた一度限りのfilterやscriptの方が固定formatより有効です。

GUI

GUIは実行中のLandscapeとListenerTwinの状態をリアルタイムに表示します。レポートは、聴いて気づいたが すべての数値を同時には覚えられなかった瞬間を、演奏後に読むためのものです。

Population — Voiceをまとめる持続単位

Conchordalを理解するための最も簡単な捉え方は、音符の次に別の音符が来るというものでは ありません。PopulationSpecが、生きたVoiceからなる持続的なPopulationへ変わります。

PopulationSpec + Placement --place()--> Population --> Voice(s)
                                                |
                                                `-- later generations

Community = runtime terrainを共有するすべてのPopulation

PopulationSpecは再利用可能な配置前の定義です。初代のVoiceの初期値と、 生存過程、生存可能性、respawnなど、Population全体に属する方針を組み合わせます。 Placementは初代のVoiceがどこへ何体入るかを指定します。place()は両者を結合し、 ただちにPopulationを返します。これはVoiceごとの参照ではなく、配置されたPopulationを 表す一つの安定した参照です。実行時のCommunityは、Landscapeを共有するすべての Populationを集約したものです。

let population_spec = harmonic()
    .amp(0.035)
    .sustain()
    .respawn_capacity(6);

let population = place(
    population_spec,
    consonance(90.0, 900.0).count(6)
);
wait(3.0);
release(population);

ここでpopulationは6つの初代のVoiceをまとめて制御します。レポートでは共有する population_idと、各々のVoiceのvoice_idを区別します。Voiceが死亡して代わりのVoiceに 置き換わるとvoice_idとgenerationは変わりますが、Populationとpopulation_idは 変わりません。

配置境界

place()だけが定義から実行時への遷移です。初期設定専用の属性は、先に PopulationSpecへすべて設定します。配置後のPopulationが公開するのは実行中の更新と releaseだけで、specificationへ戻したりfounder policyを書き換えたりはできません。

let spec = harmonic()
    .brightness(0.4)
    .brain("entrain")
    .endurance(8.0);

let population = place(spec, consonance(220.0).count(3));
population.amp(0.03); // Live patch at the current script time.
flush();              // Emit pending live patches without advancing time.
wait(2.0);
release(population);

wait(seconds)も保留中の更新を発行してからスクリプト上の時刻を進めます。 wait()もflush()も、未配置のPopulationを作りません。初代のVoiceは place()そのものによってschedule済みです。APIリファレンスでは、 PopulationSpecのメソッドを初期設定専用、Populationのメソッドを実行中に更新可能と表示します。

独立した五つの問い

PopulationSpecは、複数の独立した問いに答えます。分けて考えることで、ある音楽的判断を 別の判断と取り違えずに済みます。

問い主なcontrol意味
何が鳴るかsine, harmonic, modal, brightness, modes初代のVoiceの発音体と周波数成分。
どんな生を送るかbrain(name): entrain, seq, dronearticulationが生態系に参加するか、書かれた生を進むか、Landscapeのanchorとして持続するか。
いつ鳴るかsustain, repeat, metric, entrained, steady, flowphonationとonset timing。
音高はどこへ行くかPlacement、anchor, seek_consonance, temperature初代のVoiceが入る位置と、その後の移動。
Populationはどう持続するかendurance, recovery, viability, respawnVoiceのエネルギー、死、Populationの世代交代。

別の行に属するcallは合成できます。同じ軸では通常、最後の指定が優先されます。正確な 構築時に各メソッドがどう働くかはAPIリファレンスに記載されています。

Articulation life：brain

brain(name)は、鳴っている間にVoiceがどのような生を送るかを選びます。

  • brain("entrain")は既定の、生きた発音様式です。代謝と生存過程の設定を 通じてconsonanceとrhythmic fitに応答できます。
  • brain("seq")は固定された生を持つauthored eventです。Field viabilityとmetabolismを 無視します。
  • brain("drone")は明示的にreleaseされるまで死にません。terrain anchorなど、 持続するmaterialに適します。

これはphonation timingとは別です。

brain("entrain")は生の種類を選び、.entrained()は反復onsetを共有meterへ 中程度に結合します。

似た名前ですが別の軸なので、同時に使用できます。

let colony = harmonic()
    .brain("entrain")
    .entrained()
    .cycles(2)
    .seek_consonance()
    .endurance(8.0)
    .recovery(4.0)
    .consonance_viability(0.30, 0.80);

place(colony, consonance(90.0, 900.0).count(5));
wait(8.0);

brain()は発音体、Placement、音高の方針を選びません。droneは聴取可能にもhabitat-onlyにも でき、生きたVoiceは固定も移動もできます。同じ共鳴発音体に任意のarticulation lifeを 組み合わせられます。

Phonationとduration

Phonationは、onsetがいつ起きるか、そのonsetがどれだけ開いたままかに答えます。

  • sustain()はVoiceが生きている間、音を保持します。
  • repeat()は初期値が設定された反復発音を選びます。
  • metric()は共有拍への同期、entrained()・steady()・flow()は音響参加を選びます。 steadyは自分の予定時刻を保ち、聴いた文脈で鳴らすか見送るかだけを選びます。 発音の機会で打ち直すほか、明示の持続と併せてToneを保てます。リズムを参照してください。
  • cycles(n)はdurationをrhythmic cycle数で表します。

presetで意図を表せない場合は、低水準のonce()、pulse(rate_hz)、while_alive()、 adaptive duration controlを使えます。まずpresetから始め、作品が必要とするときだけ 明示的timingを使ってください。

Releaseはdeathではない

release(population)はスクリプトによる終端判断です。以後そのPopulationへの更新は無視され、 現在のVoiceはrelease envelopeへ入り、Populationは閉じます。生態学的な死は実行時の 結果です。一つのVoiceがenergyを使い果たした後、Populationの再生成方針が代わりのVoiceを 作る場合があります。sectionやplayの有効範囲も、終了時に内部で作ったPopulationをreleaseします。

次章では、VoiceとLandscape — 音と環境のフィードバックを説明します。

明示のsustain()とmetric()を併用すると、持続音と音から確認した拍への同期を同じVoiceで扱えます。自由音高のGateSnap／Rearticulateは、既定では採用先を保留した拍で発音し、ほかの拍では伸ばします。毎拍打つにはtie(0)。固定音高とGlideは拍ごとに打ち、持続＋entrained／steady／flowの省略値は0のままです。リズムを参照してください。

VoiceとLandscape — 音と環境のフィードバック

habitat busへ送られたVoiceはLandscapeを変え、変化したLandscapeはplacement、movement、 viabilityへ影響します。この章では、その実行時feedbackと、そこから生じるenergy、death、 respawnの過程を追います。

Voice bodies
    |-- presentation bus --> listener / ListenerTwin
    |
    `-- habitat bus --> Landscape --> placement, movement, viability
                              ^                         |
                              `------ new sound <------'

初期状態ではすべてのVoiceが両方のバスへ送られ、聴衆と生態系は同じ物理的な出来事を共有します。 意図的に分離する方法はルーティングとListenerTwinを参照してください。

音からLandscapeへ

Landscapeはhabitat busをlog-frequency spaceで解析し、次を計算します。

  • roughness potential — critical band内の干渉とbeating。
  • harmonicity potential — periodicityとvirtual rootへのsupport。
  • Consonance Field — candidate frequencyの評価に使う合成地形。

Voiceがhabitat bus上の周波数成分を変えると、これらの走査結果も変わります。そのため consonance(...).peak()は固定scale degreeを返しません。現在鳴っているものによって 答えが変わります。

Score、level、mass、density

同じLandscapeから複数の表現が導かれます。関連はありますが交換可能ではありません。

表現範囲用途
potentialkernel依存raw roughness/harmonicity output。
field score非有界の実数位置比較、hill-climb、placement tension。
field level0..1振る舞いと生存可能性に使う有界な信号。
density mass非負stochastic placementの正規化前weight。
density / PMF選択範囲内で総和1密度分布からの標本抽出。

.peak()は極値を選びます。既定の密度配置はPMFから標本を取るため、複数のVoiceは 一つの周波数区間へ重ならず、支えられた領域の周囲に分布します。 tension(degree)は最大peakより一定のfield-score stepだけ下を狙います。 生存可能性の範囲は、有界または環境相対の適合度を読みます。レポートの接尾辞も同じ区別を 保ち、mean_c_field_scoreとmean_c_field_levelは別の量です。

配置と移動は別の判断

配置はVoiceがどこへ入るか、音高の振る舞いは入った後に何が起きるかに答えます。

let fixed_strain = harmonic()
    .amp(0.035)
    .sustain()
    .anchor();

let resolving_strain = harmonic()
    .amp(0.035)
    .sustain()
    .seek_consonance()
    .glide(0.4);

section("two responses to dissonance", || {
    place(fixed_strain, dissonance(140.0, 900.0).count(3));
    place(resolving_strain, dissonance(140.0, 900.0).count(3));
    wait(6.0);
});

両方のPopulationが不協和な領域へ入ります。一方はその状態を保ち、もう一方は解決へ向かう 出発点として扱います。

自分ではなく環境を評価する

Voiceは、後で自ら評価するConsonance Fieldへ自身のエネルギーも加えます。そのままでは、強いVoiceは自分の footprintを聴くことでviableに見えるかもしれません。そこでconsonance_viability()は 既定で環境相対評価を有効にし、自分の寄与を近似的に除いて適合度を判断します。

これは生存規則であり、音の送り先を決める規則ではありません。Voiceはhabitat busへ寄与し、ほかの すべてのVoiceが読むConsonance Fieldを変え続けます。自分も含むConsonance Field全体への適合度を問いたい場合だけ viability_scope("total")を使います。

Energy、death、replacement

生態学的lifecycleはbrain("entrain")に属し、energyは0..1へ正規化されます。

  1. endurance(seconds)がzero-fit時の基準寿命を定める。
  2. attackごとにattack_cost_fractionを消費する。
  3. consonantなattackは最大attack_recharge_fractionまで回復できる。
  4. recovery(seconds)が連続回復を有効にし、viability windowが現在位置での回復量を決める。
  5. energyがゼロになるとVoiceは死亡し、音の減衰へ入る。
  6. 再生成の方針があれば、Populationは代わりのVoiceを生み出せる。
let settlement = consonance(70.0, 1100.0).spacing(0.8);

let ecology = harmonic()
    .brain("entrain")
    .entrained()
    .cycles(2)
    .seek_consonance()
    .endurance(8.0)
    .recovery(4.0)
    .attack_cost_fraction(0.017)
    .attack_recharge_fraction(0.70)
    .consonance_viability(0.32, 0.82)
    .respawn_consonance()
    .respawn_capacity(8)
    .respawn_settle(settlement);

place(ecology, consonance(70.0, 1100.0).count(8));
wait(20.0);

respawn policyは異なる作曲上の問いに答えます。

  • respawn_random() — parentの系譜を作りません。Populationを最初に配置したPlacementから candidateを作り、現在のscene scoreで重み付けして選びます。一様random配置ではありません。
  • respawn_hereditary(sigma_oct) — living parentをenergyで重み付けして選び、その近くへ offspring候補を作り、現在のField levelが最も高いcandidateを採用します。
  • respawn_consonance() — living parentをenergyで重み付けして選び、そのparentの周辺へ 偏らせながらfield scoreの高いpeakから選びます。
  • respawn_capacity(n) — Populationが維持する生存個体数の上限。未指定時は初代の個体数で、 明示値をfounder数より小さくはできない。
  • respawn_settle(placement) — そのPlacementからcandidateを追加します。respawn policy本来の baseline candidateも一つ残ります。

respawn後もPopulationとpopulation_idは維持され、voice_idとgenerationが変わります。 レポートの記録により、この世代交代を観測できます。

実行時のfeedbackと人間による修正

  • 実行時のfeedbackは自動です。音がLandscapeを変え、LandscapeがVoiceの振る舞いと 生存を変えます。
  • 人間による修正はrunの間に行います。実行し、聴き、reportを調べ、scenarioを修正して 再実行します。

実行して結果を確かめ、修正する具体的な手順は演奏で説明します。

Consonance Field — 音高を評価する地形

Conchordalの知覚coreであるLandscapeはhabitat busを聴き、log-frequency spaceへ 変換して二つのpotentialを計算します。roughnessはcritical band内の振幅変動による 感覚的不協和、harmonicityはperiodicityとtemplate matchingです。この二つを 組み合わせたConsonance Fieldは、placement、movement、prediction、survivalが 読む、周波数上の評価地形です。

Consonance Fieldはhabitat busから計算されるため、そのbusへ送られたVoiceが ほかのVoiceの読むConsonance Fieldを変形します。presentation busだけへ送られたVoiceは 変形しません。和声はchord chartではなく、このfeedback loopから生まれます。 potential、score、level、mass、densityの関係は VoiceとLandscape — 音と環境のフィードバックを参照してください。

Consonance Fieldへの配置：consonance、dissonance、edge、gap

Consonance Fieldに応じたPlacementでは、Field内の対象領域を指定します。既定では確率分布から位置を選び、 .peak()を付けると決定的な極値を選びます。

  • consonance — consonanceが高い位置（harmonic center、fusion）。
  • dissonance — consonanceが低い位置（tension、cluster、color）。
  • edge — consonance/dissonanceの境界（metastableな中間）。
  • gap — 空いたregister（空間を埋め、maskingを避ける）。

consonance(root)はroot周辺のharmonic windowを取り、range()で倍音範囲を指定します。 どの配置先にも、絶対周波数の(min_hz, max_hz)範囲を渡せます。

範囲の両端には、音源が扱える1〜20000 Hz内の有限値を指定します。大小が逆でも使えます。 初期配置は微小な揺らぎ（jitter）を加える場合も、重みがすべてゼロ、または全域が占有済みで 代替の抽選を行う場合も、指定範囲を守ります。Consonance Fieldに基づくPlacementは 解析帯域（現在55〜8000 Hz）との共通部分を使います。共通部分がなければ評価の根拠を 得られないため、指定範囲内の対数一様分布へ 切り替わります。random()は指定範囲を直接使います。この範囲は初期配置の指定であり、 その後のseek_consonance()による移動を同じ範囲へ制限するものではありません。

let anchor = harmonic()
    .brain("drone")
    .amp(0.06)
    .sustain()
    .anchor();

let voice = harmonic()
    .amp(0.04)
    .sustain();

section("field placement", || {
    place(anchor, at(110.0));
    wait(1.0);

    place(voice, consonance(110.0).peak().range(1.0, 4.0).count(6).spacing(0.9));
    wait(6.0);
});

追加指定のない配置先は密度分布として扱われます。「無作為だが調和的」なのではなく、 協和のモデルから導かれ、指定範囲内で正規化された分布です。配置は配置後の振る舞いから 独立しています。dissonanceへ入りanchor()でclusterを保持することも、 seek_consonance()で解決へ向かわせることもできます。

let cloud = harmonic().amp(0.035).sustain();

place(cloud, consonance(90.0, 1200.0).count(10).spacing(0.8));
wait(8.0);

配置時の緊張度：tension(τ)

tensionを指定しないConsonance Placementは、通常の方法で実現されます。.peak()なら 最も強いpeakを選び、既定のdensityなら通常のConsonance密度分布を作ります。 tension(τ)は、最大値より一段下のfield-scoreへ配置を偏らせます。 τ ∈ [0, 1]がtension degreeで、0は通常の配置を変えず、大きい値ほど弱く metastableなstepを対象にします。指定範囲内の評価値で target = L_max − τ·(L_max − L_min)です。movementにおけるsearch temperatureと 対になる、spawnをどれだけ解決した位置に置くかのdialです。.peak()なら最も近いstepへ 最寄りの段へ固定し、確率分布なら対象値の周辺へ重みを集中させます。

let tense = harmonic().amp(0.035).sustain();

// A metastable step below the strongest peak — placed, not resolved.
place(tense, consonance(110.0, 1200.0).peak().tension(0.4).count(6).spacing(0.8));
wait(6.0);

Consonance Fieldに依存しないPlacementには、対数周波数上で一様なrandom(min_hz, max_hz)と、幾何的な at(hz)、line(start_hz, end_hz)があります。

周波数をroot比で名づける

at(hz)とline(start_hz, end_hz)は絶対周波数を取ります。標準的な書き方は、 鳴っている一つのrootをHzで名づけ、他のpitchをその比として導くことです。完全5度なら root_hz * 1.5、完全4度ならroot_hz * 4.0/3.0、registerを上げるなら root_hz * 2.0です。比はField自身が読む物理量なので、周波数関係として考えられます。

平均律のdecimal、たとえばD3を表す146.83も動作しますが、12音のsymbol gridを裏口から 持ち込みます。sceneで実際に鳴っているrootの比を優先してください。

let root_hz = 110.0;
let voice = harmonic().amp(0.04).sustain();

place(voice, at(root_hz * 1.5));
wait(2.0);

Consonance movement：seek_consonance

VoiceがConsonance Field上のより良い位置を能動的に探すときはseek_consonance()を使います。 自由な山登り探索と音高推移の初期値を設定します。同じ移動を遅く、または速く 動かしたいときはglide(tau_sec)を使います。

let mover = harmonic()
    .amp(0.045)
    .sustain()
    .seek_consonance()
    .glide(0.35)
    .avoid_neighbors(0.6)
    .global_peaks(8, 70.0)
    .ratio_candidates(5);

place(mover, consonance(80.0, 900.0).count(8));
wait(12.0);

avoid_neighbors(strength)は混雑を避ける反発を加え、移動するVoiceがすべて同じ山へ重なるのを防ぎます。 移動の反対はanchor()です。固定されたVoiceは音高を保ち、ほかのVoiceが読むConsonance Fieldだけを 変形します。freq()は音高を固定し、anchor()は配置で選ばれた音高を保ちます。

at(hz)も通常は音高を固定します。ただし、配置するPopulationSpecに明示の seek_consonance()の意図が残り、音高が自由のままなら、初期位置だけを指定します。 この場合はline(hz, hz)と同じ配置となり、指定した人数も保ちます。たとえば、 上のmoverをplace(mover, at(220.0))で置くと、移動や滑りの指定を保って220 Hzから 始めます。指定するのは身体の初期音高で、最初に聴こえる音高や、その後の移動を保証する 指定ではありません。

音高の方策を変えるときは、書く順で最終の指定が決まります。

最後に書いた指定の順at(hz)の意味
seek_consonance() → freq()固定音高
freq() → seek_consonance()初期位置
seek_consonance() → anchor()固定音高
anchor() → seek_consonance()初期位置

動く指定を明示しなければ、at()は音高を固定します。演奏中のPopulationのfreq()も、 従来どおり音高を固定します。

移動の反映方法は発音様式から決まります。持続するVoiceは滑らかに移り、再発音するVoice （pulse()、metric()、entrained()、steady()、flow()）は発音開始ごとに新しい音高へ 移ります。pitch_apply_mode("gate_snap")とpitch_apply_mode("glide")で、 この反映方法を明示的に選べます。

持続するVoiceで、新しい音高の行き先を採用するたびに発音し直したい場合は、 参加の時計を付けず、pitch_apply_mode("rearticulate")を指定します。移動の始まりで旧いToneをreleaseし、 新しいToneは頭から新しい音高でattackします。棄却した提案、同じ行き先、 glideの途中の更新では発音し直しません。提案の間隔は行き先を選ぶ機会の間隔であって、 一定の音符を刻む時計ではありません。発音を拍に合わせて遅らせる処理もありません。

let moving = harmonic().sustain().seek_consonance()
    .pitch_apply_mode("rearticulate");
let voices = place(moving, line(220.0, 440.0).count(3));
wait(12.0);
voices.pitch_apply_mode("glide");
wait(12.0);

演奏中にglideとrearticulateを切り替えても、鳴っているToneを止めたり、 切り替えだけで新しい発音を起こしたりしません。まだ出力していない再発音の要求を取り消し、 次の採用から新しいmodeを使います。再出生するVoiceにもPopulationのtemplateから 同じmodeが渡ります。glide(tau)はGlideと、打ち直しの境界以下で滑る時の移動の時定数です。 anchor()などで固定されたVoiceにrearticulateは作用しません。

対象は音高が自由なHoldのVoiceです。自由音高のGated発音とrearticulateの組み合わせは、 builderの呼び出し順にかかわらず、配置時の最終specでscript errorになります。 演奏中の対象外の指定も、状態を書き換える前に拒否します。sustain()でHoldにするか、 Gatedではgate_snapまたはglideを選んでください。参加の時計がないHoldには、同音高の 発音だけを求める指定はありません。持続＋参加では機会による現在音高の打ち直しも できます。Voice自身が一音ごとに方策を選ぶ機能は含まれません。

音高の移動と発音の結びつきを選ぶ

行き先を採用する時と、参加の機会で鳴らすと選ぶ時は別です。次の表で、移動を音の区切りに どう結びつけるかを選べます。境界は創始のVoiceに置く発音の気質で、作曲者が選ぶ量です。 50や100 centは使い方の例であり、聴覚の原理から決まる値や推奨値ではありません。

参加の各行では、entrained・steady・flowをそれぞれ選べます。steadyはGlideでも dueの機会だけを残します。時計の違いは リズムの章で説明します。

参加の各行にintrinsic_rate(hz)を添えると、音高の適用方法とは独立に身体の初期の尺度を 置けます。発音間隔の命令や共通拍の指定にはなりません。proposal_interval(seconds)は 引き続き音高の提案の間隔です。身体の固有の速さを置くを 参照してください。

参加の時計がない場合、正の境界を指定したrearticulate_above(cents)は、最後に実際に発音した音高からの正味の変位を測ります。 経路の距離を足し合わせる量ではなく、元の音高へ戻れば相殺されます。境界以下なら同じToneで glide(tau)に従って滑り、境界を超えれば新しいToneを立ち上げます。選択は次の採用まで 保持します。両端がLog2Spaceの正確なbin中心ならbin差をcentへ換算し、それ以外は連続した log2座標の差を使います。行き先の丸め直しやepsilonは加えません。同じ未出力hopに先行する 合法な発音があれば、その音高を基準にします。取り消した要求を実発音の記憶へ残しません。

参加の時計がない場合、省略値0は採用ごとに打ち直す従来の形です。負値と有限でない値は0にし、上限は置きません。 演奏中に境界を変えても、それだけでは発音せず、次の採用から使います。Rearticulate以外への 指定は警告して無視します。配置前の書く順に依存しません。再生成したVoiceは境界を継ぎますが、 親が最後に発音した音高は継ぎません。

let moving = harmonic().sustain().seek_consonance()
    .pitch_apply_mode("rearticulate").rearticulate_above(50).glide(0.03);
let voices = place(moving, consonance(220.0, 660.0).count(2));
wait(3.0);
voices.rearticulate_above(100);
wait(3.0);
release(voices);

参加の時計を持つRearticulateでは、同じ距離の測り方を使い、打ち直しの時刻は時計に 委ねます。正の境界以下の採用は、その時刻から滑り始め、発音せず、旧い保留を取り消します。 境界を超える採用は進行中の滑りを止め、身体の音高を保ち、最新の行き先を一つ保留します。 鳴らすと選んだ機会で保留を消費し、そこへ跳んで打ち直します。保留がなければ、その時点の 身体音高で打ち直します（tieの省略または0）。滑っている途中なら、前の発音と音高が違う場合もあります。 どちらの打ち直しでも最後の実発音音高を更新します。待つ・見送るなら音と保留を保ち、 既に始まった滑りは続きます。同じsampleでは採用を先に処理し、採用時刻の発音候補を 追加しません。境界で時計の発音を間引きません。境界の省略と0はGateSnapと同じ形で、 距離0の採用も保留します。演奏中の切り替えはリズムの章で説明します。

正の境界を持つこの形では、配置前のarticulation_persistence(p)でBase／Connectを 既存の出来事にまたがって保てます。移動の境界やつなぐ割合を変える指定ではありません。 発音の方針を保つを参照してください。

gate_snap／rearticulateの参加では、tie(p)で保留がないToneを打ち直さず伸ばす確率を 置けます。gate_snapの小さい採用を含む、保留ありの発音は通します。 行き先がない機会では音を伸ばすを参照してください。

持続＋同期も同じ保留の規則を使いますが、自由音高のGateSnap／Rearticulateでは、 省略時はtie(1)と同じく保留の無い拍で伸ばします。毎拍打つにはtie(0)と書きます。 固定音高とGlideは従来どおり、entrained／steady／flowの参加は省略時0のままです。 持続音を拍へ同期させるを参照してください。

音を切って間を置く

持続音と参加の機会を併せ持つVoiceにrest()を指定すると、発音ごとに有限の音長で 音を離し、鳴り終わってから能動的な間を置きます。音長はcycles(n)、または adaptive_duration()とその調整語で指定します。音長、明示のsustain()、 entrained()・steady()・flow()、rest()は、書く順によらず独立に保持します。 有限の音長を暗黙に補う処理はありません。明示のwhile_alive()は有限の指定を消し、 その後に有限の音長を指定し直さなければ配置時にerrorになります。

予定したOffで通常のreleaseを始め、余韻は切りません。rendererが同じsource IDと generationに属する全Toneの終了を確認してから、間を数えます。rest()は確認時の 固有周期一つ分、rest(periods)は作曲者が置いた倍数のあいだ発音を禁止します。 周期が既知ならrest(0)は余韻の終了だけを待ちます。周期が未知の場合も、音が 鳴り終わっていない場合も、代わりの値や期限を置かず待ちます。負値と有限でない値は 0にし、有限の非負値に上限は置きません。

音長と間には同じ身体の固有周期を使います。intrinsic_rate(hz)で速さを変えると、同じ cyclesやduration_range、rest(periods)でも秒単位の音長と間が一緒に変わります。 entrainedが音響の反復に合わせて更新する参加周期とは独立です。

間が終わると、既存の参加の判断で鳴らす・待つ・見送るを選べます。間の終わりだけで 発音を強制しません。GateSnapは発音中、余韻待ち、間のあいだも最新の行き先を保留し、 次に鳴らすと選んだ機会で消費します。Rearticulateも余韻待ちや間のあいだに採用を扱い、 小さい採用は旧保留を取り消し、大きい採用は保留します。次の実発音まで、最後の発音音高を 基準にします。Off後も身体の滑りは続きますが、離した余韻は動かしません。Glideでも Off後の余韻に音高更新を渡しません。 release、死亡、removeが優先します。再生成したVoiceは設定を継ぎ、演奏の状態は 新たに始めます。

let notes = harmonic().sustain().entrained()
    .adaptive_duration().duration_range(0.2, 0.2).rest(2);
let voices = place(notes, at(330.0));
wait(3.0);
release(voices);

ここでの0.2周期と間の2周期は使い方の例で、推奨値ではありません。restは音長の 語と同じく配置前の指定です。明示の持続＋entrained／steady／flowと有限の音長が必要で、 Glide、GateSnap、Rearticulateを選べます。対象外の配置は状態を書き換える前に拒否します。 restがなければ既存の規則を保ちます。この形では全ての音が有限長で終わり、Voiceが 一音ごとに伸ばすか切るかを選ぶ機能は含まれません。

研究scriptにはpitch_core()など機構水準のcontrolもありますが、作品では seek_consonance()を入口にし、発音し直すか滑らかに移るかを選んでください。

consonance_viability(low, high)はconsonance window、recovery(seconds)は最大回復に 要する時間を定義します。適合度の高いVoiceは支えられ、低いVoiceは基準 endurance(seconds)へ近づきます。既定では自分の音響的な痕跡を近似的に除く 環境相対評価です。Consonance Field全体への適合度を問う場合だけviability_scope("total")を使います。

再生成は循環を生態系として閉じます。Voiceが死亡すると、再生成の方針に従って代わりのVoiceが 現れます。respawn_consonance()は、energyで重み付けして選んだliving parentの周辺へ 偏らせながら、field scoreの高いpeakから選びます。respawn_capacity(count)はliving membership上限です。respawn_settle(placement)はpolicy本来のcandidateを置き換えず、 replacementのcandidate poolへそのPlacementを追加します。

リズム：時間の知覚と個体の参加

拍は、音から推定する反復的な時間の基準です。同じ音を参照するVoiceが、同じ拍位置で 発音する必要はありません。

プリセットが保つ時間関係

プリセットは、時刻を決める方策が保つ関係を選びます。発音の機会と実際の打ち直しは 別です。生存過程、発音ゲート、有限音長、休止、発音の方針によって、発音を控えたり 生きたToneを伸ばしたりする場合があります。

entrainedの参加周期を更新するときは、まだ確定していない将来の予定までの残り時間を、 新旧周期の比で写します。確定した予定を新しい音響文脈で動かしません。

entrainedとflowは、過去のhabitat音声から得た短い未来の予期を使います。Voice自身が 合成した音も記録し、自分の反復を競合相手として扱わないようにします。発音予定の近傍で 鳴る、参加の1周期まで待つ、今回は見送る、を比較します。重なりは予定する保持時間と ADSRのreleaseを含む範囲で評価します。自分で見送った回数が増すほど次の見送りの 費用は増え、実際の発音指令で回数をリセットします。発音したときだけ周囲との関係の 記憶更新を予約し、対応する実音の観測が届いてから更新します。待ち、見送り、未実行の 予定を発音した経験にはしません。保持時間と重なり予測の音長は固有周期から求めるので、 参加周期の適応によって各音を引き延ばしません。三つの帯域のエネルギーを使う評価は 工学的な近似であり、聴覚上のマスキングや協和・融合のモデルではありません。

生成側の拍にraw T2を使う

TOMLのtop-levelでtemporal_meter_t2 = trueを指定すると、既存の生成側の拍が habitatのraw T2の連続再来を読みます。既定はfalseで、従来のevent入力を保ちます。 群のアクセントや到来を指定する[temporal_t2]とは別で、そちらの成分の重みや periodの設定は必要ありません。

T2は再来を提案し、固定した未来の成分予測を後の観測で確認します。 位相と強度は実habitatのfluxと実行したonsetから読み、最初のseedの確信度は0です。 欠測を負例にせず座標を保ち、filterを再起動した境界では支持のない比較を作りません。 offline描画ではsourceと受信のcutを固定し、実時間では届いたpacketを使います。

metricは従来と同じ、拍の確信度に応じた引力を使います。確信度は速い位相の整合と 再来の支持を組み合わせたscoreで、位相の正しさの保証ではありません。 ListenerTwinのpresentation側meter、steady・entrained・flowの私有の時刻の規則は それぞれの既存の機構を保ちます。

自分の発音予定を保つ：steady()

steadyで過ぎた機会や合法でない機会を進めるときも、固有周期の整数倍で進め、格子を ずらしません。持続音の初回のHold発音は、後続の格子とは別に従来どおり即時です。 費用の項や重みは変えません。いまの到来費用は鳴らすか見送るかを変えません。候補が 予定時刻一つで、見送りの比較から到来費用を除くためです。

let voices = place(harmonic().steady().sustain().intrinsic_rate(2.0)
    .seek_consonance().pitch_apply_mode("gate_snap"), line(220.0, 330.0).count(2));
wait(6.0);
release(voices);

timingのプリセットは後の指定が優先されます。flow().steady()はsteady、 steady().flow()はflowを選びます。音長は別軸の既存規則に従います。配置前の指定であり、 演奏中に呼ぶ語ではありません。明示のsustain()との順は問わず、見送った機会では 現在のToneを保ちます。Glide、GateSnap、Rearticulateとその境界、tie（省略時0）、 articulation_persistence、有限音長とrestの併用と優先順は既存のままです。 Glideでも音高を採用した時刻の発音候補を足しません。音高の適用方法を演奏中に替えても Toneを保ち、その変更だけでは発音しません。再生成では保存した方策と速さを継ぎ、 初期位相、due、予定、演奏状態は新しく始めます。

Director水準の地形

演出者は次の操作で、metricが参照する生成側の拍の地形を調整します。 entrained・steady・flowの身体の速さや、反復予測の周期候補を直接指定する操作ではありません。

  • meter_stability(value) — 拍を引き込む深さ（attractor depth）を[0,1]で指定します。 既定値は0で、中立の状態です。拍が形成されやすい度合いに加え、好みのテンポに 寄せて拍を読む強さも、同じ深さで決まります。好みの中心はtemporal_basinの中心、 帯域を置かなければ2 Hzです。これは作曲者が置く、モデル化した聴き手の文化層の 事前分布です。実際の周期性への引き込みを強める操作であり、非周期の入力から 拍を作り出しません。
  • temporal_basin(min_hz, max_hz) — 拍が適応できるテンポの帯域を指定します。 拍はその中心から始まり、適応も帯域内に限られます。stabilityが0なら、中心を 好む重みも、中心へ戻す力も足しません。深くするほど、中心に寄せた拍の読みと、 確信度に依存する中心への復元が強まります。consonance(min, max)の時間軸版であり、 拍を配置したり、小節を強制したりはしません。同じ整形済みの中心を、metric()の Voiceが自走を始める速さにも使います。この初期値はstabilityに依存しません。 basinを置かなければ、metricの初期値は従来どおり2 Hzです。

basinはscene全体の初期条件です。scriptで最後に指定した値を、place()とcreate()で 作る全てのmetricのPopulationに使います。Populationの配置後やwait()の後で指定しても、 同じsceneの初期値を上書きします。演奏途中で切り替える指定にはなりません。

身体が最初に刻む周期と、音から確認された拍は区別します。metricの各Voiceは別々の 初期位相を持ちます。音から拍を確認するまでは確信度と共有拍への結合は0で、確認後に 聴こえた拍へ近づきます。再生成したVoiceはPopulationに保存した初期設定から始まり、 親が演奏中に得た周期を継ぎません。entrained・steady・flowの固有ペース、pulse(rate_hz)で 明示した速さは、この初期化の対象外です。

既定の帯域で4 Hzの等間隔の入力を最初から観測する対照では、stabilityが0なら 4 Hzの拍、1なら2 Hzの拍の二分割として読みます。深さは駆動の強さと証拠を読む 速さにも従来どおり作用し、テンポの好みだけを独立に動かす操作ではありません。 間隔の仮説を初めて確認するまでは確信度を0に保ちます。ただし、確認後の不規則な 入力が偶然まとまり、一時的に確信度が上がる場合は残ります。

Voiceごとのプリセットと調整

metric()、entrained()、steady()、flow()は速さの引数を取りません。place()やcreate()より前に PopulationSpecへ設定します。時間関係と結合の省略値は上の表のとおりです。 参加の身体の尺度はintrinsic_rate(hz)で指定できます。

.entrained()とbrain("entrain")を混同しないでください。前者はonset timing、後者は Voiceの発音上の生と代謝を選びます。独立しており併用できます。

Voiceごとの設定で、参加の仕方を調整できます。

  • entrainment(strength) — [0,1]の影響の強さです。方式ごとの意味と省略値は上の表を参照してください。選んだプリセットの中で作用の強さを変えます。
  • rhythm_role("beat"|"subdivision"|"accent"|"texture") — metrical role。 accentは共有meterを強く駆動するonsetを出し、反復downbeatからmeasureを創発できる。
  • microtiming(amount) — metricの目標位置を拍位相でずらします。範囲は[-0.5, 0.5]、0.5は半拍です。entrained・steady・flowへ固定された発音位置を割り当てる設定ではありません。
  • measure_accent(amount) — 検出したmeasureに沿って、発音ごとの強弱を弱く変える設定です。 範囲は[0,1]、既定値は0。強度の倍率は1 + 0.35 * amount * confidence * cos(phase)です。 位相の原点は観測した強拍に合わせ、measureが未検出なら強度を変えません。 発音時刻は指定せず、rhythm_roleとは独立して働きます。
meter_stability(0.85);     // attractor depth: how readily a pulse forms
temporal_basin(1.8, 2.2);   // tempo region the emergent beat gravitates toward

let beat = harmonic()
    .metric()
    .rhythm_role("accent")  // a strong onset that drives the shared beat
    .cycles(2);

let entrained = harmonic()
    .entrained()
    .cycles(2);

let drift = harmonic()
    .flow()
    .cycles(1);

let offbeat = harmonic()
    .metric()
    .microtiming(0.5)       // a half-beat offset reads as syncopation
    .cycles(2);

place(beat, at(110.0));
place(entrained, consonance(110.0).peak().count(3));
place(drift, consonance(300.0, 1200.0).count(4));
place(offbeat, at(220.0));
wait(12.0);

下で説明する明示の持続と参加の併用を除き、同じ軸では最後の指定が優先されます。調整値は記憶され、対応するプリセットを選んだ時に適用されるため、 entrainment(0.8).metric()とmetric().entrainment(0.8)は同等です。 duration_range(...).adaptive_duration()と逆順も同様です。

身体の固有の速さを置く

intrinsic_rate(hz)は、entrained()・steady()・flow()で初代として生成されるVoiceの 身体の尺度をHzで置きます。固有周期は1/hzです。発音の間隔を命じたり、共通の拍を 置いたりする語ではありません。entrainedは聴こえた反復へ参加の周期を寄せますが、 固有の値は生存中ずっと保ちます。steadyは発音予定の周期も動かしません。flowはこの尺度から不規則な更新間隔を作ります。 どの形も機会を見送れ、entrainedとflowは待つ判断もするため、身体の速さを違えても、実際の発音の 二つの速さが永久に保たれる保証はありません。

place()またはcreate()より前にPopulationSpecへ指定します。参加のプリセットとの 前後は問いません。演奏中の変更には使えません。再生成ではPopulationのtemplateの値を 読み、新しい初期dueと演奏状態から始めます。親が適応した参加周期、発音予定、発音の 方針は継ぎません。

同じ固有周期を、有限音長のcyclesとduration_range、rest(periods)、重なり予測の 代表的な保持長にも使います。速さを変えると、音の長さと間の秒数も一緒に変わります。 flowの音長には既存の3倍係数が残り、ADSRのreleaseは秒指定のままです。有限音長を 指定しない持続音を、固有周期ごとに自動で切る働きはありません。

let slow = harmonic().sustain().entrained().intrinsic_rate(0.5)
    .seek_consonance().pitch_apply_mode("gate_snap");
let quick = harmonic().intrinsic_rate(2.0).sustain().flow()
    .seek_consonance().pitch_apply_mode("gate_snap");
let a = place(slow, at(220.0));
let b = place(quick, at(330.0));
wait(6.0);
release(a);
release(b);

ここでの速さは使い方の例で、推奨値ではありません。最終の指定がentrained・steady・flowなら、 有限の0.01〜200 Hzだけを受け入れます。範囲の外と有限でない値は、配置前のscript errorに なります。この範囲は実行を保護する値で、音楽的な推奨範囲ではありません。flowの更新間隔には 別の既存の制限0.035〜4秒もあるため、極端な速さでは実際の間隔はrateに比例しません。 最終の形がmetric、pulse、repeat、onceなど対象外なら、値が不正でも警告して無視します。 省略時は既存の2 Hzの経路を使い、metricのbasinの規約も変えません。

rhythm_freq(hz)はEntrainのアーティキュレーション内部の振動子を設定し、この参加の 尺度は変えません。proposal_interval(seconds)は音高を提案する機会の間隔であり、 発音を命じたり、身体の固有の速さを変えたりする語ではありません。

持続音を保ちながら参加する

sustain()とentrained()・steady()・flow()のいずれかを明示すると、Voiceは音を保ちながら、 参加の機会ごとに鳴らすか見送るかを判断します。entrainedとflowは時刻を待つ判断もします。書く順には依存しません。 sustain().entrained()とentrained().sustain()は同じ形です。 鳴らすと選んだ時は、旧いToneを離し、そのsampleの身体の音高で新しいToneを立ち上げます。 待つ・見送ると選んだ時は、鳴っているToneを保ちます。見送りを無音の間隙には変えません。 音高が同じでも、参加の機会で打ち直す場合があります。

let p = place(
    harmonic().sustain().entrained().seek_consonance().glide(0.03),
    consonance(220.0, 660.0).count(1)
);
wait(3.0);
release(p);

entrainedとflowの既定の"glide"では、新しい音高目標を採用した時に、そのsampleでの発音も、まだ決めていない合法な参加の機会へ 候補として渡します。既存の時刻、音響の文脈、重なりの費用で比較し、同じ費用なら既存の 候補を残します。既に決めた発音の予定は動かしません。採用時の発音が選ばれなければ、 音高は滑らかに移ります。採用と時計の発音が同じsampleに重なった時は、一回だけ発音します。 移動中に時計が発音を選んだ時も、その時点の身体の音高を使い、移動先へ先に跳びません。 release、死亡、removeは保留中の要求を取り消します。発行した発音は、通常のenergyと 音響の経路へ一回だけ渡ります。

参加の予測には、既存の有限長の代表的な音のfootprintを使います。音を続ける案と、 旧音を離して打ち直す案の波形を、その場で厳密に描いて比べる仕組みではありません。 フレーズの境界の検出や、音程による打ち直しの閾値も追加しません。

この併用で音高の適用方法を省略すると"glide"になります。音高が自由なVoiceへ "gate_snap"を明示すると、採用した行き先を一つ保留し、参加の機会で鳴らすと選ぶまで 現在の音高を保ちます。鳴らすと選んだ時に旧いToneを離し、保留した音高で新しいToneを 立ち上げます。保留中に別の行き先を採用すれば置き換えます。待つ・見送る間は音も保留も 保ち、滑りません。tieを省略するか0なら、保留がない機会でも現在の音高を打ち直します。

GateSnapは採用時刻の発音候補を追加せず、参加の費用と見送りの規則をそのまま使います。 同じsampleでは採用を先に処理し、その後の機会で使います。未来の採用を先の発音に 使いません。release、死亡、removeは保留を取り消します。

let p = place(
    harmonic().sustain().flow().seek_consonance().pitch_apply_mode("gate_snap"),
    consonance(220.0, 660.0).count(1)
);
wait(3.0);
p.pitch_apply_mode("glide");
wait(3.0);
release(p);

演奏中のGlide、GateSnap、Rearticulateの切り替えでは、鳴っているToneを保ち、余分な発音を起こしません。 未出力の要求と、保留していた発音用の行き先は取り消します。Glideへ戻すと、音高の判断側に 残っている目標へ、次の制御更新から滑り始めます。GateSnapやRearticulateへ替えた後は、その後の採用を 保留します。同じmodeをもう一度指定した場合は保留を保ちます。再生成したVoiceはmodeを 継ぎますが、親の演奏中の保留は継ぎません。参加のプリセット自体は配置前の指定です。

この形にpitch_apply_mode("rearticulate")を添えると、rearticulate_above(cents)で 滑りと保留を組み合わせられます。最後の実発音音高から測り、正の境界以下の採用は 旧い保留を取り消して滑り、超える採用は滑りを止め、次に鳴らす機会まで行き先を保留します。 保留のない機会は、その時点の身体音高で打ち直します。待つ・見送る時も既に始まった滑りは 続きます。どの打ち直しでも最後の実発音音高を更新し、境界は時計の発音を間引きません。 境界の省略と0はGateSnapと同じです。参加の時計がないHoldのRearticulateは採用時に 発音し、この形では鳴らすと選んだ機会で発音します。

演奏中の境界変更は、それまで選んだ挙動を次の採用まで保ちます。mode変更では未出力の 要求、保留、選んだ滑りを取り消し、Toneと判断側の目標を保ちます。配置前の書く順に 依存しません。再生成したVoiceは設定を継ぎ、親の保留、滑りの選択、最後の発音音高は 継ぎません。

既定のWhileAliveと、while_alive()だけでは、この形を選びません。sustain()だけ、 entrained()だけ、flow()だけの挙動は変えません。pulse()、repeat()と sustain()の併用は、従来どおり後の指定が優先されます。明示のsustain()とmetric()は、 下の持続＋同期を選びます。rest()がない場合は、後に cycles()やadaptive_duration()で有限の音長を指定すると、持続する形を置き換えます。 rest()があれば音長と持続＋参加を独立に保ち、音を離し、実際の余韻の終了から間を 数えます。音を切って間を置くを参照してください。

発音の方針を保つ

自由音高の持続＋参加にarticulation_persistence(p)を添えると、Voiceが音高の採用や 参加の機会をまたいで、発音の方針を保ちます。対象は、 sustain()とmetric()／entrained()／steady()／flow()を明示し、pitch_apply_mode("rearticulate")と 正のrearticulate_above(cents)を指定した形です。配置前の指定で、演奏中の Populationには呼べません。

let p = place(
    harmonic().sustain().entrained().seek_consonance()
        .pitch_apply_mode("rearticulate").rearticulate_above(50)
        .articulation_persistence(0.75),
    consonance(220.0, 660.0).count(1)
);
wait(3.0);
release(p);

この例の境界と保持確率は比較用の値で、推奨値ではありません。Voiceは、既存の境界と 参加の規則に従うBaseから始まります。もう一つのConnectでは、Toneが生きている間、 大小どちらの採用でも滑り、参加が鳴らすと選んだ機会の発音を控えて、現在の音を伸ばします。 これは費用による見送りとは別の意図による抑止です。新しいTone、発音による回復、 発音由来の参加文脈の学習は起こしません。

小さい採用と費用による見送りはConnect、大きい採用と新しく鳴らすと選んだ機会はBaseを 提案します。0 < p < 1では、現在と反対の提案だけで専用の乱数を一回引き、確率pで 方針を保ち、1-pで替えます。同じ提案や待ちのhopでは引き直しません。既に決めた 将来の機会は、実行まで同じ判断を使います。Connectへ替わる時は旧保留を取り消し、 最後の実発音音高を保ちます。取り消した採用を後で再演しません。

pはつなぐ割合ではなく、方針の続きやすさです。保持はBaseにも働くため、pを 上げてもConnectの時間や発音数は単調には動きません。長さは既存の出来事の回数で決まり、 秒や拍の数を指定しません。この保持は惰性であり、聴こえた終止、輪郭、間とは結び付かず、 フレーズの境界を推定する働きもありません。

既定の0と端の1は、私有状態や追加の乱数を通らず既存の経路を使います。1では出生時の Baseのまま替わりません。有限値は0〜1へ丸め、正の無限大は1、負の無限大とNaNは0に します。対象外の最終指定は警告して無視します。書く順には依存しません。再生成では templateのpだけを継ぎ、方針、乱数の途中、保留、最後の発音音高を継がずBaseから 始まります。演奏中のmode変更はBaseへ戻します。同じmodeの再指定と境界だけの変更は 保持を続け、境界0の間は私有経路を休止します。

有限音のOff、rest()、余韻終了、間、release、死亡、removeは保持より優先します。 Toneが無ければ、Connectも合法な初回発音や休止後の復帰を塞ぎません。方針は個々の 発音や休止をまたぎますが、一音ごとに伸ばすか切るかを選ぶ働きではありません。

行き先がない機会では音を伸ばす

持続音を参加の機会で打ち直す形に、配置前のtie(p)を添えられます。pは、行き先の保留が ない時、いまのToneを打ち直さずに伸ばす確率です。自由音高のsustain()とmetric()／entrained()／steady()／ flow()に、明示のgate_snapまたはrearticulateを組み合わせる形が対象です。境界0も含みます。 省略時は、持続＋同期では1、持続＋entrained／steady／flowの参加では0になります。参加のVoiceは 費用によって機会を見送れます。明示のtie(0)は保留の無い機会でも打ち直し、tie(1)は 対象のToneを必ず伸ばします。中間では機会ごとに両方が混ざります。固定音高とGlideは tieの対象外で、metricの交差ごとに打ち直します。音楽的な最適値を決めたものではありません。

保留があれば、その行き先へ跳んで発音します。正の境界以下の採用は既に滑っており、 保留を作らないので、そのToneも伸ばす対象です。厳密に同じ音高だけに限りません。 gate_snapでは小さい採用や距離0の採用も保留するため、その機会は打ち直します。 発音は減り、既存の機会から発音が抜けた列になります。機会の時刻、音高の提案、費用、 見送りの式は変えません。すべての音をつなぐレガートの量や、フレーズ単位の切り替えではなく、 聴こえた区切りとも結び付きません。

let voices = place(harmonic().sustain().entrained()
    .pitch_apply_mode("rearticulate").rearticulate_above(50).tie(0.5),
    line(220.0, 330.0).count(2));
wait(3.0);
release(voices);

この境界と中間の確率は使い方の例で、推奨値ではありません。伸ばした機会では新しいTone、 発音の代謝、発音由来の文脈学習を生じず、費用の見送りとしても学習しません。機会は消費し、 後で再演しません。articulation_persistenceを併せると、Connectの抑止を先に使い、tieの 乱数は引きません。Baseの保留ありは発音し、保留なしだけにtieを使います。tieで伸ばしても Base／Connectの提案や保持は変えません。大きい移動も滑らせ、発音を控えるConnectの 「つなぐ」方針とは別の量です。

Toneが無い時の合法な初回や、有限Off・余韻終了・rest()の後の発音は塞ぎません。 release、死亡、remove、休止の合法性が優先します。演奏中にpを変える指定はありません。 modeがGlideになっている間は休止し、対象に戻れば再び働きます。placeとcreateで 書く順に依存せず、再生成はtemplateの値だけを継ぎ、途中の乱数や保留、最後の発音音高は 継ぎません。有限値は0〜1へ制限し、正の無限大は1、負の無限大とNaNは0にします。 対象外の最終指定は警告して無視します。0ではtieの状態も乱数も使わず、1では乱数を引きません。 中間だけが個体別の専用系列を、機会の実行時に一度使います。

明示的なwhen/duration（Tier 2）

presetの下にはonce()、pulse(rate_hz)、while_alive()、cycles(n)、 adaptive_duration()があり、duration_range、duration_curve、shorten_on_dropで 調整できます。

生存としてのtiming（Tier 3）

既存のアーティキュレーション制御には、rhythm_coupling_vitality(lambda_v, v_floor)、 rhythm_reward(rho_t, "attack_phase_match")、rhythm_freq(freq_hz)があります。 Gated発音では位相一致報酬を使いません。下の例でも、この報酬による同期は起きません。

let pulse_voice = harmonic()
    .repeat()
    .pulse(2.0)
    .cycles(2)
    .rhythm_freq(2.0)
    .rhythm_coupling_vitality(0.8, 0.4)
    .rhythm_reward(0.4, "attack_phase_match");

place(pulse_voice, at(165.0));
wait(8.0);

Scaffold（research control）

scaffold functionは比較assay用の外部pulseを強制します。

set_scaffold_off();
set_scaffold_shared(2.0);
set_scaffold_scrambled(2.0, 17);

同期が比較や実演に不可欠な場合だけ使います。entrained・steady・flowの参加を成立させる補助として 専用の拍打ちを追加しません。

身体の周期と既存の代謝制御

cycles(n)は、entrained・steady・flowでは設定された固有周期、metricでは実効的な拍周期を使います。 entrainedの参加周期は音響の反復へ追従しますが、保持時間とその重なり予測の音長は固有周期から求めます。 したがって、周囲のペースが変わっても一音の保持を自動的に引き延ばしません。 周期への追従では自分の周期内の位置を保ち、共有の発音位相を指定しません。 flowの音長には既存の3倍の係数も適用します。rhythm_freq()はアーティキュレーションの 内部振動子を設定し、参加方策の固有ペースを直接設定しません。

Gated発音では自律attackが無効になります。発行したonsetは協和度に基づく通常の回復を 受け、attack_phase_matchによる位相一致報酬は使いません。共有リズムを読む音高探索や 振幅変調は別の経路として残ります。専用の拍打ちは、同期の実演や比較に必須の場合だけ使います。

持続音を拍へ同期させる

sustain()とmetric()を両方明示すると、生きたToneを保ちながら、既存の同期時計の 整数交差を発音の機会に使います。書く順は問いません。共有の拍は音から確認された拍です。 確認される前は、tempo basinの中心と独立した初期位相から自走します。外から拍を置く語ではありません。

初回はHoldと同じ即時の発音です。その後は拍の交差ごとに機会があります。自由音高の GateSnap／Rearticulateでは、既定は行き先の採用を保留した拍で発音し、ほかの拍では 生きたToneを伸ばします。tie(1)と同じです。毎拍打つにはtie(0)と書きます。 固定音高とGlideは、交差ごとにその時の身体音高で打ち直します。Glideは発音の間も滑ります。 GateSnapは最新の採用先を次の合法な交差まで保留します。境界0のRearticulateも同じです。 正の境界では小さい採用が旧保留を取り消して滑り、大きい採用は保留されます。 同じsampleの採用は、交差の発音より先に扱います。

let wire = harmonic().brain("drone").sustain().metric().seek_consonance()
    .pitch_apply_mode("rearticulate");
let voices = place(wire, at(660.0));
wait(4.0);
release(voices);
wait(2.0);

自由音高のGateSnap／Rearticulateにtie(p)を明示すれば、その値を使います。省略値は 配置前に解決し、演奏中のmode切替で対象に入っている間も同じ規則が働きます。 持続＋entrained／steady／flowの参加は省略時0のままで、費用による見送りがあります。 tieの演奏中のsetterは追加しません。articulation_persistenceは既存のBase／Connectを 保ちますが、同期には費用による見送りも、決めた予定を待つ状態もありません。方針の提案は 採用と発音の交差から来ます。rest()は明示の有限音長、実際の余韻の終了、間を組み合わせます。 その間も時計は進み、控えた交差を後で再演しません。

役割、確認された小節の強調、microtimingの意味は同じです。固定音高も持続＋参加と同様に 扱えますが、tieとpersistenceは自由音高だけの量です。entrainmentや役割だけを指定した Coupledには、持続＋同期の意味を広げません。

ルーティングとListenerTwin

二つのbus

各々のVoiceは、独立した二つのモノラルバスへ寄与します。

  • presentation bus → cpal出力 / offline render / UI metering（提示される作品）
  • habitat bus → NSGT解析 → Landscape（ALife生態系が応答するもの）

初期状態では両方へ送られます。一方だけに送るにはsend()、両方を明示するには|で 結合します。

// Reference anchor: sensed by the ecology, absent from the presented sound.
let anchor = harmonic().brain("drone").send(habitat_bus);

// Presented decor that does not influence the ecology.
let decor = sine().send(presentation_bus);

// Explicitly both (the default).
let normal = harmonic().send(habitat_bus | presentation_bus);

place(anchor, at(110.0));
place(decor, at(880.0));
place(normal, consonance(110.0).peak().count(3));
wait(4.0);

バスの分離は作曲の道具です。send(habitat_bus)の隠れたanchorは聞こえずにPopulationの 組織化を変え、send(presentation_bus)のdecorは生態系を乱さずに聞こえます。

初期状態ですべてのVoiceを両方のバスへ送るのは、それがDirect Cognitive Couplingだからです。 聴き手が聴くものと生態系が知覚するものが同じ物理eventになります。分離は意図的な逸脱です。 send(habitat_bus)は聞こえずにFieldを形づくるterrain、send(presentation_bus)は 聞こえるが生態系の世界の外にあるdecorです。音高の基準を作るanchorと、専用の同期補助は 区別します。拍を打つ専用Voiceや時間的scaffoldを置くのは、明示的な同期が不可欠な サンプルだけです。habitat busだけへ送る場合にも、この制限を適用します。

ListenerTwin

Conchordalは、提示された音だけをmodel化するlistener側のListenerTwinを持ちます。 habitat busは読まないため、hidden scaffoldが偽のlistener tensionを作ることはありません。 listener_state reportには四つの知覚levelがあります。

  • stability_level — 現在聞こえる音の安定性 / consonance。
  • resolvability_level — 近くに、より安定したもっともらしい継続状態があるか。
  • tension_level — (1 - stability) * resolvability。現在は不安定だが改善経路がある状態。
  • attention_level — presentation由来のonset / spectral-flux salience。

listener側のmeter推定も含みます。

  • beat_hz、beat_phase、beat_confidence
  • subdivision_ratio、subdivision_confidence
  • measure_hz、measure_ratio、measure_confidence

generated_frame_id、analysis_frame_id、analysis_lag_framesは知覚遅延を明示します。 report eventと原因となった音を比較するときに重要です。

Twinを操作するscripting verbはありません。命令する対象ではなく観測する対象です。 report有効時にlistener_state recordを出し、GUIにも同じstateを表示します。generationへ 結合する前に、自分が聴くtensionとTwinのreportが一致するかを確認してください。

DCC：Twinを戻す結合

任意の結合であるDCCはscriptではなくconfig.toml（または--configで指定したfile）で 設定します。

[dcc]
# Listener pressure is report/UI-only by default.
# coupling_strength = 0.0
# max_temperature_bonus = 0.10
  • coupling_strength（0.0–1.0、既定値0.0）：0.0ではレポートとUI専用で、 generationは変わりません。値を上げると tension_pressure = tension_level * coupling_strengthを 一時的な音高探索の加算値としてだけ使います。ListenerTwinの緊張度にはすでに 解決可能性が含まれるため、結合時に重ねて掛けません。目標音高やリズム同期を 直接設定しません。
  • max_temperature_bonus（既定値0.10）：一時的な加算値の上限。

listener_stateが音楽的に読めることを確かめてからcoupling_strengthを少しずつ上げます。 結合中はdcc_pressure recordにpressureとtemperature bonusが記録されます。

タイムラインと構造

シナリオは音響標本を一つずつ予定表へ並べません。スクリプト上の時刻を進め、その時点で Populationを配置し、更新または終了する時刻を記述します。

place、wait、flush

place()は現在時刻に初代のVoiceをただちに配置し、安定したPopulationへの参照を 返します。wait(seconds)は保留中の更新を発行して時刻を進めます。flush()は 時刻を進めずに保留中の更新だけを発行します。

let spec = harmonic()
    .amp(0.04)
    .brightness(0.35)
    .sustain();

let population = place(spec, consonance(220.0).count(3));
population.amp(0.025); // Live patch at the same script time.
flush();               // Emit it; the cursor does not move.
wait(2.0);             // Advance two seconds.
release(population);

意味上の境界はwait()やflush()ではなくplace()です。発音体、振る舞い、生存過程、 再生成の初期設定はPopulationSpecに属し、実行中の更新と終了だけがPopulationに属します。

release、section、play

release(population)は明示的なreleaseです。section(name, callback)と play(callback, ...)は有効範囲を作り、関数が戻ると内部で作られたPopulationを 自動的にreleaseします。有効範囲の終了時にはreleaseより前に保留中の更新を発行します。

名前の付いたformにはsectionを使います。名前はreportのscene_markerになります。 引数を取る再利用可能なgestureにはplayを使います。

let gesture = |root_hz, duration_sec| {
    place(

Parallel timeline

parallel([callbacks])は現在時刻から複数のcursorをforkします。全branchは同時に始まり、 記述後の主時刻は最長の分岐の終端へ進みます。各分岐も一つの有効範囲であり、戻ると内部の Populationをreleaseします。

section("overlap", || {
    parallel([
        || {
            place(sine().amp(0.05).sustain(), at(220.0));
            wait(3.0);
        },
        || {
            wait(1.0);
            place(harmonic().amp(0.03).sustain(), at(330.0));
            wait(1.0);
        }
    ]);
});

第一branchはforkから3秒後、第二branchは2秒後に終わるため、main cursorは3秒進みます。 両分岐の有効範囲が重なる区間だけ、両方のVoiceが同時に鳴ります。

スクリプト上の時刻と実行時の振る舞い

スクリプト上の時刻は制御事象の時刻を決めます。その時刻のLandscapeを予測するものでは ありません。wait()でscenarioが進む間も、movement、coupled rhythm、death、respawnは 実行中も続きます。

  • scriptはmacro structureを書く。
  • Communityは瞬間ごとの振る舞いを生成する。
  • レポートは、記述された区間で実際に起きたことを示す。

演奏で説明した手順を使って結果を確かめ、scenarioを修正します。 特定の実現を再現するときだけseed(...)または--seedを使います。

Phonationとリズム

Voiceがいつ、どれだけの間鳴るかを決める。Tier 1はリズム結合連続体の領域を選び、Tier 2はwhen/durationを明示し、Tier 3は専門的な調整を行う。同じ軸では最後の指定が優先される。

brain

brain(name)

適用対象：PopulationSpecのみ。 初期設定専用：place()より前にPopulationSpecへ設定する。

Articulation life: "entrain" (default), "seq", or "drone". Selects how the voice lives while sounding; orthogonal to the rhythm timing presets (metric/entrained/steady/flow). entrain is a living articulation whose vitality responds to consonance and rhythm fit, subject to the metabolism economy. seq holds for a fixed lifetime, ignoring the field and metabolism. drone is undying, sustaining forever with a slow sway – useful as terrain material.

sustain()

適用対象：PopulationSpecのみ。 初期設定専用：place()より前にPopulationSpecへ設定する。

Sustain phonation mode (default). Explicit sustain() plus entrained(), steady() or flow(), in either order, retains a Tone while the Voice considers participation. With glide (the omitted mode), clock attacks use current body pitch; entrained/flow can offer one legal adoption-time candidate with unchanged costs, otherwise it glides. Steady evaluates only its own due time and never adds an adoption-time candidate. Explicit gate_snap on free pitch holds the latest adopted target until a sounded clock opportunity, then jumps and attacks; wait/skip retains pitch and pending target, and no adoption-time candidate is offered. Rearticulate with a positive rearticulate_above boundary glides small adoptions, cancelling older pending pitch, and defers large ones to a sounded opportunity. Zero or omission matches gate_snap; clock attacks are not filtered by the boundary. Implicit WhileAlive and while_alive() alone do not enable the combination. Pulse and repeat retain their last-write-wins rule. Explicit sustain() plus metric(), in either order, keeps a live Tone and uses the existing coupling-clock integer crossings as opportunities. For free-pitch gate_snap/rearticulate, omitted tie means tie(1): beats with a pending adopted target attack, while other beats extend the living Tone. Explicit tie(0) re-attacks every legal crossing; explicit intermediate values are unchanged. Fixed pitch and glide still re-attack at each crossing. Omitted tie for sustained entrained/steady/flow remains zero, where participation can skip opportunities by cost. No adoption-time opportunity or participation cost policy is added. articulation_persistence(p)

適用対象：PopulationSpecのみ。 初期設定専用：place()より前にPopulationSpecへ設定する。

Retain a Voice’s private articulation policy across pitch adoptions and sustained clock opportunities. The sustained metric combination uses shared-beat crossings, including crossings without adoptions; before acoustic confirmation it free-runs. Unlike participation, synchronization has no cost skip or committed plan. Initial-only, for free-pitch sustain() plus metric()/entrained()/steady()/flow(), rearticulate and a positive rearticulate_above boundary. The private policy starts in Base (the existing boundary and participation behavior); Connect glides all adoptions while a Tone lives and intentionally withholds sounded opportunities to extend it. Small adoptions and participation cost skips propose Connect; large adoptions and newly selected sounded opportunities propose Base. For 0 < p < 1, only an opposing proposal draws from a dedicated individual random stream: retain with probability p, switch with 1-p. A planned opportunity freezes its decision until execution; waiting hops do not draw again. Entering Connect cancels pending pitch but retains the last actual onset; cancelled adoptions never replay. Intentional withholding is distinct from cost skip and creates no Tone, onset metabolism or onset-context learning. Rest, finite Off, tails/gaps and lifecycle constraints take priority; Connect cannot block a legal onset when no Tone lives. Zero (the default) and one bypass the private state and RNG and retain the existing path. Finite values clamp to 0..1, positive infinity becomes one, negative infinity and NaN become zero. Unsupported final specs warn and ignore the value, independent of builder order. Replacements inherit the template parameter, not policy, RNG, pending decisions or last-onset memory, and start in Base. Live mode changes reset Base; the same mode and boundary-only changes retain the policy. A zero boundary suspends the private path. This is policy inertia, not a legato proportion: increasing p need not monotonically increase Connect time or reduce attacks. Retention is measured in existing events, not seconds or beats, and is not tied to heard cadence, contour, rests or phrase boundaries. Example values are comparisons, not recommendations. With tie(p), Connect vetoes first without a tie trial; Base uses tie only without pending pitch. Tie never changes policy proposals or retention.

rearticulate_above

rearticulate_above(cents)

適用対象：PopulationSpecとPopulation。 実行中に更新可能：Population内で鳴っているVoiceを更新する。

Choose sliding or rearticulation by distance from the last sounded onset pitch. For free-pitch Hold without coupled opportunities, a positive boundary measures net displacement from the last actual ToneSpec onset to the adopted target: strictly above attacks, at or below glides with glide(tau). Selection persists until the next adoption. Earlier legal onsets in the same output hop provide the reference; cancelled requests do not replace the last actual onset. Exact Log2Space centers use bin-distance in cents, otherwise continuous log2 distance is used without rounding or epsilon. Without sustained coupled timing, zero retains every-adoption rearticulation. With explicit sustain plus metric/entrained/steady/flow, a small adoption cancels older pending pitch and glides immediately; a large adoption stops the glide, holds body pitch and defers one latest target to the next sounded opportunity. At a sounded opportunity without pending pitch, explicit tie(0) attacks at current body pitch; omission extends in free-pitch sustained metric and retains attacks in entrained/steady/flow. Other tie(p) values may extend its living Tone; either attack updates the reference. Waiting/skipping retain sound and pending pitch while existing glides continue. Zero or omission matches GateSnap, including zero-distance adoptions. The boundary does not suppress clock attacks and adds no adoption-time candidate. Negative or nonfinite values become zero; no upper limit is imposed. A live boundary change emits no attack and applies at the next adoption. Outside rearticulate, a call warns and is ignored. Builder order is independent at placement; replacement Voices inherit the boundary but not the onset-pitch memory. The composer chooses the boundary; 50 or 100 cents are examples, not recommendations. Initial-only articulation_persistence(p) can retain a private Base/Connect policy within the positive-boundary sustained-participation form; the boundary alone never suppresses clock attacks.

適用対象：PopulationSpecとPopulation。 実行中に更新可能：Population内で鳴っているVoiceを更新する。

Search temperature shared by both pitch cores: 0 settles greedily, higher is more exploratory. The single stochastic-search knob. At 0 the hill-climb is greedy (move only on a clear improvement, otherwise stay) and the peak sampler takes the argmax candidate. Higher values let the hill-climb accept downhill moves (Metropolis) and soften the peak sampler’s candidate choice. Musically the movement-tension dial; its placement twin is tension().

Directorとglobal parameter

meter_stability

meter_stability(value)

Attractor depth in 0-1: how readily a pulse forms. Default 0 (neutral). A soft prior: it only deepens the basin for a real periodicity; it never fabricates a beat from non-metric input. It also weights the tempo preference toward the center of temporal_basin, or 2 Hz in the default beat band. The preference weight equals the depth, clamped to [0,1]; it is part of the modeled listener’s enculturation. Higher depth favors an in-band tactus nearer that center, including an integer subdivision reading of faster input.

temporal_basin

temporal_basin(min_hz, max_hz)

Set the beat’s tempo band and metric Voices’ initial rate. The time-axis analogue of consonance(min, max): it seeds the beat at the band center and confines tempo adaptation to the band. At meter_stability(0), the band adds no center preference or restoring pull; with higher stability, candidate preference and confidence-weighted center restoring grow with the depth. The same sanitized center sets the intrinsic starting rate of metric() Voices, even at stability 0; without a basin that rate is 2 Hz. entrained()/steady()/flow() retain their separate bodily rate, 2 Hz unless intrinsic_rate(hz) is supplied, and explicit pulse(rate_hz) retains its rate. This is one scene initial condition: the last basin declaration applies to every metric Population, regardless of its position before or after place, create, or wait. It is not an in-performance change. Independent Voice phases and acoustic confirmation remain required; this does not place a beat or force a measure.

サンプル

16本のサンプルを、同じsamples/内の二つの群として紹介します。1〜12は、機能を 一つずつ確かめる小さな実演です。音楽作品ではなく、APIと挙動を示します。 13〜16は、それらの機能を組み合わせて曲として書いた、やや長い場面です。 どちらも実行し、scriptを読んで確かめられます。

cargo run --release -- samples/01_a_single_voice.rhai

機能の実演（1〜12）

  1. A Single Voice — 一つのVoiceが現れ、息を保ち、去る。
  2. Constellation — line、peak、density、strain、gap、chanceという六つの入り方。
  3. Gravity — 二つのsunの下の同じroot。peakはchartではなく現在の音を聴く。
  4. Tension — Voiceが協和へ落ち着き、不安定になって離れ、再び冷えて落ち着く。
  5. Settling — 散らばったVoiceが、Consonance Fieldに支えられる場所へ滑らかに移る。
  6. Bells — 打撃されるbody。最後のbellはpartialをFieldに選ばせる。
  7. Heartbeat — 拍を打つ専用Voiceを使い、同期を実演する。
  8. Murmuration — 指揮者のいない群れ。各Voiceは自分の間合いを保ち、聴こえた再来へ周期を寄せる。共有の拍は狙わない。
  9. Rain — beatを持たず、Fieldに沿って落ちる時間。
  10. Generations — Voiceが生き、飢え、和声に支えられる場所へ生まれ直す。
  11. Autumn Cycle — directionを持つharmony。季節が巡り戻る。
  12. Emergence and Resolution — Populationの探索が強まり、再び落ち着く。専用の拍打ちは置かず、Voice自身の発音がリズムの入力を担う。

機能を組み合わせた曲（13〜16）

  1. Three Windows — 三本の線が音高を採用するたびに発音し、それぞれの扉から去る。
  2. Stone and Wire — 拍を刻む二つのVoiceの間を、独立した線が横切る。
  3. Folded Air — 相手が休みを置いて戻り、区間ごとに発音の形を変える。
  4. Open Court — やや密な群れが、独立した二本の道の周りへ集まる。

道筋と実行

1〜6はConsonance Field上の配置、引力、緊張、移動、音色を紹介します。 7〜9は三つの時間の取り方を示します。metric()は音から確認された共有拍へ寄り、 entrained()は共有拍の位相を狙わず、音を聴いて参加します。flow()は拍を作らない、 かたまりの更新を担います。10は生存と世代交代の循環、11〜12は複数の機構の組み合わせです。 13–16は、採用ごとに発音する線、拍を刻むVoiceと横切る線、 休む相手と区間ごとの発音の切り替え、やや密な群れを示します。 全サンプルはtest suiteでcompile-checkされ、現在のAPIとの 不一致を検出します。最上位のサンプルは意図的にseed(...)を呼ばず、毎runを新しい scenario seedで始めます。 比較を再現可能にする必要があるresearch assayだけが固定seedを使います。

音高の基準を作るanchorは、通常はhabitat busだけへ送られ、直接は聞こえません。 Gravityでは、聞こえる持続音そのものが主題です。Heartbeatは同期を実演するため、拍を打つ 専用Voiceを置いています。他の公開サンプルには専用の拍打ちVoiceはありません。

Research assay

samples/research/にはheredity/selection ablation、external-scaffold rhythm control、 mechanism studyなどの比較fixtureがあります。instrumentを演奏するのではなく研究するもので、 上の道筋には含まれません。 専用の同期補助は、明示的な同期が実演や実験に不可欠な場合だけ使います。 habitat busだけへ送って聞こえなくしても、他のサンプルで使える理由にはなりません。

Offline rendering

conchordal instrumentはaudioをdiskへ書きません。演奏は、音が鳴り終わるとinstrument内には 残らない一過的な出来事（ephemeral）として設計されています。offline WAVには、同じcore engineを 共有する別binaryのconchordal-renderを使います。
